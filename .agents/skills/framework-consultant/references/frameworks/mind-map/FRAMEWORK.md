# マインドマップ

## 概要

マインドマップは、**1つの中心テーマ**を紙の中央に置き、そこから**枝（ブランチ）を放射状**に伸ばして
連想を広げ、思考を1枚のツリー構造に可視化する発想・整理法。核となる考え方は
**放射思考（Radiant Thinking）**——脳が連想でアイデアをつなぐ「放射状」の働きを紙に写し取り、
**1枝1語**でキーワードを置くことで連想を閉じずに次々と広げる、というもの。

- **核となる原理**: 単語は連想の「引き金」、文章は「閉じた完成品」。だから枝には文でなく1語を置き、
  中心→主枝→子枝と外へ分岐させ、色・イメージで識別と想起を助ける。分析の網羅性より**連想の量と流れ**を優先する。
- **出自（普及者は明確、"発明"は断定回避）**: **トニー・ブザン（Tony Buzan、英国の著述家・教育コンサルタント。BBC番組の司会者としても知られる）**が
  「Mind Map」という呼称を普及させた。**1974年のBBC番組『Use Your Head』**と関連書籍が契機とされる（→要確認）。
  ただし放射状の図解自体は古く、**Porphyry（3世紀）のカテゴリ図やRamon Llull（1235–1315）**等の先行があり、
  ブザンは「発明者」というより**体系化・命名・普及**をした人物と捉えるのが正確（「Mind Map」は商標登録されている）。
- **類似手法との区別**: **概念地図（concept map, Novak）**は複数概念を自由なネットワークで結び、
  リンクに関係ラベルを付けて**遠い概念間の因果・相互関係**を厳密に示す。マインドマップは**単一中心＋放射ツリー**で、
  厳密な関係網の記述は苦手。用途が違うので混同しない（→前提と限界・相性）。

## いつ使う / 使わない

**使う（適する状況）**
- **単一テーマの発散**——1つのお題でアイデア/論点/連想を一気に広げたいとき（一人ブレスト含む）。
- **頭の中のダンプと整理**——考えが渦巻いて言語化できないとき、まず中心から書き出して全体像を掴む。
- **骨子づくり**——企画・文章・プレゼン・プロジェクトの構成を放射状に組み立てる下書き。
- **ノート・要約・学習整理**——講義/読書/会議の内容を中心テーマから枝分けして俯瞰する。

**使わない / よくある誤用（アンチパターン）**
- **枝に文章を書く（1枝1語違反）**——最頻の失敗。文で書くと連想がそこで閉じ、ただの装飾ノートになる。1語に削る。
- **線形アウトラインの化粧直し**——箇条書きを枝に置き換えただけで放射連想になっていない。中心からの連想の流れが要。
- **網羅的・MECEな論理分解に使う**——漏れ/ダブりの検証や論理的な分解は**ロジックツリー/MECE**の領域。連想は飛ぶので網羅は保証されない。
- **多概念の厳密な相互関係を描こうとする**——因果・関係ラベル付きの網なら**concept map**へ。放射ツリーでは表現しきれない。
- **選択肢の比較・意思決定に使う**——採点や優先順位づけは**意思決定マトリクス/ペイオフマトリクス**へ。
- **集団の合意形成・収束に使う**——多人数の付箋を集約・グルーピングして合意するなら**KJ法**が向く。マインドマップは個人色が強く共有しづらい。
- **発散しっぱなしで収束しない**——広げて満足して終わる。必ず絞り込み・次の一手まで導く。

## 前提と限界

- **前提**: 中心に置く**テーマが1つに定まっている**こと（曖昧だと放射がぶれ、雑多な落書きになる）。
  個人または少人数＋ファシリテーター。無地の紙/ホワイトボード/ツール（テキストのみの環境ではツリー記法で代替）。
- **限界（批判・エビデンスを踏まえて）**:
  - **記憶・学習効果のエビデンスは割れる**。Farrand ら (2002) は600語テキストで recall 約10%増を報告したが、
    **好みのノート法よりモチベーションが有意に低下**した。D'Antoni ら (2010) は医学生131名で
    **短期recall・批判的思考ともに有意差なし**。マインドマップは万能の記憶術ではなく**思考の補助**と捉える。
  - **ブザンの脳科学的主張は誇張されやすい**（例:「脳は画像を文字の6万倍速く処理」「曲線が記憶に残る」等は
    裏付けが弱い→要ファクトチェック）。効果を過大評価しない。
  - **放射ツリーは遠い枝どうしの関係を表現しにくい**（そこは concept map の得意領域）。矢印で補うが限界がある。
  - **極めて個人的**——他人のマインドマップは読みにくく、引き継ぎ・共有・ドキュメント化には不向き。
  - **発散ツールであって収束ツールではない**。網羅性の錯覚（描けた＝漏れなし）にも注意。
- これらは、**発散後にロジックツリー/MECEで論理的に締め直す / 集団の収束はKJ法へ渡す /
  遠い関係は矢印やconcept mapで補う**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。

1. **中心テーマを1つに固定し、セントラルイメージを中央に描く。** お題を動詞まじりの短い問い/語にする（例:「会議を短くする」）。
   なぜ: 中心が曖昧だと枝が発散しすぎる。絵にすると連想が起動しやすい（テキスト環境では中心に1語を置く）。
2. **主枝（BOI＝基本アイデア）を3〜7本、放射状に伸ばす。** 太い曲線で、1枝1語の大分類を置く。
   なぜ: 最初の数本が全体の骨格＝分類軸になる。多すぎると散る（目安7±2）。曲線は手が止まりにくい。
3. **各主枝から子枝へ連想を展開する。** ここも**1枝1語**を厳守し、思いついた語をどんどん外へ分岐させる。
   なぜ: 単語は連想の引き金、文章は思考を閉じる。1語なら後から枝を足せ、視点が狭まらない。
4. **色分けとイメージ/アイコンを添える。** 主枝ごとに1色、要所に簡単な絵や記号を置く。
   なぜ: 色と絵は枝の識別と想起を助ける（ただし記憶効果を過信せず、あくまで補助）。
5. **判断を保留して量を出す（発散）。** 手を止めず速く、良し悪しを評価せずに枝を伸ばし切る。
   なぜ: 批評は連想を殺す（ブレスト原則）。まず広げ切ってから選ぶ。
6. **枝どうしの関連を矢印・クラウドで結ぶ。** 離れた枝に共通点や因果があればつなぎ、番号で重要度を示す。
   なぜ: 放射ツリー最大の弱点（遠い枝の関係が見えない）をここで補い、新しい組み合わせの洞察を拾う。
7. **俯瞰して収束する。** 全体を眺めて空白の枝を追い、**重要な枝を数個に絞り、次の一手を決める**。
   なぜ: マインドマップは起点であってゴールではない。ここで止めると「広げて終わり」になる。

## 壁打ち質問リスト

各枝を利用者自身の言葉で埋めるための問い。空欄を勝手に埋めず、まずこれで引き出す。

1. **中心に置く1つのテーマ／問い**は何ですか？（できれば動詞まじりで具体的に。例:「新サービスの案を広げる」）
2. このマップの**ゴール**はどれですか？ 発散（アイデアを広げる）／整理（全体像を掴む）／記憶（学習）／計画（骨子づくり）。
3. 中心から最初に伸ばす**主要な枝（大分類）**は何が思い浮かびますか？ まず3〜7個挙げてください。
4. いま各枝を**「文章」で考えていませんか**？ それを**1語**に削ると何になりますか？（1枝1語に変換）
5. すでに埋まっている枝と、**まだ空白で連想を出し足りない枝**はどれですか？
6. **離れた枝どうしで、実はつながっている関係**（共通点・因果・組み合わせ）はありますか？
7. ひととおり出し切ったあと、**次に何を絞りたい／決めたい**ですか？（収束の出口）

## 出力フォーマット

ALWAYS この型で出力する（発散のツリー → 関連づけ → 収束）。チャットはテキストなので放射図を
**インデントのツリー記法**で表現し、色/イメージは意図を`[ ]`で注記する。**枝は必ず1枝1語**に保つ。

```
【マインドマップ】中心テーマ: <1語/短い問い> ／ 目的: <発散/整理/記憶/計画>
● <中心テーマ>
├─ 主枝1: <1語> [色: …]
│   ├─ <1語>
│   │   └─ <1語>
│   └─ <1語>
├─ 主枝2: <1語> [色: …]
│   └─ <1語>
└─ 主枝3: <1語> [色: …]
    └─ <1語>

【関連リンク（枝をまたぐ発見）】
  - <主枝1の枝> ⇄ <主枝3の枝>：<なぜつながるか／どんな組み合わせか>

【収束】重要な枝 Top3: <…>
【次の一手】<検証/決定/アクションを1〜3個>
【未確認の前提】<掘り足りない枝・壁打ちで埋める点>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。中心テーマ「**会議時間を減らす打ち手を広げる**」を
一人ブレストで発散する場面。

- **手順①中心**: 「会議を短くする」を中央に置く（目的＝発散）。
- **手順②主枝（3〜7本）**: `事前` / `進行` / `参加者` / `ツール` / `やめる` の5本を放射状に。
- **手順③子枝を連想展開（1枝1語）**:
  - `事前`: 議題 → 事前配布 → 目的明記 → 到達点
  - `進行`: 時間箱 → タイマー → 立ち会議 → 決定係
  - `参加者`: 絞る → 役割 → 欠席可 → 議事録共有
  - `ツール`: 非同期 → チャット → 録画 → 共同編集
  - `やめる`: 定例廃止 → 隔週化 → メール代替 → 承認不要化
- **手順④色/イメージ**: 主枝ごとに色分け（例 `やめる`＝赤で「減らす」を強調）。テキストでは`[色]`注記。
- **手順⑤発散**: 良し悪しを判断せず、思いつく限り枝を伸ばし切る。
- **手順⑥関連リンク**: `進行:立ち会議` ⇄ `やめる:定例廃止`＝どちらも「そもそも集まらない」方向で相乗。
  `事前:目的明記` ⇄ `参加者:絞る`＝目的が明確なら呼ぶ人も絞れる。
- **手順⑦収束**: 重要な枝Top3＝「目的明記」「時間箱」「定例の隔週化」。
  次の一手＝まず1つの定例で「議題に到達点を書く＋30分固定」を試す。
- **空白（掘り足りない枝）**: `ツール:非同期` 系が薄い——非同期で代替できる会議の線引きは要検討（壁打ちで深掘り）。

（注: これは手順を示す一般化例。実際は利用者の中心テーマと言葉で枝を作る。数値・実名は捏造しない。）

## 相性（組み合わせると効く）

- `kj-method`: マインドマップ（個人の放射発散）で広げ、複数人の付箋を親和図で**収束・合意**する。発散→収束の対。
- `logic-tree`: 連想で飛んだ枝を、あとから**論理的・階層的に構造化し直す**。放射の自由さを論理で締める。
- `mece`: 主枝や子枝に**漏れ・ダブりが無いか検算**する。連想は網羅を保証しないので補完に効く。
- `brainstorming`: 集団の自由連想で出た大量のアイデアを、マインドマップの枝として**受け止め・構造化**する。
- `scamper`: 枝が伸び悩んだとき、7つの動詞で**強制発想**して連想を再点火する（発散のブースター）。
- `mandala-chart`: 3×3の放射で、より**強制的・網羅的**に展開したいときの近縁ツール（マス埋めで空白を潰す）。
- 揺さぶり枠として `reverse-assumption`（中心テーマの前提を反転して別マップを描く）や
  `six-hats`（枝ごとに視点の帽子を割り当てて偏りを崩す）を添えると連想の幅が広がる。
