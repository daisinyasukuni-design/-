# 交渉フレームワーク（BATNA / ZOPA）

## 概要

BATNA/ZOPA は、**相手のいる交渉に臨む前の「準備」を構造化する**フレームワーク。中核は
**「交渉力は弁舌でなく"決裂したときの代替案の強さ"で決まる」** という洞察にある。
`Getting to Yes`(Fisher & Ury, 1981) が提唱した**原則立脚型交渉**の道具立てで、
感情や立場のぶつかり合いを、代替案・利害・客観基準という**分析可能な要素**に翻訳する。

| 用語 | 定義 | 役割 |
|---|---|---|
| **BATNA** | 交渉決裂時に取れる**最善の代替案**（Best Alternative To a Negotiated Agreement） | 「合意すべきか否か」を測る唯一の基準。強いほど交渉力が高い |
| **留保価格(reservation price)** | これ以上は譲れない**撤退ライン**（walk-away） | BATNA から算出する内なる最低条件。買い手＝上限、売り手＝下限 |
| **ZOPA** | 双方の留保価格が**重なる範囲**（合意可能圏） | 正の重なり＝妥結可能、負＝合意不能でBATNA発動 |
| **WATNA** | 決裂時の**最悪**の帰結（要FC・任意） | BATNAの裏。撤退の痛みを直視して過信を防ぐ |

- **核となる考え方**: 交渉のゴールは「勝つ」ことでなく、**BATNAより良い合意を得る**こと。
  BATNAより悪い条件なら合意せず立ち去るのが正解。だから**準備の主戦場は自分と相手のBATNAの見積り**にある。
- **原則立脚型交渉の4原則**（原典の骨格）: (1)**人と問題を分離**する、(2)**立場でなく利害**に焦点、
  (3)**相互利益のオプション**を創出、(4)**客観的基準**を主張する。BATNA/ZOPAはこの土台の上で機能する。
- **七つの要素**（Harvard Negotiation Project の準備チェック）: 利害 / 選択肢 / 代替案(BATNA) /
  正当性(客観基準) / コミュニケーション / 関係 / コミットメント。準備の抜けを塞ぐ網。
- **出自（要確認あり）**: BATNA・原則立脚型交渉は **Roger Fisher & William Ury『Getting to Yes』(1981)** が初出
  （第3版で Bruce Patton 共著）。**ZOPA** の体系化は **Howard Raiffa『The Art and Science of Negotiation』(1982)**
  に帰されることが多い（語の初出帰属は二次資料依存→出典・要FC）。

## いつ使う / 使わない

**使う（適する状況）**
- **相手がいて条件（価格・納期・報酬・契約条項）を詰める**交渉の**準備**をしたいとき。
- 値引き/値上げ要求、取引先との条件交渉、転職オファー、契約更改、給与交渉、対立の調停など。
- 「どこまで押せるか」「いつ席を立つべきか（撤退ライン）」「落としどころはどこか」を事前に決めたいとき。
- 相手に足元を見られている・強気に出られない——**自分の交渉力の源泉（代替案）を棚卸し**したいとき。
- ゼロサムに見える綱引きを、利害と客観基準で**パイを広げる交渉**に組み替えたいとき。

**使わない / よくある誤用（アンチパターン）**
- **交渉相手のいない自社内の案の優劣づけに使う**——それは decision-matrix / decision-tree の領分。BATNAは"相手"が要る。
- **相手が特定できていない段階で使う**——「誰と交渉するか・誰を巻き込むか」が未整理なら先に stakeholder-analysis。
- **BATNAを"中心戦略"に据えすぎる**（Sebenius の警告）——代替案の誇示に固執すると、交渉中の新情報や
  価値創造（オプション創出）を見落とす。BATNAは**参照点**であって振り回す棍棒ではない。
- **自分のBATNAだけ見て相手のBATNAを推定しない**——ZOPAは双方の留保価格で決まる。片側だけでは着地点を誤る。
- **立場（要求額）の綱引きに終始する**——「いくら払え」の応酬でなく、その裏の**利害（なぜそれが必要か）**を掘らないと相互利益案は出ない。
- **客観的基準を用意せず"意地の張り合い"にする**——市場相場・前例・専門家見解などの外部基準がないと、譲歩が「負け」に感じられ決裂しやすい。
- **BATNAを実際より強く思い込む**（過信）——甘い代替案の見積りは、決裂して初めて痛みが分かる。WATNAで裏を取る。
- **関係・評判を無視した勝ち逃げ**——継続的関係では、一度の勝利より信頼維持が価値を持つ場面がある。

## 前提と限界

- **前提**: (1) **交渉相手が特定**できていること。(2) 自分の**代替案（BATNA候補）が列挙・評価**できること
  （無ければ交渉前に代替案づくりそのものが最初の打ち手）。(3) 相手の利害・代替案を**推定する材料**が多少なりとあること。
  相手が未特定なら stakeholder-analysis を、代替案が空なら「BATNA強化」を先に置く。
- **限界（批判を踏まえて）**:
  - **BATNA中心主義の危うさ**——Sebenius (2017) は BATNA が "problematic, limiting, even misleading" になりうると指摘。
    代替案の強さに酔うと、目の前の価値創造や関係を損なう。
  - **力・情報の非対称**——一方が圧倒的に強いと、客観的基準や公正が機能しにくい。弱いBATNA側は準備で補うしかない。
  - **相手のBATNA/留保価格は推定でしかない**——ZOPAの境界は不確実。過信すると外れる。ブラフの可能性も残る。
  - **分配交渉・非合理な相手への非万能性**——純ゼロサムや感情的対立では、利害統合の余地が乏しい場面もある。
  - **静的な準備**——交渉は動く。準備した留保価格・ZOPAは、交渉中の新情報で更新する前提で使う。
  - **文化・関係・倫理**——数値化しきれない要素（信頼、長期評判、面子）は別途配慮が要る。
- これらは、**決裂シナリオを premortem で先回りし／相手の手を red-team で読み／自分のBATNA過信を devils-advocate で叩き／
  複数オプションを decision-matrix で採点する**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップに「なぜ」を添える。**弁舌の準備でなく、代替案と留保価格の数値化が肝**。

1. **交渉の対象と相手・論点を定義する。** 誰と、何について（価格/条件/範囲）、いつまでに合意したいかを明文化する。
   なぜ: 相手と論点が曖昧だと、以降のBATNA/留保価格がすべてぶれる。まず土俵を1つに固定する。
2. **自分のBATNAを洗い出し、最善を1つ選ぶ。** 「この交渉が決裂したら現実に取れる選択肢」を複数列挙し、価値を評価して**最善**を特定する。
   なぜ: BATNAが交渉力の源泉。合意条件の良し悪しは"BATNAと比べて"しか測れない。曖昧な代替案は交渉前に具体化・強化する。
3. **自分の留保価格を決める。** 選んだBATNAを金額/条件に換算し、「これより悪ければ席を立つ」撤退ラインを1本引く。
   なぜ: 留保価格が無いと、雰囲気に流されてBATNAより悪い合意を飲んでしまう。撤退ラインは交渉中の防波堤になる。
4. **立場の裏にある利害を、双方について書き出す。** 相手と自分の「要求（立場）」と「なぜそれが要るか（利害）」を分けて列挙する。
   なぜ: 立場は対立しても利害は両立しうる。利害を掘らないと相互利益のオプションは生まれず、綱引きに堕す（原則②）。
5. **相手のBATNA・留保価格を推定する。** 相手が決裂時に取れる代替案と、相手の撤退ラインを、入手情報から見積もる（不確実なら幅で持つ）。
   なぜ: ZOPAは双方の留保価格で決まる。相手側を推定しないと着地点も、押せる余地も読めない。
6. **ZOPA（合意可能圏）を描く。** 自分の留保価格と相手の推定留保価格の**重なり**を図示する。重なりが無ければ、価値創造かBATNA発動を検討。
   なぜ: ZOPAの有無と幅が「妥結可能か・どこが着地か」を決める。負の重なりのまま粘るのは消耗。
7. **相互利益のオプションを複数創出する。** 論点を分解し（金額だけでなく納期・数量・保証・付帯条件）、パイを広げる案を**その場で評価せず**まず量産する。
   なぜ: 単一論点の綱引きは分配（ゼロサム）になる。論点を増やし交換材料を作ると、双方の利得を同時に上げられる（原則③）。
8. **客観的基準（正当性）を用意する。** 市場相場・前例・第三者評価・原価・法規など、**双方の意思から独立した基準**を集め、譲歩の根拠にする。
   なぜ: 「あなたが折れろ」でなく「基準がこうだから」にすると、譲歩が敗北でなく合理になり、決裂と遺恨を避けられる（原則④）。
9. **最初の一手（アンカー/オープニング）と譲歩計画を設計する。** 目標値・最初の提示・譲歩の順序と交換条件を、留保価格を割らない範囲で決める。
   なぜ: 出たとこ勝負は留保価格を割りやすい。譲歩を「見返り付き」で計画すると、一方的な値引きを防げる。
10. **決裂条件と次の一手を確定する。** どうなったら席を立つか（留保価格割れ/BATNA発動）を明文化し、検証すべき前提（相手BATNAの推定等）を1〜3個決める。
    なぜ: 撤退基準が言語化されていないと、サンクコストで悪い合意に流れる。準備は"降りる勇気"まで含めて完成する。

## 壁打ち質問リスト

交渉の準備を事実で埋めるために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。

1. この交渉で**最終的に何を得たい**ですか？相手は誰で、論点（価格/条件/範囲）は何ですか？期限はありますか？
2. **この交渉が決裂したら、あなたは現実に何ができます**か？（＝BATNA候補。複数挙げ、一番マシなのはどれですか）
3. その最善の代替案を条件に直すと、**「これより悪ければ降りる」ラインはどこ**ですか？（＝あなたの留保価格）
4. あなたの**要求の裏にある本当の理由（利害）**は何ですか？表向きの要求と、譲れない核は同じですか、違いますか？
5. **相手はなぜこの交渉に来ている**と思いますか？相手の利害・事情・締切は？相手が決裂したら相手は何を失いますか（相手のBATNA）？
6. あなたと相手、**それぞれの撤退ラインは重なりそう**ですか？（＝ZOPAの有無。重ならない場合、条件を増やせば重なりますか）
7. 金額以外に**交換できる論点**（納期・数量・保証・支払条件・継続取引・付帯サービス）はありますか？
8. 譲歩や要求を正当化できる**客観的な基準**（相場・前例・見積・第三者評価）は用意できますか？
9. この相手との**関係は一度きり**ですか、**継続**しますか？勝ちすぎが将来に響く懸念はありますか？
10. 相手が**強く出てきた/ブラフを張った**場合、あなたはどう応じ、どこで席を立ちますか？

## 出力フォーマット

ALWAYS この型で出力する（自分の足場 → 相手の推定 → ZOPAと戦術 → 決裂条件）。型を固定し、常にこの構造で返すこと。

```
【交渉の設定】相手: <誰> ／ 論点: <価格/条件/範囲> ／ 期限: <いつまで> ／ 関係: <一度きり/継続>

【自分の足場】
  BATNA（決裂時の最善代替案）: <具体案（複数なら最善を明示）>
  留保価格（撤退ライン）:      <これより悪ければ降りる、の1本>
  中核の利害（なぜ）:          <立場の裏にある譲れない理由>
  目標値（狙う着地）:          <BATNAより十分良い理想値>

【相手の推定】※不確実は幅で
  相手のBATNA:      <相手が決裂時に取れる手>
  相手の留保価格:    <相手の撤退ラインの推定（根拠）>
  相手の利害:        <相手がこの交渉で満たしたい核>

【ZOPA と戦術】
  ZOPA（合意可能圏): <双方の留保価格の重なり／無ければ「負・要価値創造」>
  相互利益オプション: <パイを広げる交換材料（金額以外の論点）を複数>
  客観的基準:        <譲歩を正当化する外部基準（相場/前例/見積）>
  初手と譲歩計画:    <最初の提示 → 見返り付き譲歩の順序>

【次の一手】<交渉前に潰すべき準備・検証すべき前提を1〜3個。相手BATNAの裏取り・代替案強化など>
【未確認の前提】<相手の留保価格/BATNAの推定、ZOPAの境界、ブラフの可能性——裏取りが要る点>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の企業名・数値は用いない）。**あるフリーランス開発者が、既存クライアントからの
継続案件の単価改定（値上げ交渉）に臨む**場面。

- **手順①設定**: 相手＝既存クライアントの発注担当、論点＝次期契約の月額単価と稼働時間、期限＝現契約の更新月。関係＝継続。
- **手順②BATNA**: 決裂時の代替案を列挙——(a)別クライアントの引き合いを受ける、(b)現単価のまま継続、(c)稼働を減らして別案件と兼業。
  引き合い(a)の条件を具体化し、それが最善BATNAと判断（曖昧なら交渉前に引き合いを固めておくのが先決）。
- **手順③留保価格**: 最善BATNA(a)の実質時給に換算し、「これを下回る改定なら現クライアントは降りて(a)へ移る」撤退ラインを1本引く。
- **手順④利害**: 自分の立場＝「単価を上げたい」／利害＝「稼働に見合う収益と、スキル向上につながる仕事」。
  相手の立場＝「単価は据え置きたい」／利害（推定）＝「予算枠の維持と、慣れた開発者の離脱回避」。
- **手順⑤相手の推定**: 相手のBATNA＝新規開発者を探す（引き継ぎコスト大）。相手の留保価格＝「乗り換えコストを考えれば一定の値上げは飲む」と推定（幅で保持）。
- **手順⑥ZOPA**: 自分の撤退ラインと相手の推定上限の間に**正の重なりがありそう**＝妥結可能圏あり、と判断。
- **手順⑦オプション**: 単価だけでなく、稼働時間の調整・複数月コミットによる割引・優先対応の保証・成果ベースの加算——と交換材料を量産。
- **手順⑧客観的基準**: 同等スキルの市場相場、過去の成果指標、引き継ぎコストの試算を根拠として用意。
- **手順⑨初手と譲歩**: 目標値をやや上回る額でアンカーし、相手が渋れば「複数月コミットと引き換えに刻んだ譲歩」を順に出す（留保価格は割らない）。
- **手順⑩決裂条件・次の一手**: 撤退ライン割れなら(a)へ移行、と事前に決める。次の一手＝交渉前に引き合い(a)の条件を書面で固める（BATNA強化）。
- **未確認の前提**: 相手の予算枠と留保価格は推定にすぎない。引き合い(a)の確度も要裏取り——ここが甘いとBATNA過信になる。

## 相性（組み合わせると効く）

- `stakeholder-analysis`: 「誰と交渉し・誰を巻き込むか」の関係者マップを先に描く**前工程**。相手が特定できたら本スキルへ渡す。
- `premortem`: 「この交渉は決裂した」と仮定して失敗筋を逆算し、準備の穴（甘いBATNA・読み違い）を先回りで塞ぐ揺さぶり枠。
- `red-team`: 相手の立場に立って本格的に自分の提案を攻撃し、相手のBATNA・反論・ブラフを事前に読む。ZOPA推定の精度を上げる。
- `devils-advocate`: 「自分のBATNAは本当にそんなに強いか」という過信（Sebeniusの警告）を叩き、留保価格の甘さを検める。
- `decision-matrix`: 手順⑦で出した相互利益オプションや複数のBATNA候補を、多基準で採点して比較する後工程。
- 補助として `jtbd`／`five-whys`（相手の立場の裏の利害＝真のニーズを掘る前工程）、
  `payoff-matrix`（相手の出方と自分の手の利得構造を整理し、初手・譲歩を設計する）を添えると、
  「立場の綱引き」から「利害に基づく価値創造」への組み替えが進む。
