# カスタマージャーニーマップ

## 概要

カスタマージャーニーマップは、ある顧客（アクター/ペルソナ）が**目標を達成するまでの過程**を時間軸に沿って
「**行動 / 思考 / 感情 / タッチポイント**」で可視化し、**痛点(pain point)・摩擦・感情の谷**と**改善機会**を
発見するフレームワーク。Nielsen Norman Group の定義では「人が目標を達成するために経る**プロセスの可視化**」で、
**ストーリーテリング（物語）とビジュアライゼーション（一枚図）**の掛け合わせでチームの認識を揃える道具。

- **核となる考え方**: 会社の都合（部門・チャネル別のサイロ）でなく、**顧客の一連の体験**を横串で並べ替える。
  すると、個々の接点は良くても**繋ぎ目で顧客が躓く**箇所（感情の谷）が見え、そこが最大の改善機会になる。
- **標準構造（NN/g の3ゾーン）**:

| ゾーン | 中身 | 問い |
|---|---|---|
| **A. レンズ（枠組み）** | アクター（ペルソナ）＋シナリオ・ゴール | 「誰の」「何を達成する」旅か |
| **B. 体験本体** | フェーズ（段階）× 行動 / タッチポイント / 思考 / 感情曲線 / 痛点 | 顧客は各段階で何をし、何を感じるか |
| **C. アウトプット** | インサイト・改善機会 ＋ **内部オーナー** | どこを誰が直すか |

- **出自（諸説あり・単一の考案者はいない）**: 数十年の CX/UX 発展の産物とされる。先行ツールとして
  **G. Lynn Shostack** の「サービスブループリント」（HBR 1984年）が挙げられ、**McKinsey** は2009年に直線ファネルを
  円環モデル（**消費者意思決定ジャーニー / ロイヤルティループ**）へ置き換えた。個別の起源説（人名・年）は
  資料間で食い違うため断定しない（→出典・要確認項目）。

## いつ使う / 使わない

**使う（適する状況）**
- **一連の順序だった体験**（購入・申込・オンボーディング・サポート・旅行など）や**プロセス**を対象にするとき。
- 顧客が**どこで離脱・離反・不満を感じているか**（痛点・摩擦）を、接点をまたいで特定したいとき。
- **複数チャネル**（Web・アプリ・店頭・電話・レビュー・口コミ）にまたがる体験を1枚に束ねたいとき。
- 部門バラバラの施策を**顧客視点で横串を通し**、関係者の合意形成・優先順位づけをしたいとき。
- 定性調査（インタビュー・観察・サポートログ）で得た顧客理解を、**行動に落とす器**が欲しいとき。

**使わない / よくある誤用（アンチパターン）**
- **想定だけで描く（データ欠如）**——最頻・最重の失敗。「顧客はこう動くはず」という社内の思い込みで埋めると、
  もっともらしいが**誤った地図**になる。最低限のインタビュー/観察/ログで接地する（無ければ壁打ちで補い、推測と明示）。
- **会社視点＝工程図(process map)になる**——「社内審査」「申請受付」など**自社の業務フロー**を並べてしまい、
  顧客の体験になっていない。各行を「これは**顧客が**する/感じることか？」で検算する。
- **タッチポイント近視眼(touchpoint myopia)**——決済画面など"お気に入り接点"だけ最適化し、影響の大きい他所
  （購入後サポート等）を放置する。旅全体で優先順位を見る。
- **単一の直線に単純化しすぎ**——実際は分岐する複数経路を、無理に1本の規定ルートに押し込め、現実と乖離する。
- **感情を描かない/浅い**——感情の山谷（体験の勝敗が決まる瞬間）を欠くと、ただの接点リストになる。
- **作って放置（静的な壁の額縁）**——一度作って"チェック箱"を埋めて終わり。改善アクションもオーナーも無く陳腐化する。
- 精緻な定量最適化（コンバージョン率のA/Bや統計分析）そのものには不向き。アナリティクス/ファネル分析で補完する。

## 前提と限界

- **前提**: (1) **対象アクター（ペルソナ）とシナリオ・ゴールが1つに定まっている**こと。曖昧なままだと「誰の旅か」が
  ぶれて発散する（未定なら persona / jtbd を先に回す）。(2) **顧客の実データ**（定性中心）にアクセスできること。
  想定で埋めた地図は誤った確信を生むため、事実と推測を必ず区別する。
- **限界**:
  - **定性的で主観が入りやすい**——サンプルの偏りや作り手のバイアスで、実態と違う旅を"正しい"と誤認しやすい。
    複数の顧客・データ源で裏を取る。
  - **一本の地図は複雑な現実を単純化する**——セグメント/経路が複数あるなら地図を分ける（1ペルソナ=1シナリオ）。
  - **静的で環境変化に弱い**——チャネルや顧客行動が変われば地図も陳腐化する。定期的に更新する前提で使う。
  - **地図はゴールでなく起点**——痛点を可視化しても、**オーナーとアクションが無ければ何も変わらない**
    （地図作成に予算を使い切り、改善に残さないのが典型の失敗）。
- これらは、**入力の精度を persona / jtbd で上げる / 痛点を value-proposition-canvas で打ち手に変換する /
  裏側の業務までは service blueprint 的に拡張する / 想定を reverse-assumption・devils-advocate で疑う**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。

1. **目的（why/what）を1つに固定する。** 「この地図で何を良くするか」（例: オンボーディングの離脱を減らす／
   問い合わせを減らす）を明文化する。なぜ: 目的の無い地図は"きれいだが使えない"に堕ちる最頻の失敗。
2. **アクターとシナリオ・ゴールを決める（Zone A）。** 誰（ペルソナ）が、どんな状況で、何を達成しようとする旅か。
   なぜ: 「誰の旅か」が定まらないと、全段階で判断がぶれる。ペルソナ未定なら persona、根底の用事なら jtbd を先に。
3. **定性データで接地する。** インタビュー・行動観察・サポート/レビュー・アナリティクスから、実際の行動・言葉・
   感情を集める。なぜ: 想定で埋めるのが最大の誤用。事実と推測を分け、推測は印を付けて残す。
4. **フェーズ（段階）を先に置き、骨格を作る。** 顧客の現実に合う段階に区切る（例: 認知→比較検討→購入→
   利用開始→継続/離反）。テンプレの固定段階を鵜呑みにせず、対象の実態に合わせる。なぜ: 骨格が先だと接点が整理できる。
5. **各フェーズに 行動 / タッチポイント・チャネル / 思考・疑問 / 感情 / 痛点 を配置する（Zone B）。**
   各行を「これは**顧客が**する・感じることか？（自社の工程でないか）」で検算する。なぜ: 会社視点＝工程図化を防ぐ。
6. **感情曲線を描き、谷（moments that matter）を特定する。** 期待と現実のギャップが大きい山谷に印を付ける。
   なぜ: 体験の勝敗はこの瞬間で決まる。ここが最優先の改善候補。
7. **インサイトと改善機会を抽出し、各機会に内部オーナーを割り当てる（Zone C）。** 影響度×実現性で優先順位をつける。
   なぜ: オーナーとアクションが無い地図は行動を生まない。ここでSWOT/VPC等の打ち手変換に橋渡しする。
8. **次の一手に落とし、生きた文書として更新する。** 検証すべき仮説・施策を1〜3個決め、定点で見直す。
   なぜ: 地図は起点。作って終わりにせず、環境変化に追随させる。

## 壁打ち質問リスト

各要素を事実で埋めるために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す（想定は推測と明示）。

1. この地図で**最終的に良くしたいこと**は何ですか？（離脱を減らす／満足度を上げる／問い合わせを減らす等、目的を1つに）
2. **誰の旅**をマップしますか？（ペルソナ/セグメント）その人は**どんな状況で、何を達成しようとして**いますか（ゴール）？
3. 顧客の実際の行動・気持ちについて、**手元にあるデータ**は何ですか？（インタビュー・行動ログ・サポート記録・レビュー・アンケート）
   まだ**確認できていない前提**はどれですか？（＝推測と事実の切り分け）
4. 顧客はこの体験で**どんな段階（フェーズ）**を通りますか？ 各段階で顧客が**取る行動**と、接触する**タッチポイント/チャネル**
   （Web・アプリ・店頭・電話・レビュー・口コミ等）は何ですか？
5. 各段階で顧客は**何を考え・何に不安や疑問**を感じ、**感情はどこで上がり/下がり**ますか？
   一番の**痛点・摩擦（谷）**はどこですか？
6. その痛点は**どのくらいの顧客に、どれだけの影響**を与えていますか？（頻度・深刻度）また**自社内の誰が**そこを担当していますか？
7. 見えている接点は**顧客体験の一部だけ**になっていませんか？（購入前の情報収集や口コミ、購入後のサポート等、抜けている領域は？）

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。オンライン学習サービスが「無料登録者の有料転換が伸びない」を
改善するため、ジャーニーを描く場面。

- **手順①目的**: 「無料登録から**最初の学習完了→有料転換**までの離脱を減らす」。
- **手順②アクター/シナリオ**: ペルソナ=「スキルを独学したい社会人」。シナリオ=広告で知り、無料登録して学び始める旅。
- **手順③接地**: 登録後の行動ログ、離脱者へのアンケート、サポート問い合わせを確認（＝想定でなく事実で埋める）。
- **手順④フェーズ**: 認知 → 登録 → 初回学習 → 継続 → 有料転換。
- **手順⑤配置（Zone B）**:
  - 認知: 行動=広告/検索で流入、タッチポイント=SNS/検索、思考「自分に合う？」、感情=中。
  - 登録: 行動=無料登録、タッチポイント=登録フォーム、思考「手間は？」、痛点=入力項目が多く離脱。
  - 初回学習: 行動=最初の教材を開く、思考「何から始める？」、感情の谷★=どこから手を付けるか分からず放置。
  - 継続: 行動=再訪、痛点=学習が続かない、リマインドが刺さらない。
  - 有料転換: 行動=価格ページ閲覧、思考「払う価値は？」、痛点=無料で得た価値を実感する前に課金案内が来る。
- **手順⑥感情曲線**: 最大の谷は「初回学習の入口（何から始めるか不明）」。ここで多くが放置に至ると特定。
- **手順⑦機会/オーナー（Zone C）**:
  - ★初回学習の谷 → 機会: 登録直後に「最初の一歩」を提示するオンボーディング導線 ／ オーナー: プロダクト。
  - 登録フォーム離脱 → 機会: 入力項目を必須最小限に削減 ／ オーナー: 成長/マーケ。
  - 早すぎる課金案内 → 機会: 価値実感（初回学習完了）の後に転換訴求を出す ／ オーナー: CRM。
- **手順⑧次の一手**: 「初回オンボーディング導線」を小さく試し、**初回学習完了率**という仮説を検証する。
- **未確認の前提**: 離脱の主因が「入口の分かりにくさ」か「動機自体の弱さ」か——アンケート/インタビューで裏取りが要る
  （想定のまま施策化しない）。

## 相性（組み合わせると効く）

- `persona`: ジャーニーの主語（アクター）を具体化する直接の前工程。ペルソナが甘いと旅全体がぶれる（手順②の入力）。
- `jtbd`: 顧客が根底で片付けたい「用事（ジョブ）」を定義し、シナリオ・ゴールと感情の意味づけを深める（異なるレンズ）。
- `purchase-behavior`（AIDMA/AISAS）: 認知→購買のフェーズ設計の骨格を与え、段階の抜け漏れを防ぐ。
- `value-proposition-canvas`: 地図で見つけた痛点・機会（Zone C）を、提供価値（pain reliever/gain creator）へ変換する後工程。
- `4c-marketing`: タッチポイント/チャネルを買い手視点（利便性・コミュニケーション）で点検し、接点設計に落とす。
- `stp`: 「誰の旅を描くか」を決めるセグメント/ターゲティングの上流。複数セグメントなら地図を分ける判断に使う。
- 揺さぶり枠として `reverse-assumption`（「顧客は実は逆の順路/動機では？」と想定を反転）や
  `devils-advocate`（「この地図は社内の思い込みでは？」と接地を疑う）、`premortem`（施策が失敗する筋を先回り）を添えると、
  最頻の失敗＝想定で描く罠を回避できる。
