# AARRR（海賊指標）／ノーススターメトリック

## 概要

AARRR は、プロダクトの成長を **顧客ライフサイクルの5段階** で計測し、
**段ごとのコンバージョン率から最も弱い段（ボトルネック）を特定して、そこに集中投資する** ためのフレームワーク。
Dave McClure が2007年に "Startup Metrics for Pirates" として提示し、頭字語が海賊の唸り声「アー！」に聞こえることから海賊指標と呼ばれる。

| 段階 | 問い | 代表指標の例 |
|---|---|---|
| **Acquisition（獲得）** | ユーザーはどこから来て到達したか | 訪問数・DL数・LP流入・流入元別サインアップ |
| **Activation（活性化）** | 初回に「価値ある体験(aha)」に届いたか | オンボーディング完了率・初週の中核アクション到達率 |
| **Retention（継続）** | 再訪・再利用しているか | n日/週/月後の復帰率・利用頻度・定着コホート |
| **Referral（紹介）** | 他者に薦めているか | 招待数・バイラル係数・口コミ経由の新規・レビュー |
| **Revenue（収益）** | 収益化できているか | 課金転換率・MRR/ARR・ARPU・LTV |

- **核となる考え方**: マーケが Acquisition（集客）だけに偏るのを戒め、**ライフサイクル全体を数値化**する。
  各段のコンバージョン率を並べて**一番漏れている段（ボトルネック）を1つ特定**し、全部を薄く改善せずそこに集中する。
- **North Star Metric（NSM）**: AARRR が「面（どこを測り直すか）」なら、NSM は「点集中（全社で1つ何を追うか）」。
  **プロダクトの中核価値を最もよく捉え、持続的成長を牽引する単一の先行指標**を北極星に据え、その **入力指標（input metrics, 通例3〜5個）** として
  活性化率・継続率・紹介係数などAARRR各段を配置する。NSMが上がれば施策が効いている、停滞すれば売上に響く前の早期警告になる。
- **AARRRとNSMの関係**: NSMを頂点、AARRRを頂点を動かす計器盤、と重ねて使うのが実務の定石。順序は固定でなく、
  課題に応じて計測対象を選ぶ。
- **出自（要確認あり）**: AARRR は **Dave McClure (2007)**。NSM は **Sean Ellis**（グロースハッキングの命名者）に用語が帰属するとされ、
  **Amplitude** が2017年以降 "The North Star Playbook"（**John Cutler** ら共著）で枠組み化・普及させた（一次の初出は弱い→出典/要確認）。

## いつ使う / 使わない

**使う（適する状況）**
- 成長指標が乱立し、**チームが何を追うべきか揃っていない**とき。北極星に据える1指標を決めたいとき。
- 獲得はできるのに **定着・収益化しない**、どの段が漏れているか（ボトルネック）を数値で特定したいとき。
- プロダクトの **どこを直せば成長が伸びるか**、改善の優先順位を1枚で俯瞰したいとき。
- グロースの打ち手が発散しており、**計測点と改善対象を構造化**したいとき。
- プロダクト主導成長（PLG）で、**購買後の継続・紹介・収益まで含むループ**を管理したいとき。

**使わない / よくある誤用（アンチパターン）**
- **購買前の認知ファネル整理に流用する**——認知→興味→購買のマス広告的ファネルは purchase-behavior（AIDMA/AISAS）の領域。
  AARRR は購買後まで含むプロダクト内行動が本領。混同すると Acquisition だけの薄い分析になる。
- **NSMに売上系（遅行指標）を据える**——最頻の誤用。MRR/ARR/ARPU は「過去に起きたこと」を映す遅行指標。
  NSMは**顧客価値の先行指標**であるべき。売上は結果であって北極星にすると打ち手が遅れる。
- **NSMをバニティ指標にする**——DL数・登録者数・PV・広告表示のように「見栄えは良いが価値と繋がらない」指標を選ぶと、
  数字は伸びても事業が伸びない。中核価値を表す行動量を選ぶ。
- **獲得偏重（穴の空いたバケツ）**——継続(Retention)が壊れたまま獲得に投資すると流入がザルから漏れる。
  この批判が RARRA（Retention 先頭の並べ替え, Petit & Papp 2017前後）を生んだ。まず継続の底を確認する。
- **5段を全部同時に改善しようとする**——リソースが薄く広がり効かない。**最弱の1段に集中**するのが趣旨。
- **段のコンバージョン率を定義せず眺める**——分母・分子・期間を決めずに率を出すと段間比較が崩れる。定義を固定する。
- **NSMを立てて放置する**——市場・プロダクトの変化で中核価値はずれる。入力指標との連動が切れたら見直す。

## 前提と限界

- **前提**: (1) 段ごとのイベントを**計測できる**こと（分析基盤・イベント設計。無ければまず計測設計から）。
  (2) 各段のコンバージョン率を**分母・分子・期間で一貫定義**できること。(3) プロダクトの**中核価値が言語化**できること
  （NSM選定の土台）。曖昧なら壁打ちで補うか、customer-journey / jtbd を前工程に置く。
- **限界（批判を踏まえて）**:
  - **順序は絶対でない**——AARRR の綴りどおりの線形順で埋めると獲得偏重に陥る。RARRA（継続先頭）の指摘のとおり、
    どの段を先に見るかは事業状況で変える。
  - **段の定義に恣意性**——「活性化」の到達点（aha体験）や「継続」の期間の置き方で数字が動く。定義を明示し一貫させる。
  - **NSMの単一化リスク**——1指標に絞ると、それを局所最適化する歪み（gaming）が起きる。ガードレール指標や入力指標で補正する。
  - **企業別NSM例の鵜呑み**——他社NSM（後述の要確認例）は文脈依存。自社の中核価値から導出し、コピーしない。
  - **BtoB/長期購買サイクルへの適用限界**——単純なプロダクト内行動で活性化を測りにくい業態では段の再定義が要る。
- これらは、**中核価値の掘り下げを jtbd/customer-journey で、採算の裏取りを unit-economics で、
  仮説検証の回し方を lean-startup-mvp で、盲点の揺さぶりを premortem/devils-advocate で** 補って埋める（→相性）。

## 進め方（手順）

命令形で示す。各ステップに「なぜ」を添える。**全段を薄く触るのでなく、最弱の1段とNSM1つに絞る**のが肝。

1. **目的と対象プロダクト/顧客を1つに固定する。** 「何を決めるための計測か」（北極星の選定／ボトルネックの特定／改善の優先順位）と、
   対象プロダクトと主要ユーザー像を明文化する。
   なぜ: 目的が曖昧だと段の定義もNSMもぶれる。土俵を1つに絞って初めて段間の比較が意味を持つ。
2. **プロダクトの中核価値を言語化する。** ユーザーがこのプロダクトで得る「価値ある体験」を1文で書く。
   なぜ: この価値がActivation（aha到達点）とNSM候補の両方を規定する。価値が曖昧なままでは北極星を選べない。
3. **AARRR各段の指標を1つずつ定義する。** 5段それぞれに代表指標を1つ選び、**分母・分子・期間**まで決める（例: 活性化率＝初週にaha到達したサインアップ数÷サインアップ数）。
   なぜ: 定義を固定しないと段間のコンバージョン率が比較できず、ボトルネック特定が成立しない。
4. **各段の現状値とコンバージョン率を並べる。** 実測（無ければ推計＋「要検証」札）を段の順に並べ、段から段への転換率を出す。
   なぜ: 率を横並びにして初めて「どこで一番漏れているか」が見える。絶対数でなく転換率で弱点を探す。
5. **ボトルネック（最弱の1段）を特定する。** 転換率が最も低い、または改善余地×インパクトが最大の段を1つ選ぶ。
   なぜ: リソースは有限。獲得を増やす前に、漏れている段を塞ぐ方が投資対効果が高い（穴の空いたバケツを先に直す）。
6. **North Star Metric を1つ選ぶ。** 中核価値を最もよく捉え、**先行指標であり・実行可能で・広すぎない**指標を北極星に据える。
   売上系（遅行）やバニティ指標を避ける。
   なぜ: 全社の向きを1つに揃えるため。遅行指標を選ぶと打ち手が後手に回り、バニティ指標を選ぶと数字が事業と乖離する。
7. **NSMの入力指標（3〜5個）を紐づける。** NSMを動かす、現場が日々動かせる要因を3〜5個選ぶ（多くはAARRR各段の率）。
   なぜ: NSMは直接いじれない。合わさってNSMを生む入力に分解して初めてチームが手を動かせる。ガードレール指標も添える。
8. **ボトルネック段に集中施策を当て、次の一手に落とす。** 特定した段の改善仮説を立て、検証すべき仮説を1〜3個決める。
   なぜ: 分析で終わらせず改善に接続するのが本題。全段でなく1段に絞った施策の方が効果が測りやすい。

## 壁打ち質問リスト

各段とNSMを事実で埋めるために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。

1. この分析で**最終的に決めたいこと**は何ですか？（北極星の選定／ボトルネックの特定／改善の優先順位／指標の交通整理）
2. 対象の**プロダクトと主要ユーザー**は誰ですか？1つに絞れますか？（複数プロダクトが混ざると段の定義が割れます）
3. ユーザーがこのプロダクトで得る**中核価値**を1文で言えますか？（それがActivationの到達点とNSM候補を決めます）
4. **Activation（活性化）の到達点＝aha体験**は具体的に何ですか？「使い始めた」でなく「価値を実感した」瞬間はどこですか？
5. 5段のうち、いま**イベントを計測できている段・できていない段**はどれですか？（計測できない段はまず設計が要ります）
6. 各段の**コンバージョン率**（分母・分子・期間）はどう定義しますか？いま数字が取れているのはどれですか？
7. 体感として、**一番漏れている・伸び悩んでいる段**はどこだと思いますか？（獲得はできるが定着しない、等）
8. 北極星の候補指標はありますか？それは**売上そのもの（遅行）やDL数（バニティ）になっていませんか**——顧客価値を先取りしていますか？
9. NSMを動かす**入力指標（現場が日々動かせる3〜5個）**として、何が挙がりますか？
10. この計測結果を、どの**意思決定**（グロース施策の優先順位／KPI設計／OKR）に接続しますか？

## 出力フォーマット

ALWAYS この型で出力する（AARRR計測 → ボトルネック → NSM設計 → 次の一手）。型を固定し、常にこの構造で返すこと。

```
【前提】目的: <決めたいこと> ／ 対象: <プロダクト・主要ユーザー> ／ 中核価値: <1文> ／ データ: <実測/推計の別>

【AARRR計測】各段の代表指標（分母/分子/期間）と現状値・転換率
  Acquisition（獲得）:   <指標・値>（定義: …）
  Activation（活性化）:  <指標・値>（aha到達点: …）→ 前段からの転換率: <%>
  Retention（継続）:     <指標・値>（期間: …）→ 転換率: <%>
  Referral（紹介）:      <指標・値>          → 転換率: <%>
  Revenue（収益）:       <指標・値>          → 転換率: <%>

【ボトルネック】最弱の1段: <段名> ／ 根拠: <転換率 or インパクト×改善余地> ／ 獲得偏重(穴の空いたバケツ)の有無: <所見>

【North Star Metric】NSM: <単一指標>（先行指標か: … ／ バニティ・遅行でない理由: …）
  入力指標(3〜5): - <入力1> - <入力2> - <入力3>…
  ガードレール指標: <局所最適化を防ぐ監視指標>

【次の一手】<ボトルネック段の改善仮説・検証すべき仮説を1〜3個。1段集中>
【未確認の前提】<段の定義・計測の有無/サンプル・NSMの妥当性・他社NSM例の流用——裏取りが要る点>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。ある**BtoCのモバイル学習アプリ**が、
獲得はできるのに伸び悩む状況で、追うべき指標と改善対象を決める場面。

- **手順①②目的・中核価値**: 目的=「北極星の選定とボトルネック特定」。対象=「独学で資格勉強する個人ユーザー」。
  中核価値=「毎日少しずつ学習を継続でき、合格に近づく実感を得る」と1文化。
- **手順③④指標定義と現状**: 5段に指標を定義。獲得=DL数、活性化=初週に1レッスン完了した率、継続=登録4週後の週次利用率、
  紹介=招待経由の新規率、収益=有料転換率。各段の転換率を横並びにする（一部は「要検証」札）。
- **手順⑤ボトルネック**: 獲得（DL）は潤沢だが、活性化→継続の転換率が急落していると判明。**継続(Retention)が最弱段**。
  獲得に広告費を足す前に、定着の底が抜けている（穴の空いたバケツ）と診断。
- **手順⑥NSM選定**: 北極星を「有料課金額（遅行）」でも「DL数（バニティ）」でもなく、中核価値を先取りする
  **『週あたり学習を継続したアクティブ学習者数』**に置く。これは合格＝収益に先行する先行指標。
- **手順⑦入力指標**: NSMの入力を、初週レッスン完了率（活性化）／リマインド通知の反応率／連続学習日数の中央値（継続）／
  招待送信率（紹介）の4つに分解。ガードレールに「解約率」を添え、継続を煽って燃え尽きさせる歪みを監視。
- **手順⑧集中施策・次の一手**: 最弱段（継続）に絞り、オンボーディング直後の学習習慣づけ（初週の再訪トリガー）を改善仮説として立てる。
- **次の一手**: 初週リテンション施策をA/Bで検証し、活性化→継続の転換率が動くかを計測してから獲得投資を再開する。
- **未確認の前提**: 各段の期間定義とサンプルの厚み、aha到達点が「1レッスン完了」で妥当か、NSMが本当に収益に先行するか——実データで裏取りが要る。

## 相性（組み合わせると効く）

- `purchase-behavior`: 認知→購買の**マス広告ファネル**（AIDMA/AISAS）を、AARRRの Acquisition/Activation の**前段**として接続。購買前と購買後で役割分担する。
- `kgi-kpi-okr`: 目標の階層分解体系に、AARRR/NSMが「**頂点に何を置くか（顧客価値の先行指標）**」と「計測すべき5段」を供給する。NSM=KPIツリーの頂点、入力指標=下位KPI。
- `unit-economics`: Revenue段の裏で、LTV・CAC・回収期間の**採算構造**を検証。継続改善がLTVに効くかを金額で裏取りする。
- `rfm`: Retention/Revenue段の内訳として、優良顧客（Recency/Frequency/Monetary）を抽出し、継続・収益施策の**ターゲットを精緻化**。
- `lean-startup-mvp`: ボトルネック段の**改善仮説を検証**する回し方（Build-Measure-Learn）を供給。AARRR=計測、MVP=検証実験の実行部。
- `customer-journey`: 各段の裏にある**体験の時系列**（接点・感情）を描き、活性化の aha 到達点や継続の離脱点を発見する前工程。
- `service-blueprint`: 継続・活性化を支える**裏側のオペレーション**を可視化し、指標が動かない原因を舞台裏に探す。
- `kpt`: 施策のふりかえり（Keep/Problem/Try）で、AARRR改善サイクルを**運用ループに乗せる**後工程。
- 揺さぶり枠として `premortem`（NSMの局所最適化や獲得偏重が失敗を招く筋を先回り）、
  `devils-advocate`（「これが北極星だ」という思い込みを疑う）を添えると盲点が減る。
