## 1. 三層の定義と因果の向き

- **KGI（重要目標達成指標 / Key Goal Indicator）**: 最終ゴールの到達度を測る**成果（遅行）指標**。「何を・どれだけ・いつまでに」。原則**1つ**に絞る。
- **KSF / CSF（重要成功要因 / Key/Critical Success Factor）**: KGIを達成するうえで決定的に効く**要因・プロセス**。多くは定性的。「何が効くのか」の仮説。
- **KPI（重要業績評価指標 / Key Performance Indicator）**: KSFを測る**中間（先行）指標**。定量で、日々〜週次で動かせる。
- **因果の向き**: KPI（動かす）→ KSF（効く要因が満たされる）→ KGI（ゴールが動く）。この連鎖は**検証すべき仮説**であり、自明ではない。

## 2. 設計手順（KGIから分解する）

1. **KGIを1つ確定**する（例: 期末の売上／解約率／利益率などを、数値・期限つきで）。
2. **KGIを構成要素に分解**する（例: 売上＝顧客数×客単価×購入頻度）。恒等式・ドライバー分解を使うと漏れにくい。
3. 各要素について「**何が効くのか（KSF）**」を問い、重要な成功要因を絞る。
4. 各KSFに**測れるKPI**を割り当てる（KSFを代理測定する先行指標）。
5. **ツリーを検算**する: 「下位KPIが全部改善したら、上位（最終的にKGI）は本当に動くか？」を各分岐で問う。動かないなら分解か指標が誤り。
6. **数を絞る**: 追える数（各層で数個）に限定。多すぎるKPIは監視されず形骸化する。

## 3. MECEで分解する（漏れ・ダブりを潰す）

- 各分岐は **MECE（Mutually Exclusive, Collectively Exhaustive＝漏れなくダブりなく）** を狙う。
- **ダブり**: 同じ動きを二重に数えるKPIは、片方が改善しても実態が伴わない錯覚を生む。
- **漏れ**: KGIを動かす主要ドライバーが抜けると、KPIを全達成してもKGIが動かない。
- 掛け算分解（売上＝A×B×C）や、ファネル分解（認知→検討→購入→継続）は漏れを抑えやすい。

## 4. 先行指標と遅行指標

- **遅行指標（lagging）**: 結果が出てから分かる（例: 売上、解約率）。KGIはたいてい遅行。
- **先行指標（leading）**: 結果に**先立って動き、予告する**（例: 商談数、トライアル利用率）。良いKPIは先行指標を選ぶ——遅行だけだと手を打つ頃には手遅れ。
- ペアで持つ: 遅行（KGI）で「どこへ」を、先行（KPI）で「今どう手を打つか」を見る。

## 5. 指標の品質チェック（SMART）

各指標（KGI/KPI）を **SMART** で点検する:
- **S**pecific（具体的）／**M**easurable（測定可能）／**A**chievable（達成可能）／**R**elevant（ゴールに関連）／**T**ime-bound（期限あり）。
- 特に **Relevant** が弱いと「測れるが効かない」虚栄の指標（vanity metric）になる。KGIとの因果でつながっているかを常に問う。

## 6. アンチパターン

- **虚栄の指標（vanity metrics）**: 見栄えは良いが意思決定に効かない（例: 累計登録数だけ）。判断を変える指標を選ぶ。
- **KGIとの断絶**: KPIを追ってもKGIが動かない＝因果仮説が未検証／誤り。定期的に相関・寄与を検証する。
- **指標の乱立**: 追いきれない数のKPIは監視されない。各層で重要数個に絞る。
- **手段の目的化（Goodhart）**: KPI自体が目的化し、数字合わせ（ゲーミング）が起きる。指標は目的の代理であることを忘れない。
