# KGI/KPI/OKR

## 概要

KGI/KPI/OKR は、**「最終的に何を達成するか」を数値化し、そこへ至る中間指標へ分解し、期間ごとに挑戦的な目標を立てて進捗を測る**、目標と指標のマネジメント体系。互いに補完する2系統からなる。

**系統1: KGI → KSF → KPI（ゴールを分解して管理する軸）**

| 用語 | 読み・英名 | 役割 | 性質 |
|---|---|---|---|
| **KGI** | 重要目標達成指標 / Key Goal Indicator | 最終ゴールの到達度（何を・どれだけ・いつまでに） | 成果＝**遅行**指標。原則1つ |
| **KSF/CSF** | 重要成功要因 / Key (Critical) Success Factor | KGI達成に決定的に効く要因・プロセス（「何が効くか」） | 多くは**定性**的 |
| **KPI** | 重要業績評価指標 / Key Performance Indicator | KSFを測る中間指標 | 定量＝**先行**指標が望ましい |

因果の向きは **KPIを動かす → KSFが満たされる → KGIが動く**。これは自明でなく**検証すべき仮説**。KGIを頂点にロジックツリーで分解した図が **KPIツリー**で、MECE（漏れなくダブりなく）に割るほど精度が上がる。

**系統2: OKR（Objectives and Key Results）（挑戦を仕掛けて進捗を測る軸）**

- **Objective（目標）**＝達成したい定性的で鼓舞的な「何を」。**Key Results（主要な結果）＝3〜5個**の、達成を議論なく判定できる測定可能な成功基準。定型は「**I will〈Objective〉as measured by〈Key Results〉**」。
- **KPIは"定常業務(BAU)の健全性を監視する"、OKRは"変化を起こす挑戦的目標"**。KPIは何が起きているかを見せ、OKRはそれを良くする。両者は併用できる（→本体末尾・references）。

**出自（要確認扱い・年号/人名は断定回避）**
- **OKR**: **アンディ・グローブ**が1970年代に Intel で導入（自著『High Output Management』1983）。**ピーター・ドラッカーのMBO（1950年代）**の発展形とされる（二次資料で扱いが割れる）。**ジョン・ドーア**が Intel で学び1999年頃 Google に紹介、著書『Measure What Matters』(2018)。"OKR" の名称はドーアによるとされる。
- **KGI**: 用語としては IT ガバナンス標準 **COBIT**（ITGI/ISACA系）が2000年の Management Guidelines で KGI/KPI を定義した系統がある（COBIT 2019 で呼称整理）。「KGI/KSF/KPIのトリオ」としての普及は日本の実務慣用。**単一の起源に断定しない**（→出典・要確認）。

## いつ使う / 使わない

**使う（適する状況）**
- 最終ゴールを**数値目標に落とし**、そこへ至る中間指標へ**分解**して管理したいとき（KGI→KSF→KPI／KPIツリー）。
- 全社・部門・チーム・個人の目標を**階層で揃え（アライメント）**、focus を作りたいとき。
- 四半期などの期間で**挑戦的な変化を仕掛け、進捗を可視化**したいとき（OKR）。
- 「目標は立てるが達成されない／何を追えばいいか分からない」を、**因果でつながった指標**に整理したいとき。
- KPIとOKRの**違い・使い分け**を判断したいとき。

**使わない / よくある誤用（アンチパターン）**
- **目的・戦略が未定のまま指標だけ作る**——効かない指標が量産される。先に戦略/現状分析（swot・backcasting等）で方向を決める。
- **指標を報酬・人事評価に直結させる**——**Goodhartの法則**「指標が目標になると良い指標でなくなる」。数字のゲーミングやサンドバッギング（低い目標を置く）を招く。OKRは評価と**切り離す**のが定石。
- **Key Results（手段）とObjective（目的）の取り違え**——KRを追ってObjectiveを見失う最頻の失敗。KRを全達成してもObjectiveに届かないなら設計ミス。
- **KRやKPIをactivity/output（やること・作った量）で書く**——outcome（成果・状態変化）で書く。
- **KGIとKPIの断絶**——KPIを全達成してもKGIが動かない（因果仮説が未検証/誤り）。
- **指標の乱立・虚栄の指標（vanity metrics）**——追えない数、意思決定を変えない数字。各層で重要数個に絞る。
- **作って放置（set-and-forget）**——週次/隔週のチェックインが無いと形骸化する。

## 前提と限界

- **前提**: 目的・戦略の方向が定まっていること（KGIは戦略の従属変数）。方向が曖昧なら先に戦略/発想フレームで決める。KSF→KPIの因果は**仮説**であり、データで検証しながら使う。
- **限界（批判を踏まえて）**:
  - **測れるものへの偏り**: 数値化しやすい指標に注意が寄り、重要だが測りにくい価値（品質・信頼・学習）が軽視されやすい。定性のKSFやコミット型OKRで補う。
  - **Goodhartの法則**: 指標が目標化すると代理が本体を歪める。報酬連動を避け、指標は目的の代理と自覚する。
  - **短期偏重**: 四半期の数値に最適化すると長期の投資を削りがち。年次OKRや先行指標で時間軸を補正する。
  - **OKRの型宣言**: アスピレーショナル（0.7前後で成功）とコミット（1.0前提）を混同すると採点の意味が壊れる。**開始前に型を宣言**する。
- これらは、**KGI設定にbackcastingで長期視点を、KPI分解にlogic-tree/meceで網羅性を、運用にpdcaで振り返りを、目標の妥当性検証にpremortem/devils-advocateで揺さぶり**を足すと補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。詳細は references（`kpi-tree-design.md` / `okr-playbook.md`）に退避——本体では**どのサブツールをいつ使うか**を示す。

**まず分岐を決める**: 「最終ゴールから中間指標へ分解して管理」が主目的なら **A（KGI/KSF/KPIツリー）**。「四半期で挑戦的な変化を仕掛ける」が主目的なら **B（OKR）**。多くは A で土台を作り B を重ねる。

1. **目的とスコープ・期間を1つに固定する。** 何のための指標か（例: 事業成長／解約改善）、対象（全社/部門/チーム）、期間（四半期/年）を明文化する。
   なぜ: 目的が無いと効かない指標が量産される（最頻の誤用）。

**A. KGI/KSF/KPI（ゴールを分解する）** — 詳細は `references/kpi-tree-design.md`
2. **KGIを1つ、数値・期限つきで確定する。** 「何を・どれだけ・いつまでに」。
   なぜ: ゴールが複数だと優先が割れ、KPIが発散する。
3. **KGIを構成要素に分解する（KPIツリー）。** 恒等式・ドライバー分解（例: 売上＝顧客数×客単価×頻度）やファネル分解を使う。
   なぜ: 掛け算/段階で割ると漏れ・ダブりを抑えやすい。
4. **各要素のKSF（何が効くか）を特定し、測るKPIを割り当てる。** KPIは先行指標を優先。
   なぜ: 遅行指標だけでは手を打つ頃に手遅れ。先行指標で早く動かす。
5. **ツリーを検算する（MECE＋因果）。** 「下位KPIが全改善したらKGIは本当に動くか？」を各分岐で問う。動かなければ分解か指標が誤り。各層は重要数個に絞る。
   なぜ: 因果の断絶と指標乱立が、KPIツリー最大の失敗要因。

**B. OKR（挑戦を仕掛ける）** — 詳細は `references/okr-playbook.md`
6. **Objectiveを2〜4個に絞って立てる。** 定性・鼓舞的・「業務を回す」の言い換えでない、変化を表す「何を」。
   なぜ: 多いとフォーカスが薄れOKRの意味が消える。
7. **各Objectiveに3〜5個のKey Resultsを、outcomeで書く。** 「I will〈O〉as measured by〈KR〉」。activity/outputで書かない。**型（コミット/アスピレーショナル）を宣言**する。
   なぜ: 手段（output）を目的化すると、作業しても成果が動かない。型宣言が採点の前提。
8. **定期レビューのリズムを決める。** 週次/隔週チェックイン（現在値・信頼度・障害・次アクション）＋期末スコアリング（0.0〜1.0）。
   なぜ: チェックインが無いと「作って放置」に堕ちる。採点は評価でなく学習のため。

**共通の締め**
9. **次の一手に落とす。** 立てた指標/OKRから、直近で動かすアクションと検証すべき因果仮説を1〜3個決める。
   なぜ: 指標はゴールでなく手段。ここで止めると「表を作って終わり」になる。

## 壁打ち質問リスト

各要素を事実で埋めるために利用者へ投げ返す問い。空欄を勝手に埋めず、まずこれで引き出す。

1. この目標設定で**最終的に達成したいこと**は何ですか？ それを**数値・期限**で言うと（KGI候補）どうなりますか？
2. 対象と期間は何ですか？（全社／部門／チーム／個人 ・ 四半期／半期／年）そして今回は「**ゴールを分解して管理（KGI/KPI）**」と「**挑戦を仕掛ける（OKR）**」のどちらが主目的ですか？
3. そのゴールを動かす**主要なドライバー**は何だと思いますか？（例: 売上なら顧客数・単価・頻度のどれが効くか＝KSFの仮説）
4. いま追っている指標があれば教えてください。それは**結果が出てから分かる遅行指標**ですか、**早く動かせる先行指標**ですか？ KGIと因果でつながっていますか？
5. （OKRの場合）その目標は「**必ず達成すべき約束（コミット型）**」ですか、「**届けば大成功の挑戦（アスピレーショナル型）**」ですか？ 両者を混ぜていますか？
6. 目標の**進捗を誰が・どのくらいの頻度でレビュー**しますか？（週次チェックインの有無）
7. これらの指標は**評価・報酬に直結**しますか？（直結する場合、数字合わせ＝ゲーミングのリスクをどう避けますか）
8. すでにある**事実・データ**は何で、まだ**検証できていない前提（因果の仮説）**は何ですか？

## 出力フォーマット

ALWAYS この型で出力する。主目的に応じて【A】か【B】を主に、両方あれば併記する。命令形で埋める。

```
■ 前提
  目的: <この指標体系で達成したいこと>  対象/期間: <全社・部門… / 四半期・年>

   └─ KSF③<効く要因>  → KPI: <…>

【B. OKR】（挑戦を仕掛けて測る／期間: 四半期など）

    KR2: <…>
    KR3: <…>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。サブスク型サービスが「解約を減らして継続収益を伸ばす」を検討する場面。

- **手順①目的/スコープ**: 目的＝継続収益の改善。対象＝当該事業、期間＝1年（KGI）＋四半期（OKR）。主目的はまずAで土台、Bで挑戦を重ねる。
- **手順②KGI**: 「年間の継続収益（または解約率）を、期末までに目標水準へ」——最終ゴールを1つ、数値・期限で置く（具体値は実データで設定）。
- **手順③KPIツリー分解**: 継続収益 ≒ 顧客数 × 継続率 × 平均単価、と分解。解約に効くのは「オンボーディング完了」「主要機能の定着」「サポート応答」あたり、と仮説（＝KSF候補）。
- **手順④KSF→KPI**: KSF「初期定着」→ KPI「オンボーディング完了率」「初月アクティブ率」（先行指標）。KSF「サポート品質」→ KPI「一次応答時間」。
- **手順⑤検算（MECE＋因果）**: 「オンボーディング完了率と初月アクティブ率が上がれば、継続率→KGIは本当に動くか？」を問う。ここは相関を検証すべき仮説として明示（推測のまま断定しない）。
- **手順⑥OKR（Objective）**: 「新規顧客が最初の1か月で価値を実感し、離れなくなる」——鼓舞的な「何を」。型はアスピレーショナル（挑戦）と宣言。
- **手順⑦Key Results（outcomeで）**: KR1「初月アクティブ率を現状→目標へ」／KR2「オンボーディング完了率を→目標へ」／KR3「早期解約率を→目標へ」。いずれも"機能をリリースする"（output）でなく状態変化（outcome）で記述。
- **手順⑧レビュー**: 隔週チェックインで各KRの現在値・信頼度・障害を共有。期末に0.0〜1.0で採点し、0.6〜0.7を挑戦の目安に振り返る。
- **手順⑨次の一手**: 「オンボーディング改善」を小さく試し、"完了率↑→継続率↑"の因果仮説を実データで検証する。
- **未確認の前提**: 各KPIとKGIの実際の相関、目標水準の妥当性——ここは自社データで裏取りが必要（数値を捏造しない）。

## 相性（組み合わせると効く）

- `backcasting`: 「あるべき未来」から逆算してKGI（最終ゴール）と道筋を設定する前工程。長期視点で短期偏重を補正する。
- `logic-tree`: KGIをKPIツリーへ分解する骨格。ロジックツリーの技法そのものがKPI分解の中核。
- `mece`: KPIツリーの各分岐を漏れなくダブりなく割り、指標の抜け・二重計上を防ぐ検算に使う。
- `pdca`: 立てたKPI/OKRを回す運用サイクル。週次チェックインと期末振り返り（Check→Act）を担う。
- `decision-matrix`: KPI候補やKSF候補が複数あるとき、影響度×測定容易性などで採用指標を選ぶ。
- 揺さぶり枠として `premortem`（「期末に目標を大きく外した」と仮定し未達要因を先回り）や `devils-advocate`（そのKPIは本当にKGIを動かすか、ゲーミングを招かないかを疑う）を添えると、指標の妥当性検証が深まる。
