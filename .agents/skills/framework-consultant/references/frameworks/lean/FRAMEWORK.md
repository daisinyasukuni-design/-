# リーン生産方式

## 概要

リーン生産方式は、**顧客にとっての価値を最大化しつつ、価値を生まない活動（ムダ）を徹底的に排除する**改善の思想と手法の体系。
トヨタ生産方式(TPS)を、米国の研究チームが他社・他業種でも使える形に一般化・命名したものが「リーン(lean)」である。

- **核となる考え方**: 価値は**最終顧客が定義する**。工程を「価値を生む活動 / 生まない活動（ムダ）」に切り分け、
  後者を削って**流れ(flow)**を作り、顧客の需要に合わせて**引く(pull)**。これを終わりなく繰り返す（カイゼン）。
- **5原則（Womack & Jones『Lean Thinking』1996 が体系化）**: 順に回す。
  1. **価値(Value)**: 何が顧客価値かを顧客視点で特定する。
  2. **価値の流れ(Value Stream)**: 製品/サービスの全工程を洗い出し、価値を生まない段階を可視化する。
  3. **流れ(Flow)**: 価値を生む段階を淀みなく連続させる（停滞・停止をなくす）。
  4. **引く(Pull)**: 顧客需要を起点に上流から引く（作りすぎない）。
  5. **完璧(Perfection)**: 1〜4を繰り返し、ムダゼロへ継続改善する。
- **TPSの2本柱**: **ジャストインタイム(JIT)**（必要なものを必要なときに必要なだけ）と
  **自働化(jidoka)**（異常が起きたら止まる/止め、不良を作らない・流さない・見える化する）。
- **出自（諸説・年号は要確認）**: TPSはトヨタの **大野耐一** を中心に、**豊田英二** の後押しで概ね1948〜1975年に確立された
  （自働化の源流は創業者 **豊田佐吉** の自動織機、JITの発想は **豊田喜一郎** に帰される）。用語「lean」はMITのIMVP研究者
  **John Krafcik** が1988年の論文で命名し、『The Machine That Changed the World』（Womack/Jones/Roos, 1990年頃）で世界に広まった。
  **人名・年号・書誌は断定せず要確認扱い**（→出典・要ファクトチェック）。

## いつ使う / 使わない

**使う（適する状況）**
- **反復性のある工程・業務**（製造ライン、事務処理、受発注、サービス提供など）のムダ・停滞を減らしたいとき。
- **リードタイム短縮・在庫圧縮・不良削減・手待ち解消**など、流れと効率を改善したいとき。
- 「**コスト削減で何から手をつけるか**」を、価値起点で優先順位づけしたいとき（闇雲な一律カットの前に）。
- 作業を**標準化して品質を安定**させたい、現場のカイゼンを回す土台を作りたいとき。
- 製造に限らず**サービス・医療・ソフト開発・バックオフィス**（リーンオフィス等）にも展開できる。

**使わない / よくある誤用（アンチパターン）**
- **道具主義（tool-head）**——最頻の失敗。5S・カンバン等のツールだけ形式導入し、価値・流れ・人（文化）を欠く。
  「リーンはツールの集合ではなく、ツールを含む**思考体系**」。他社の道具を無思考でコピーしても効かない。
- **「リーン＝人員削減／単純コストカット」への矮小化**——ムダ排除を首切りに直結させると、現場の信頼と
  カイゼンの原動力（人）を壊し逆効果。空いた時間・人は付加価値へ振り向けるのが原義。
- **JIT/在庫最小化の行き過ぎ**——単一調達・在庫ゼロを突き詰めると外乱（災害・供給途絶・地政学）に脆い。
  近年は just-in-case（戦略バッファ確保）への揺り戻しも議論される。効率と回復力(resilience)はトレードオフになりうる。
- **局所最適の罠**——一工程だけ速くしても全体は速くならない。制約(ボトルネック)を無視した改善は在庫を増やすだけ（→TOCの視点）。
- **変動の大きい/一品受注/R&D探索の前段には不向き**——流れ化・標準化の前提が崩れる。不確実性が本質の領域は別手法で。
- 統計的な**ばらつき低減**が主目的なら単独では弱い（→シックスシグマを併用＝リーンシックスシグマ）。

## 前提と限界

- **前提**: 対象とする**バリューストリーム（価値の流れ）が識別できる**こと。何を「価値」とするかを顧客視点で言えること。
  現状（工程・リードタイム・在庫・不良率など）を**現地現物（ゲンバ）で観察・計測**できること。推測で工程を語らない。
  改善を続ける**マネジメントの関与と現場参加**があること（トップの号令だけ／現場任せのどちらでも根付かない）。
- **限界（批判を踏まえて）**:
  - **文化・人の変革を伴わないと形骸化**——ツール導入率と成果は一致しない。定着はリーダーシップと教育に依存する。
  - **回復力とのトレードオフ**——効率を極限まで追うとサプライチェーンが脆くなる。何を守り（顧客・供給の連続性）、
    どこにバッファを残すかを戦略的に決める必要がある。
  - **ムダだけ見て「ムラ・ムリ」を見落とす**——負荷の不均一(ムラ)や過負荷(ムリ)がムダの真因のことが多い。3M（ムダ/ムラ/ムリ）で見る。
  - **短期のコスト指標だけで評価すると迷走**——リードタイム・品質・学習など長期の効果を併せて見ないと現場が疲弊する。
- これらは、**制約が支配的ならTOCを先に／ばらつきにはシックスシグマ／真因はなぜなぜ・特性要因図／
  失敗の先回りはプレモータム**を併用することで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。**個々のムダ潰しに走る前に、価値と流れを先に定義する**のが要。

1. **顧客価値を特定する。** 対象の製品/サービスについて「顧客は何に対価を払うのか（何が価値か）」を顧客視点で言語化する。
   なぜ: 価値の定義がないと「何がムダか」を判定できず、社内都合の効率化に陥る。リーンの起点は常に顧客価値。
2. **対象バリューストリームとスコープを1つに絞る。** 改善する製品ファミリー/業務フローを決め、始点と終点を固定する。
   なぜ: 範囲が発散すると全工程を薄く触って成果が出ない。1本の流れに絞って端から端まで見る。
3. **現状の流れを可視化する（現地現物）。** 各工程・所要時間・停滞・在庫・手戻りを、ゲンバで観察・計測して図にする（VSM等）。
   なぜ: 机上の想定は実際とずれる。付加価値時間 対 リードタイム全体の比（多くは数%）を可視化すると、ムダの所在が見える。
4. **7つのムダを洗い出す。** 各工程を次の観点で点検する。**作りすぎ**（最も悪い＝他のムダを誘発）／手待ち／運搬／
   加工そのもの・過剰品質／在庫／動作／不良・手直し（＋人の能力の未活用）。
   なぜ: ムダを類型で見ると見落としが減る。特に「作りすぎ」は在庫・運搬・手待ちを連鎖的に生むため最優先で疑う。
5. **ムラ・ムリも合わせて診る。** 負荷の波（ムラ）や人・設備への過負荷（ムリ）がムダの真因でないかを確認する。
   なぜ: ムダはムラ・ムリの結果として現れることが多い。表面のムダだけ潰すとモグラ叩きになる。
6. **真因を特定してから対策する。** 主要なムダについて「なぜ起きるか」を掘り下げる（なぜなぜ分析・特性要因図）。
   なぜ: 症状（在庫が多い）への対処ではなく真因（段取り替えが長い→まとめ作り）を叩かないと再発する。
7. **流れを作り、引く仕組みに変える。** 停滞を除き工程を連続化し、需要起点で上流から引く（カンバン/平準化/段取り短縮/標準作業/ポカヨケ等を必要に応じ選ぶ）。
   なぜ: ムダ排除の目的は「淀みない流れ」。押し込み(プッシュ)を引き(プル)に変えると作りすぎと在庫が構造的に減る。
8. **標準化し、カイゼンを回す（PDCA）。** 改善後の状態を標準作業として固定し、効果を計測、次のムダへ継続改善する。
   なぜ: 標準がないと改善は元に戻る。標準化→逸脱の見える化→次の改善、の循環が「完璧の追求」の実体。

## 壁打ち質問リスト

各要素を事実で埋めるために、利用者へ投げ返す問い。空欄を勝手に埋めず、まずこれで引き出す。

1. 改善したい**対象の工程・業務は具体的に何**で、**始点と終点**はどこですか？（1本の流れにスコープを絞る）
2. その工程で**顧客（社内外）が本当に価値と感じるアウトプット**は何ですか？逆に、顧客が対価を払わない作業はどれですか？
3. 今**一番の困りごとは何**ですか？（リードタイムが長い／在庫が多い／不良・手戻り／手待ち／残業——症状を特定）
4. 現状の**数字は分かりますか**？（1件あたりの所要時間、待ち時間、在庫量、不良率、リードタイム全体など。無ければ計測から）
5. どこで**停滞・滞留・手戻り**が起きていますか？その工程は**現地現物で観察**しましたか、それとも推測ですか？
6. その停滞は**なぜ起きている**と思いますか？（段取り替え・まとめ作り・情報待ち・不均一な負荷など、真因の仮説）
7. 需要や仕事量は**安定していますか、波がありますか**（ムラ）。人・設備に**過負荷（ムリ）**はありませんか？
8. 改善を**続ける体制**はありますか？（現場が参加できるか、コスト削減＝人員削減という空気になっていないか）

## 出力フォーマット

ALWAYS この型で出力する（現状可視化 → ムダ診断 → 改善設計 → 次の一手）。埋まらない箇所は壁打ち質問で確定させてから埋める。

```
【対象と価値】
  バリューストリーム: <始点→…→終点>  スコープ: <製品/業務>
  顧客価値: <顧客が対価を払う価値>   価値でない作業: <…>

【現状の流れ（可視化）】
  工程: <工程1→2→3…>  リードタイム全体: <…>  うち付加価値時間: <…（比率）>
  停滞・滞留・手戻りの所在: <どこで何が滞るか（現地現物で確認したもの）>

【7つのムダ診断】※該当のみ・重要順
  作りすぎ / 手待ち / 運搬 / 加工・過剰品質 / 在庫 / 動作 / 不良・手直し（/ 人の未活用）
    - <ムダの種類>: <具体> ／ 真因の仮説: <なぜ起きるか> ／ ムラ・ムリの有無: <…>

【改善設計（流れを作る）】
  優先課題: <最も効くムダ/制約>
  打ち手: <連続化/引く仕組み/段取り短縮/標準化/ポカヨケ 等から選択＋理由>
  期待効果: <リードタイム/在庫/不良 等でどう変わるか（計測前提）>

【次の一手】<小さく試す改善（Plan）＋計測する指標（Check）を1〜3個>
【未確認の前提】<数値・真因など、実地の確認が要る点（壁打ちで埋める）>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は捏造しない）。**受注から出荷までの事務・製造リードタイムが長い**中小メーカーの改善場面。

- **手順①価値**: 顧客が価値と感じるのは「正しい製品が短い納期で届く」こと。承認の往復や再入力そのものは価値でない。
- **手順②スコープ**: 「受注→生産指示→加工→検査→出荷」を1本の流れとして端から端まで見る。
- **手順③可視化（現地現物）**: 各工程を観察すると、加工など**価値を生む時間はリードタイム全体のごく一部**で、
  大半が「承認待ち・部材待ち・工程間の仕掛品滞留」であることが見える（＝停滞が支配的）。
- **手順④7つのムダ**: 手待ち（承認・部材待ち）、在庫・作りすぎ（まとめ生産による仕掛品）、運搬・動作（工程が離れている）、
  不良・手直し（受注情報の再入力ミス）を検出。最も悪い**作りすぎ**が在庫と手待ちを誘発している疑い。
- **手順⑤ムラ・ムリ**: 受注に波（ムラ）があり、繁忙期にまとめて流すため過負荷（ムリ）→仕掛りが膨らむ、という連鎖の仮説。
- **手順⑥真因**: 「なぜ仕掛りが多い？→ まとめ作り → なぜ？→ 段取り替えに時間がかかるから → …」と掘り、真因を段取りと平準化不足に絞る。
- **手順⑦流れ／引く**: 段取り替えの短縮、ロットの小口化、後工程が必要な分だけ引く（カンバン的な）仕組み、承認の簡素化を候補にする。
- **手順⑧標準化・カイゼン**: 改善後の手順を標準作業に固定し、リードタイムと仕掛品量を計測、次のムダへ継続改善。
- **次の一手**: まず「承認ステップの簡素化」を小さく試し、リードタイムと手戻り件数の変化を計測して仮説を検証する。
- **未確認の前提**: 各工程の実所要時間・仕掛品量・不良率は**実地で計測**が必要（数値は推測のまま進めない）。

## 相性（組み合わせると効く）

- `value-stream-mapping`: 現状の流れ・停滞・付加価値比率を可視化する、手順③の中核ツール（リーンの目＝どこにムダがあるか）。
- `toc`: 制約（ボトルネック）が支配的な場合、全体最適の観点で「どこを改善すべきか」を先に決める。局所最適の罠を防ぐ補完。
- `five-whys`: 検出したムダの**真因**を掘り下げる（手順⑥）。症状潰しでなく再発防止へ。
- `fishbone`: 不良・停滞の要因を人・設備・方法・材料などに整理し、なぜなぜと併せて真因を構造化する。
- `pdca`: カイゼン（手順⑧）を回す循環そのもの。改善の定着と継続を担保する。
- `ecrs` / `5s`: 個々の作業レベルのムダ排除（排除・結合・交換・簡素化）と、改善の土台となる現場の整備。
- `six-sigma`: ばらつき・不良の統計的低減を担い、リーン＝流れ改善と組んで「リーンシックスシグマ」になる。
- 揺さぶり枠として `premortem`（JIT/在庫最小化を進めた結果の供給途絶・脆さを先回りで洗う）や
  `devils-advocate`（「リーン＝コスト削減」への矮小化を疑う）を添えると、行き過ぎの失敗を防げる。
