# ペルソナ

## 概要

ペルソナは、対象の商品・サービスの**典型的（象徴的）な顧客を、実在する1人の人物のように具体化した「架空だが調査に裏打ちされた人物像」**。
氏名・年齢・職業といった**識別情報（下記6要素の外）**だけでなく、意思決定に効く**6要素——①ゴール/動機・②悩み/課題・③行動・④情報源/チャネル・⑤意思決定基準・⑥代表的な引用（生の言葉）**を、
インタビューや行動データから合成し、抽象的なセグメントを1人の「顔」に翻訳する。目的は「**誰のために作るのか**」をチームで固定し、判断のブレをなくすこと。

| | ターゲット（層） | ペルソナ（1人） |
|---|---|---|
| 粒度 | 属性ベースの幅（例: 30代女性・年収600万・関東） | その層の中の**典型的な1人**を具体化 |
| 中身 | デモグラ中心 | ゴール・動機・悩み・行動・情報源・口癖まで |
| 用途 | おおまかな絞り込み | **具体的な意思決定基準**（設計・訴求・チャネル） |

- **核となる考え方**: 「多くの人に当てはまる平均像」ではなく「**具体的で外れない1人**」を作る。Cooper はこれを
  **precision, not accuracy（統計的代表性より、的の絞り込み）** と表現する。設計・施策は、満たすべき**主ペルソナ（primary persona）1体**に照準を合わせる。
- **出自（諸説あり・年号は要確認）**: ソフトウェアデザイナー **Alan Cooper** が起点とされる。1983年頃、プロジェクト管理ソフト
  「Plan*It」開発中に同僚 約7〜8人へ非公式インタビューを行い、広告代理店で稼働管理（traffic）を担う女性 **Kathy** をモデルに
  最初の原始的ペルソナを作った、と本人が回顧している。著書 **『The Inmates Are Running the Asylum』（1998/1999）** で広く普及。
  マーケ側では **Angus Jenkinson** の "CustomerPrints"（1990年代）も並行して語られる（→出典・要確認）。
- **種類**: goal-directed（Cooper系）／ role-based ／ engaging（物語・感情重視）／ fiction-based の4視点（Lene Nielsen の整理として引用される）。
  調査前にチームの仮説を明示するための **proto-persona**、データからクラスタリングで作る **定量ペルソナ**、あえて狙わない
  **ネガティブ（除外）ペルソナ** もある。

## いつ使う / 使わない

**使う（適する状況）**
- 顧客像がチーム内でバラバラ／「30代女性」止まりで、**コンテンツ・UI・訴求・チャネルの判断がぶれる**とき。
- マーケ・企画・開発・営業が **共通言語（誰のために作るか）** を持ちたいとき。alignment（合意形成）ツールとして。
- 新規事業・新商品で、**顧客中心に発想・意思決定**したいとき（VPC・ジャーニー・STPの入力にもなる）。
- 施策の優先順位や訴求メッセージを、**具体的な1人の視点**で検証したいとき。

**使わない / よくある誤用（アンチパターン）**
- **作って使われない**——最頻の失敗。NN/G（Flaherty, 2018）は失敗要因として「作るが使わない／リーダーの賛同がない／
  UX単独のサイロ作成／活用法が伝わらない／目的違い（マーケ用に作りUXに流用）」を挙げる。作る=手段、使う=目的。
- **思い込みで捏造**——実調査でなく、社内の推測・逸話・願望で作る（"pulled out of thin air"）。これはセグメンテーション調査の代用にならない。
  必ず**客観データ（インタビュー・行動データ）**で裏を取る。データが無いなら proto-persona として「仮説」と明示し、検証前提で使う。
- **意思決定に無関係な装飾過多**——愛犬の名前・好きなコーヒーなど、設計/施策に効かない細部を盛りすぎる。**判断に効く情報だけ**残す。
- **静的で放置**——人は行動間を流動的に動くのに、ペルソナは固定カテゴリとして扱いがち。定期的に見直す前提で使う。
- **「誰」は言えるが「なぜ/どんな状況で」を言えない**——属性だけのペルソナは行動を説明しない。状況・文脈が購買を左右するなら
  **ジョブ理論(jtbd)** を併用する（→相性）。
- **ステレオタイプの助長**——不要な性別/人種/年代の決めつけが実際の顧客行動を覆い隠す。属性は行動・動機を語るのに必要な範囲に絞る。
- マス向けで1人に絞る意味が薄い場合や、精緻な定量セグメント最適化そのものが目的の場合は不向き。他フレームで補完する。

## 前提と限界

- **前提**: (1) このペルソナで**どの意思決定をするか**（用途）が1つに定まっていること。用途が曖昧だと装飾的プロフィールに堕ちる。
  (2) 裏付ける**実顧客の声・行動データ**にアクセスできること。無ければ proto-persona（仮説）として扱い、後で検証する。
- **限界（批判を踏まえて）**:
  - **抽象的な人格像に寄ると意思決定に繋がりにくい**——McKeen（UXmatters, 2019）は、性格特性の記述に偏るペルソナは具体的な
    アウトプットを生みにくいと批判し、JTBD（状況とジョブ）を推す。→ ゴール・行動・悩みを核に据えることで緩和する。
  - **相互排他の罠**——人は「行動スペクトラム」上を動くのに、ペルソナを排他的な箱として扱うと現実とズレる。1人=1固定と決めつけない。
  - **科学的厳密性の欠如・組織バイアス**——少人数・主観で作ると偏る。データ由来・複数視点・ステークホルダー巻き込みで補う。
  - **平均の罠**——「みんなに当てはまる無難な人物」を作ると、誰にも刺さらない。precision（具体・尖り）を優先する。
- これらは、**JTBDで状況・ジョブを補う／カスタマージャーニーで時間軸に展開する／VPCで価値との対応を検証する／
  reverse-assumptionやdevils-advocateでステレオタイプ・思い込みを弾く**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。

1. **用途とスコープを1つに固定する。** 「このペルソナで何を決めるのか」（例: LPの訴求／機能の優先順位／広告のチャネル）を明文化する。
   なぜ: 用途が無いと属性の作文になり、"使われないペルソナ"の最頻ルートに入る。
2. **既存の材料を棚卸しする。** 定量（アクセス解析・CRM・購買・アンケート）と定性（顧客インタビュー・観察・営業/CSの声）を集める。
   なぜ: ペルソナは調査の合成物。手元にある事実と、これから取りに行く事実（未確認）を先に切り分ける。
3. **顧客の生の声を集める（定性が核）。** 実顧客/見込み客に**オープンな質問**でインタビューする（「売り込みでなく学びが目的」と伝える）。
   目安は1ペルソナあたり数名（例: 3〜5人以上。飽和＝同じパターンが繰り返し出るまで）。なぜ: 動機・悩み・意思決定は本人の言葉からしか取れない。
4. **発言・行動をパターンに束ねる（アフィニティ）。** 「voice of customer」をそのまま記録し、似た悩み・ゴール・行動でグルーピングして
   セグメント（＝ペルソナ候補）を見つける。なぜ: 属性でなく**行動・動機の共通性**でまとめると、意思決定に効く軸が立つ。
5. **ペルソナを起こす。** 各候補について、識別情報（氏名・意思決定に効く範囲のデモグラ）に加え、意思決定に効く**6要素——①ゴール/動機・②悩み/課題・③行動・④情報源/チャネル・
   ⑤意思決定基準・⑥代表的な引用（生の言葉）**を埋める。なぜ: この6要素が「誰に何をどう届けるか」の判断材料になる（氏名・デモグラは6要素の外の識別情報）。装飾は入れない。
6. **主ペルソナを1体に決める（＋副/ネガティブ）。** 「その人を満たせば他も大きく損なわない」1人を主に選ぶ。狙わない客はネガティブペルソナに。
   なぜ: 照準を絞らないと施策が総花的になる。Cooper の primary persona の考え方。
7. **実データと突き合わせて検証し、意思決定に接続する。** ペルソナが実際の行動データと整合するか確認し、用途（手順1）に対する
   具体アクション（訴求・機能・チャネル）へ落とす。定期的に更新する。なぜ: ペルソナはゴールでなく起点。使って初めて価値が出る。

## 壁打ち質問リスト

各要素を**事実**で埋めるために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。推測と事実を分ける。

1. このペルソナで**最終的に何を決めたい**ですか？（LPの訴求／機能の優先順位／広告チャネル／営業トークなど、用途を1つに）
2. いま手元にある**顧客の一次情報**は何ですか？（インタビュー記録・アクセス解析・購買データ・営業やCSが聞いた生の声など）。
   逆に、**まだ確認できていない前提**はどれですか？
3. その人が、あなたの商品/サービスで**達成したいこと（ゴール・片付けたい用事）**は何ですか？なぜそれを今やろうとしていますか？
4. その人が抱える**悩み・不満・障害**は具体的に何ですか？購入や利用を**ためらう理由**は？（できれば本人の言葉で）
5. その人は、意思決定の前に**どこで情報を集め、誰に相談し、何を決め手に選ぶ**のですか？（チャネル・情報源・意思決定基準）
6. 「典型的な1人」と言えるだけの**具体性**がありますか？逆に「多くの人に当てはまる平均像」になっていませんか？（尖りの確認）
7. あえて**狙わない客（ネガティブペルソナ）**は誰ですか？（獲得コストが高い/継続しない/価値が合わない層を外すと照準が締まる）
8. その人物像の中で、**データの裏付けがある部分**と**まだ思い込み/仮説の部分**はどこですか？（後者は検証タスクに回す）

## 出力フォーマット

ALWAYS この型で出力する（人物像→意思決定への接続）。装飾情報は入れず、用途に効く要素に絞る。

```
【ペルソナ】用途: <このペルソナで決めること> ／ 種別: <データ由来 / proto(仮説)>
  名前・一言: <氏名>（<立場・状況を一言で>）
  基本属性:   <意思決定に効く範囲のデモグラ・職業・状況>
  ゴール/動機: <達成したいこと・なぜ今それを>
  悩み/課題:  <障害・ためらう理由>（できれば生の言葉の引用）
  行動:       <普段の行動・利用文脈>
  情報源/チャネル: <どこで知り・相談し・比較するか>
  意思決定基準: <何を決め手に選ぶか>
  代表的な引用: 「<インタビューで出た本人の言葉>」

【主/副/ネガティブ】主: <照準を合わせる1人> ／ 副: <…> ／ 狙わない: <ネガティブペルソナ>

【意思決定への接続】<このペルソナから導く訴求・機能・チャネル等の打ち手を1〜3個>
【未確認の前提】<データ裏付けがなく検証が要る点（壁打ちで埋める）>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の詳細プロフィールや数値は捏造しない）。地域の学習塾が Web 集客の訴求を作る場面。

- **手順①用途**: 「塾のLPで、どの悩みにどう訴求するか」を決めるためのペルソナ、と用途を固定する。
- **手順②棚卸し**: 手元にあるのは問い合わせフォームの記述と面談メモ（定性）とアクセス解析（定量）。世帯の詳細な所得等は未確認、と切り分ける。
- **手順③生の声**: 実際に入塾した/検討した保護者数名に、決め手・不安・情報収集の流れをオープンに聞く（売り込みでなく学びが目的と伝える）。
- **手順④パターン化**: 発言を束ねると「成績より“勉強習慣がつくか”を気にする層」と「受験直前の点数アップを急ぐ層」に分かれる、といった行動軸が見える。
- **手順⑤ペルソナ化**（習慣重視の層を1体に起こす・要素のみ、数値は作らない）:
  - ゴール/動機: 子が自分から机に向かう習慣をつけたい。
  - 悩み/課題: 家庭では続かない、他塾は詰め込みで合うか不安。「本人がやる気になるかが一番心配」（生の言葉）。
  - 行動/情報源: 口コミと体験授業で判断。決め手は「面談での相性・雰囲気」。
- **手順⑥主/ネガティブ**: 主=習慣重視層。ネガティブ=直前の点数だけを求め相性を重視しない層（訴求がぶつかるため外す）。
- **手順⑦接続**: LPは「成績アップ」より「学習習慣と本人のやる気」を前面に、体験授業への導線を主動線にする、という打ち手に落とす。
- **未確認の前提**: この悩みが検討層の多数派かは要検証——問い合わせ内容の集計で裏取りする（推測のまま本番施策に流さない）。

## 相性（組み合わせると効く）

- `jtbd`: ペルソナの「誰」に、**状況とジョブ（なぜ・どんな時に雇うのか）**を足す最重要の補完。属性偏重を防ぎ、行動の説明力を上げる。
  （ペルソナ=who、JTBD=situation/why の食い違いこそ新しい視点になる。）
- `customer-journey`: ペルソナ（主人公）を**時間軸の体験フロー**に展開し、各接点の思考・感情・課題を可視化する直接の続き。
- `stp`: STPの Target（狙う層）を、**具体的な1人**に翻訳するのがペルソナ。セグメント→ペルソナで抽象を具体化する。
- `value-proposition-canvas`: ペルソナの悩み/ゴールを VPC の顧客プロフィール（pains/gains/jobs）に写し、提供価値との対応を検証する。
- `design-thinking`: 共感（Empathy）フェーズの成果物としてペルソナ/共感マップを用い、人間中心の発想の土台にする。
- 揺さぶり枠として `reverse-assumption`（ペルソナの前提を反転し、狙わない客・逆張り像を出す）や
  `devils-advocate`（「それは実データか、思い込みか」を突く）を添えると、ステレオタイプと捏造を弾ける。
