# So What?/Why So?

## 概要

So What?/Why So? は、事実・データと結論のあいだの**縦の論理（論理の飛び）**を通すための思考技術。
照屋華子・岡田恵子『ロジカル・シンキング ──論理的な思考と構成のスキル』（東洋経済新報社, 2001）が
**MECE** と並ぶロジカルシンキングの2大道具として体系化した（→出典・要確認）。

- **So What?（だから何が言えるか）**: 手元の情報・データの集合**全体**から「結局どういうことか」という
  **中身のある結論・示唆（エッセンス）を絞り出す**作業。下（要素）→上（結論）へ向かう。
- **Why So?（なぜそう言えるか）**: 抽出した結論に対し「その根拠は何か」を要素で**検証**する作業。
  上（結論）→下（根拠）へ戻る。So What? の妥当性を裏づけで確かめる。
- 両者は**背中合わせ**で、往復させることで**話の飛び**をなくす。片方だけでは成立しない。

| 向き | 問い | 何をするか |
|---|---|---|
| **So What?**（下→上） | だから何が言えるのか | 事実の集合から中身のある示唆・結論を抽出する |
| **Why So?**（上→下） | なぜそう言えるのか | その結論を根拠となる事実で検証・裏づけする |

**2つの型（原典の分類）**——ここを取り違えると出力がぶれる。
- **観察の So What?/Why So?**: 提示された事実**全体**から言えることを要約し（So What?）、要素分解で検証する（Why So?）。
  **同種**の情報の中で結論を出す（例: 3事業とも赤字 → 「全社で採算が悪化している」）。
- **洞察の So What?/Why So?**: 複数のデータに潜む**法則・パターン**を導く、または**取るべき行動と影響**を考える。
  既存情報から**異種**の情報を引き出す（例: 全社赤字という観察 → 「固定費構造にメスを入れるべき」という打ち手）。

**空・雨・傘との対応**: 空（事実＝空が曇る）→ 雨（解釈＝降りそうだ＝観察のSo What?）→ 傘（行動＝傘を持とう＝洞察のSo What?）。
認識・解釈・行動を分けることで飛びを防ぐ、実務で広く使われる姉妹フレーム（考案帰属は不明・要確認）。
英語圏では Barbara Minto のピラミッド原則（初版年は資料により1985/1987等と割れ要確認、増補版『The Minto Pyramid Principle』1996年）の**縦の論理（Q&A dialogue）／"so what" テスト**に対応する。

## いつ使う / 使わない

**使う（適する状況）**
- データ・グラフ・調査結果を前に「**で、結局何が言えるのか**」を引き出したいとき。
- 報告・提案・企画書が「**やったことの羅列**」で示唆が無いと指摘された、または自分でそう感じるとき。
- 結論に対して「**その根拠は揃っているか／飛んでいないか**」を点検したいとき（提出前チェック）。
- ロジックツリー・ピラミッドストラクチャーの**縦のつながり**を検算したいとき（縦の論理はSo What?/Why So?で保証される）。
- 会議やレビューで「要するに？」に即答できるよう、**結論と根拠を1本の線で**繋いでおきたいとき。

**使わない / よくある誤用（アンチパターン）**
- **フレームだけ描いて中身が無い**——最頻の失敗。「販促を3施策実施した」のように"何をやったか"の枠を述べただけで、
  "だから何が言えるか"が欠落する（原典p.109の例）。So What? は**中身のある示唆**を出して初めて成立する。
- **単なる短縮と混同する**——原典は「必要な情報と不要な情報を切り分け、**必要な情報は十分な密度で**述べる」と説く。
  短くすることが目的ではない。削りすぎて根拠が消えれば Why So? に答えられなくなる。
- **洞察 > 観察という思い込み**——奇抜な洞察のSo What?ほど価値が高いと錯覚しがち。だが本当に重要なのは
  **相手のWhy So?に答えられること**（聞き手の論理・前提と接続すること）。根拠で支えられ相手が納得できるかが肝。
- **事実と解釈と行動を混ぜる**——空・雨・傘が分離するように、観察（事実）と洞察（行動示唆）を段階で分けないと、
  「事実を見ずに結論に飛ぶ」か「解釈せず事実を垂れ流す」かのどちらかに堕ちる。
- **根拠（Why So?）を用意せず結論だけ言う**——聞き手は必ず「なぜ？」を返す。裏づけの無いSo What?は主観・憶測になる。
- 事実・データがまだ無い段階、発散的なアイデア創出、合意形成そのものが目的の場には単体では不向き。他フレームで補う。

## 前提と限界

- **前提**: So What? の材料となる**事実・データが手元にある**こと（無ければ先に収集し、MECEで漏れ・ダブりを整える）。
  「何のための示唆か」という**問い（論点）が1つ定まっている**こと。論点が曖昧だとSo What?は発散する。
- **限界（批判を踏まえて）**:
  - **入力の質に依存する**——偏った・漏れのあるデータからは、正しく往復させても誤った示唆しか出ない
    （garbage in, garbage out）。横の網羅性は別途 MECE で担保する必要がある。
  - **結論先出し・縦の論理は共創に向きにくい**——Minto流の演繹的な提示は、聞き手を巻き込む探索・合意形成の場では
    かえって対話を閉じることがある。聞き手と目的を選ぶ。
  - **"それらしい"So What?で止まる罠**——一般論の言い換え（「顧客満足が重要だ」等）はSo What?に見えて中身が無い。
    「この事実**だから**言える、他では言えない」まで具体化しないと示唆にならない。
  - **観察と洞察を混同すると論理が破綻する**——同種の要約（観察）と異種の跳躍（洞察）は検証のしかたが違う。
    洞察はより大きな飛びを含むため、Why So? の裏づけをより厳しく求める。
- これらは、**横の漏れをMECEで潰す / 分解構造をロジックツリー・ピラミッドで持つ / 結論の思い込みを
  devils-advocate や premortem で叩く**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。

1. **問い（論点）を1つに固定する。** 「この情報から何を言えれば役に立つか」を明文化する（例: この事業を続けるべきか）。
   なぜ: So What? は問いに対する答え。問いが無いと示唆が発散し、"それらしい一般論"に堕ちる。
2. **事実を並べ、観察か洞察かを決める。** いま出したいのは事実の要約（観察）か、行動・法則への跳躍（洞察）か。
   なぜ: 2つの型は検証のしかたが違う。混ぜると「事実の羅列」か「根拠なき飛躍」のどちらかになる。
3. **So What? を出す（下→上）。** 事実の集合**全体**から「だから何が言えるか」を、中身のある1文に絞り出す。
   「この事実だから言えて、他では言えない」まで具体化する。なぜ: 枠の描写や一般論の言い換えはSo What?ではない。
4. **短縮で消したものを点検する。** 削った情報が「不要」なのか「必要な根拠」なのかを見分ける。
   なぜ: 原典の要諦は"短くする"ではなく"必要な情報を十分に残す"。根拠を削ると次のWhy So?で崩れる。
5. **Why So? で検証する（上→下）。** 出したSo What?に「なぜそう言えるのか」を問い、根拠となる事実を並べて裏づける。
   なぜ: 聞き手は必ず「なぜ？」を返す。ここで裏づけが揃わなければ、それは主観・憶測でありSo What?を作り直す。
6. **相手のWhy So?で最終チェックする。** 「この聞き手・この前提の人が納得するか」を相手の立場で問い直す。
   なぜ: 本当に重要なのは奇抜さではなく、相手の論理と接続していること。自分基準の裏づけでは通らない。
7. **飛びが残れば階層を足して往復し直す。** 結論と根拠のあいだが遠ければ中間のSo What?を1段挟む（空・雨・傘の分離）。
   なぜ: 大きな飛びは中間結論を置いて分割すると消える。ピラミッド/ロジックツリーの縦がこれで通る。

## 壁打ち質問リスト

各段を事実で埋めるために利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。

1. この情報から**最終的に答えたい問い（論点）**は何ですか？（何を判断・主張したいのか1つに）
2. 手元にある**事実・データ**は具体的に何ですか？（数字・観察・調査結果を、推測と分けて挙げてください）
3. いま出したいのは、事実全体の**要約（観察）**ですか、それとも取るべき**行動や法則（洞察）**ですか？
4. その事実**全体**から言える「だから何が言えるか」を1文にすると何ですか？——それは**この事実だから言えて**、
   他の場面では言えない中身になっていますか？（一般論の言い換えになっていないか）
5. その結論に「**なぜそう言えるのか**」と問われたら、**どの事実**を根拠として示せますか？飛んでいる箇所はどこですか？
6. その根拠は、**この聞き手（相手）の前提や論理**からも納得できるものですか？相手はどこに「なぜ？」を返しそうですか？
7. 結論と根拠のあいだが遠い場合、**中間の結論（空→雨→傘のどの段）**を1段挟むと飛びは消えますか？
8. 短くまとめる過程で、**必要な根拠まで削っていません**か？（残すべき情報と捨ててよい情報の切り分け）

## 出力フォーマット

ALWAYS この型で出力する（示唆の抽出 → 根拠での検証を1本の線に）。命令形で固定する。

```
【問い（論点）】<この情報から答えたいこと1つ>
【型】観察 / 洞察 のどちらか（＋空・雨・傘のどの段か）

【事実（材料）】
  - <事実・データ①（数字/観察）>
  - <事実・データ②>
  - <事実・データ③>

【So What?（だから何が言える）】
  <事実全体から絞り出した、中身のある示唆・結論を1〜2文で。この事実だから言える形に>

【Why So?（なぜそう言える＝根拠検証）】
  - <上のSo What?を支える根拠①（どの事実がどう効くか）>
  - <根拠②>
  → 飛びチェック: <結論と根拠のあいだに残る飛び。必要なら中間結論を1段挿入>

【相手のWhy So?（聞き手の納得）】<この相手が返しそうな「なぜ？」と、それへの答え>
【次の一手】<この示唆から取るべき行動・検証（洞察型のSo What?へ接続）>
【未確認の前提】<事実か推測か曖昧な点（壁打ちで裏取りする）>
```

## 具体例（ワークスルー）

対象を一般化した例（企業名は用いず一般化。数値は手触りを出すため**"説明用の架空数値"**と明示して添える——実データではない）。ある新製品の販促結果レビューで、報告が「やったことの羅列」に
なっている場面を、観察のSo What?/Why So? で示唆に変える。原典p.109の趣旨に沿う。

- **手順①問い**: 「この販促の結果から、次に何を判断すべきか」。
- **手順②型**: まず事実の要約＝**観察**型。行動提案は後段の**洞察**型へ回す。
- **手順③材料（悪い例＝枠の描写）**: 「上期に販促を3施策実施した」——これは"何をやったか"の枠で、示唆が無い。
- **手順③So What?（良い例＝中身のある示唆）**: 事実（売上 対目標△12%・利益 対目標△18%・利益率 対計画△3pt、値引き/インセンティブの投入、
  中間時点での方針転換。※数値はすべて説明用の架空値）全体を束ねて——「**新製品は上期に売上・利益・利益率とも目標未達（売上△12%、利益率△3pt）。中間で未達が確実になった
  ため販促を切り替え、売上は持ち直したが値引き・インセンティブにより利益率がさらに悪化した**」と、必要情報を十分な密度で述べる。
- **手順④短縮の点検**: 「施策名」や「販路」は不要情報として落とし、「目標未達」「利益率の悪化」という根拠は残す。
- **手順⑤Why So?（検証）**: なぜそう言えるか → 売上/利益/利益率それぞれの対目標実績（△12%/△18%/△3pt）、方針転換の時点、
  値引き・インセンティブが利益率を押し下げた因果、で裏づく。裏づけが揃うのでSo What?は妥当。
- **手順⑥相手のWhy So?**: 経営層は「売上改善は評価すべきでは？」と返す → 「売上は改善したが**利益率悪化**により
  収益目標には届いていない」と、相手の論理に接続して答える。
- **手順⑦洞察へ接続（次の一手）**: 観察（利益率を犠牲にした売上改善）→ 洞察のSo What?「**値引き依存の販促から、
  利益率を保てる打ち手へ切り替えるべき**」。ここは空→雨→傘の"傘"にあたる行動示唆。
- **未確認の前提**: 利益率悪化が販促だけによるものか（原価変動等の他要因の切り分け）は要データ確認（推測で断じない）。

## 相性（組み合わせると効く）

- `mece`: 横の漏れ・ダブりを潰す道具。MECEで材料を網羅してからSo What?/Why So?で縦を通すと、示唆の抜けが減る（2大道具）。
- `pyramid-structure`: 結論→根拠の階層構造。その**縦のつながり**を保証するのがSo What?/Why So?。ピラミッドの縦の検算に直結。
- `logic-tree`: 問題を分解した各枝に対しWhy So?（なぜ）で下り、So What?（だから）で上る。ツリーの縦の論理を点検する。
- `five-whys`: 「なぜ」を掘る点で近縁だが、five-whysは**因果**の追究、Why So?は**論理的裏づけ**の検証。真因分析と併用すると強い。
- 揺さぶり枠として `devils-advocate`（そのSo What?は本当に事実から言えるか、思い込みを反対役で叩く）や
  `premortem`（洞察のSo What?＝打ち手が失敗する要因を先回り）を添えると、独りよがりの示唆を防げる。
