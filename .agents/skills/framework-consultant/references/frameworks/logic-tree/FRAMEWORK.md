# ロジックツリー

## 概要

ロジックツリーは、扱いきれない大きな問題や問い（幹）を、**MECE（漏れなくダブりなく）に枝分かれさせて階層的に分解**し、
原因・構成要素・打ち手を一枚の樹形図に可視化する思考ツール。左（＝解くべき問い）から右（または上から下）へ進むほど
具体化し、末端は**データで検証でき、行動に移せる粒度**まで落とす。核となる発想は「**分割して統治する（divide and conquer）**」——
手に負えない問題を、答えられる小さな問いに割って一つずつ潰す。

**4つの型（目的で使い分ける）**

| 型 | 別名 | 幹に置く問い | 何をする |
|---|---|---|---|
| **Whatツリー** | 要素分解ツリー | 「〜は何で構成されるか」 | 全体を足し算分解し、問題の所在・大きさを把握 |
| **Whyツリー** | 原因追究ツリー | 「なぜ〜なのか」 | 「なぜ」を繰り返し根本原因へ（→なぜなぜ分析と地続き） |
| **Howツリー** | 問題解決/イシューツリー | 「どうすれば〜できるか」 | 打ち手を洗い出し具体化・優先順位づけ |
| **KPIツリー** | 指標分解ツリー | 「KGIは何の掛け算か」 | KGIを式（掛け算）でKPIに分解し数値の共通認識化 |

- **1本のツリーでは Why か How のどちらかに統一する**（原因と打ち手を1本に混ぜない）。要素の把握が先なら What を単独で回す。
- **出自（諸説あり・断定回避）**: 木構造による問題分解は一般的手法で、**単一の考案者は確定していない**。実務手法としては
  **McKinsey & Company** が体系化・普及させたとされる（Wikipediaは McKinsey と戦略学者 Arnaud Chevallier による精緻化に言及、
  考案年・単独考案者の記載は無い）。枝分けの規律である **MECE** は **Barbara Minto** がMcKinsey在籍中（1960年代後半とされる）に
  考案し、著書『The Pyramid Principle』（初版年は資料により1985/1987等と割れ要確認、増補版『The Minto Pyramid Principle』1996年）で広めたと語られる。**年号・人名は要確認**（→出典・要ファクトチェック）。

## いつ使う / 使わない

**使う（適する状況）**
- 問題が大きく漠然としていて、**どこから手をつけるか分からない**とき（幹を割って着手点を見つける）。
- 売上減・コスト増・不良・離脱などの**原因を切り分けたい**（Whyツリー）／**打ち手を漏れなく出したい**（Howツリー）とき。
- 全体像を掴み、**問題がどこにどれだけあるか**を可視化したい（Whatツリー）とき。
- チームで**分担（divide and conquer）**して調べたい、議論の**論点を構造化**したいとき。
- KGIをKPIに分解し、**指標の共通認識**を作りたい（KPIツリー）とき。

**使わない / よくある誤用（アンチパターン）**
- **問題が曖昧・多義的で、複数の視点が要る段階**——細分化より先に、概念フレーム（3C・SWOT等）で論点自体を発見すべき。
- **純粋な発散アイデア発想**——飛躍や異分野借用が要る創造には、分解型は向かない（ブレスト・アナロジー等へ）。
- **kitchen sink（何でも入れ）**——最頻の失敗。第1階層に6〜8枝を雑多に並べ、優先順位もグルーピングもできず
  「構造でなく単なるリスト」になる。第1階層は3〜5枝に絞る。
- **aggregator fallacy（集約の誤謬）**——器を原因と取り違える。「倉庫が多い→盗難が多い」は倉庫が盗難を"生む"のでなく、
  既存の発生率を集約しただけ。分解の枝が**因果のドライバー**か、ただの**入れ物（セグメント）**かを問う。
- **早すぎる打ち手**——真因を把握する前にHowへ飛ぶ。まずWhyで原因を確定してからHowへ。
- **反証不能な切り方**——データで枝を消せない（検証できない）分け方は、分割して統治にならない。

## 前提と限界

- **前提**: 分解する**問題が一つに定義できている**こと。「何を解くのか」が曖昧なまま構造化すると、的外れなツリー
  （例: 本当の問題は「盗難」なのに上位概念の「在庫ロス」を分解）になる。目的が曖昧なら先に壁打ちで問題を固定する（手順①）。
- **限界（誤用と表裏）**:
  - **切り口の質が成果を決める**——技術的にMECEでも、示唆の無い切り方（弱いドライバーから割る等）は価値を生まない。
    「insightful breakdown（示唆に富む切り口）」が要る。
  - **完全なMECEは難しい**——特に原因や仮説は本質的に重複・漏れが出やすい。神経質に完璧を狙うより、
    重要な枝を8割押さえ、反証しながら回す方が実務的。
  - **静的な一枚図**——作った瞬間の理解を映すだけ。前提が変われば作り直す前提で使う。
  - **量と大きさの混同**——頻度だけ数え、1件あたりの規模（magnitude）を見落とすと優先順位を誤る。
- これらは、**MECEで枝を検算する / なぜなぜ分析で真因を掘る / 特性要因図で切り口を補う / 打ち手はペイオフ/意思決定
  マトリクスで優先順位づけする / ピラミッドストラクチャーで説明用に組み替える**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。**まず型（What/Why/How/KPI）を1つ選ぶ**ところから始める。

1. **解く問題を1つに具体的に定義し、幹に置く。** 「なぜ売上が下がったか」「どうすれば解約を減らせるか」等、
   問い（key question）を一文で言い切る。なぜ: 問題定義がずれると、以降の枝がすべて的外れになる（最上流の失敗）。
2. **型を選ぶ。** 所在把握＝What／原因究明＝Why／打ち手立案＝How／指標分解＝KPI。**1本に Why と How を混在させない**。
   なぜ: 原因と対策を1本に混ぜると、階層の意味（分解の論理）が壊れる。
3. **第1階層の切り口を選び、3〜5枝に割る。** 最優先は**数式分解（Math tree）**——売上＝客数×客単価、利益＝売上−費用の
   ように式があれば、それは常にMECE。式が無ければ定番の切り口（プロセス順・要素・対象セグメント等）を当てる。
   なぜ: 第1階層のMECEが全体の質を決める。式ベースは漏れ・ダブりを構造的に防げる最も安全な分け方。
4. **各枝をMECEで検算する。** 重複（Mutually Exclusive）と漏れ（Collectively Exhaustive）を問う。
   同一階層は**粒度を揃える**（「北米」と「中国・インド」＝大陸と国の混在をしない）。
   なぜ: 重複は労力の二重化、漏れは真因の取りこぼしを生む。粒度不揃いは比較を狂わせる。
5. **その枝は"ドライバー"か"入れ物"かを問う。** 各枝が問題を**因果的に動かす要因**か、ただの**集約セグメント**かを判定する。
   なぜ: 集約の誤謬（aggregator fallacy）を避け、打ち手や真因に効く枝だけを深掘りするため。
6. **問題が潜んでいそうな枝だけ、1階層ずつ深掘りする（selective deepening）。** 全枝を均等に伸ばさない。
   Whyツリーは「なぜ」を、Howツリーは「どうやって」を繰り返し、**データで検証でき／行動に移せる粒度**まで割る。
   なぜ: 全展開は時間の浪費。仮説の高い枝に資源を集中し、データで枝を消しながら進めるのが分割統治の本質。
7. **末端をアクション・検証項目に変換し、優先順位をつける。** Whyの末端＝検証すべき真因仮説、Howの末端＝実行可能な打ち手。
   効果×実現性などで絞る。なぜ: ツリーはゴールでなく起点。行動と検証に落として初めて問題解決になる。

## 壁打ち質問リスト

各枝を事実で埋めるために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。

1. このツリーで**最終的に答えを出したい問い**は何ですか？（一文で。例:「なぜ解約が増えたか」「どうすれば粗利を回復できるか」）
2. 今回の目的は、**原因を突き止めること（Why）／打ち手を洗い出すこと（How）／全体像の把握（What）／指標分解（KPI）**の
   どれですか？（型を1つに決めるため）
3. その問題を**数式や既知の構造で分解**できますか？（例: 売上＝客数×客単価、離脱＝新規×継続率）。使える式・分け方はありますか？
4. 第1階層で考えている切り口は何ですか？その枝どうしに**重複や漏れ（MECE違反）**はありませんか？粒度は揃っていますか？
5. 挙げた各枝は、問題を**実際に動かす要因（ドライバー）**ですか、それとも**ただの入れ物（セグメント）**ですか？
6. どの枝に問題が**最も潜んでいそう**ですか？その仮説の根拠（数字・観察）は何ですか？（深掘りする枝を絞るため）
7. 各枝は**データで確かめられ／消せます**か？確かめる術が無い枝はどれですか？
8. すでに分かっている事実は何で、まだ**確認できていない前提**は何ですか？（推測と事実を分ける）

## 出力フォーマット

ALWAYS この型で出力する（インデント階層で樹形を表現し、末端を行動/検証に落とす）。

```
【ロジックツリー】型: What/Why/How/KPI ／ 解く問い（幹）: <一文>
第1階層の切り口: <数式 or 定番の切り口> ／ MECEチェック: 重複[なし/…] 漏れ[なし/…]

<幹の問い>
├─ 枝A（<ドライバー/入れ物>）
│    ├─ A-1 …
│    └─ A-2 …
├─ 枝B
│    ├─ B-1 …
│    └─ B-2 …
└─ 枝C
     └─ C-1 …

【深掘りした枝】<問題が潜むと見た枝＋その根拠（仮説）>
【次の一手】
  - Whyの末端: <検証すべき真因仮説（データで確認）>
  - Howの末端: <実行可能な打ち手（効果×実現性で優先順位）>
【未確認の前提】<事実確認が要る点（壁打ちで埋める）>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。あるサブスク型サービスで「解約が増えている」問題を扱う場面。

- **手順①問題定義（幹）**: 「なぜ月次の解約率が上がっているのか」を幹に置く。所在把握より原因究明が先と判断。
- **手順②型**: 原因を突き止めたいので **Whyツリー**（Howは真因確定後に別途回す）。
- **手順③第1階層（数式/構造で分解）**: 解約は「顧客が価値を感じない」か「価値はあるが離脱要因がある」に大別。
  さらに前者を **①期待とのギャップ（オンボーディング）／②継続的な価値提供／③価格に対する納得感**、
  後者を **④競合への乗り換え／⑤運用・サポートの不満** に割る（3〜5枝に収める）。
- **手順④MECE検算**: 「価格不満」と「競合乗り換え」は重複しうる（安い競合へ移る）ため、
  「自社への不満（内的要因）」と「外的な引力（競合）」で切り分け直し、重複を解消。粒度も揃える。
- **手順⑤ドライバー/入れ物**: 「新規顧客が多い月ほど解約が多い」は入れ物（新規の母数）の可能性——集約の誤謬に注意し、
  母数でなく**オンボーディング完了率**という因果ドライバーを枝に採る。
- **手順⑥深掘り（枝を絞る）**: 観察から「初月での離脱が多い」仮説が濃いので、①オンボーディングの枝だけを
  「初回設定の完了率」「最初の成功体験までの日数」まで深掘りする（全枝は均等に伸ばさない）。
- **手順⑦末端→次の一手**: 末端の真因仮説「初回設定を完了しない顧客が初月で離脱している」を、
  利用ログで検証する（コホート別の完了率×継続率）。検証できたら Howツリーに切り替え打ち手を設計する。
- **未確認の前提**: 初月離脱の実際の比率、競合乗り換えの実数——ここは実データで裏取りが要る（推測のまま進めない）。

## 相性（組み合わせると効く）

- `mece`: ロジックツリーの各分岐が「漏れなくダブりなく」かを判定する土台の原則。枝の検算（手順④）で必ず併用する。
- `five-whys`: Whyツリーの有望な1枝を、なぜを反復して真因まで深掘りする（手順⑥の縦の深掘り）。
- `fishbone`: 原因の切り口（4M＝人・機械・材料・方法 等）を与え、Whyツリー第1階層の抜け漏れを補う。
- `pyramid-structure`: ツリーで分解・検討した中身を、今度は「説明・説得」用に主張→根拠へ組み替える出口の相方。
- `so-what-why-so`: 各枝の上下関係が論理的に繋がるか（So What?／Why So?）を検証し、飛躍・こじつけを弾く。
- `payoff-matrix` / `decision-matrix`: Howツリーで洗い出した打ち手を、効果×実現性や評価軸で採点し優先順位づけする（手順⑦）。
- 揺さぶり枠として `reverse-assumption`（切り口の常識を反転させ別の分解軸を得る）や `premortem` / `devils-advocate`
  （「この分解で真因を取りこぼしていないか」を疑う）を添えると、思い込みの切り口を破れる。

**要ファクトチェック（Web調査で誤りが混入しやすい断定）**
- **考案者・出自**: ロジックツリー/イシューツリー自体に単一の考案者は確定していない。McKinsey による体系化・普及は通説だが、
  「誰が最初に考案したか」の一次資料は無い。Wikipedia の Arnaud Chevallier への帰属は"精緻化"の文脈であり、原案者ではない。
- **MECEの帰属と年号**: Barbara Minto の考案（1960年代後半とされる）、入社年(1963)・ロンドン移籍(1966)・『The Pyramid Principle』
  出版年（初版は資料で食い違う: Wikipedia=1985／本人サイトは「1987執筆」と記載／Internet Archiveに1981年Minto International版。増補版1996は一致）は二次情報。年号・経歴の細部は要確認。
- **What/Why/How/KPI の4分類**は主に日本の実務・研修で普及した整理で、英語圏の diagnostic tree / solution tree /
  hypothesis tree とはラベル体系が異なる。呼称を一次文献の定義と混同しない。
- **数式分解が「常にMECE」**という表現は、式が対象を過不足なく表す場合の話。式の定義自体が現実を取りこぼす場合は別途検証が要る。
