# DMAIC 各フェーズ詳細（＋DMADV）

DMAICは既存プロセスの改善サイクル。各フェーズには「目的・主な活動・使う道具・成果物・次へ進む判定(トールゲート)」がある。
**前のフェーズの成果物が揃わないまま次へ進まない**（特に Measure の測定系検証を飛ばさない）。道具の選び方は `tools-and-stats.md` を参照。

## D — Define（定義）
**目的**: 「何を・どれだけ・誰のために良くするか」を1つに固定する。曖昧なテーマは以降を空回りさせる最大要因。

**主な活動**
- 問題を一文で定義（対象プロセス／悪さ／規模／期間）。「良い/悪い」の判定基準を明確に。
- 顧客の声(VOC)を集め、本当に効く品質特性 CTQ(Critical To Quality) に翻訳する。
- 改善対象の結果指標(Y)と目標値、範囲(スコープ)、期間、推進体制(ベルト・関与者)を決める。
- プロセス全体を SIPOC（Supplier-Input-Process-Output-Customer）で俯瞰し、境界を確定。

**道具**: プロジェクト憲章 / VOC / CTQツリー / Kanoモデル / SIPOC / ステークホルダー分析。
**成果物**: プロジェクト憲章、SIPOC、CTQ定義、目標値。

## M — Measure（測定）
**目的**: 現状を数値で固定し、出発点(ベースライン)を作る。「本当に・どれだけ悪いか」を事実にする。

**主な活動**
- データ収集計画（何を・誰が・いつ・どう測るか、操作的定義）を立てる。
- **測定システム分析(MSA / Gage R&R)を先に行う**——測定者・機器・測定位置で数値がぶれないか。ここが甘いと以降が全部崩れる。
- 一定期間データを取り、ベースラインの工程能力(Cp/Cpk)・シグマ水準・DPMO を算出（`tools-and-stats.md`）。
- パレート・ヒストグラム・チェックシート・時系列(ランチャート)で、ばらつき/不良の分布と偏りを掴む。

**道具**: 詳細プロセスマップ / データ収集計画 / MSA・Gage R&R / 工程能力(Cp,Cpk) / チェックシート / ヒストグラム / パレート / ランチャート。
**成果物**: 信頼できる測定系、ベースラインの工程能力・シグマ水準、絞り込んだ着目点。

## A — Analyze（分析）
**目的**: ばらつき・欠陥の**真因(X)を統計で実証**する。印象のXを潰し、Y=f(X)の効くXだけを残す。

**主な活動**
- 特性要因図(4M: 人/機械/材料/方法 等)・なぜなぜ分析で候補X を洗い出す。
- パレートで的を絞り、**仮説検定(t検定/ANOVA/カイ二乗)・相関/回帰**で候補XとYの関係を検証する。
- 必要に応じ **DOE(実験計画法)** で複数Xの効き方・交互作用を効率的に調べる。FMEA で危険な故障モードを評価。
- 「疑っていたX」と「データが示すX」の食い違いをここで明確にする（取り違えの検出）。

**道具**: 特性要因図(石川ダイアグラム) / なぜなぜ / パレート / 仮説検定(t,ANOVA,χ²) / 相関・回帰 / DOE / 工程能力 / FMEA。
**成果物**: データで実証された真因X（複数なら重要度順）。

## I — Improve（改善）
**目的**: 効くXへの打ち手を設計し、**本番展開の前に効果を実データで検証**する。

**主な活動**
- 対策案を発想し（Xの最適条件・設計変更・標準化）、実現性で候補を絞る。
- **DOE で最適条件を探索**、**パイロット/シミュレーション**で規格内に収まるか・副作用がないかを実証。
- **ポカヨケ(mistake-proofing)** で「誤った状態を選べない」設計にする。Kaizen・5S で現場を整える。
- 効果が数値で確認できた案だけを本展開へ。効かない/副作用が大きい案は採らない。

**道具**: DOE / FMEA / ポカヨケ / パイロット・シミュレーション / Kaizenイベント / 5S / 対策選定マトリクス。
**成果物**: 効果実証済みの改善策と実装計画。

## C — Control（管理）
**目的**: 改善を**元に戻らない仕組み**にして定着させ、担当へ引き継ぐ。ここを省くと必ず戻る（最頻の未完）。

**主な活動**
- **管理図(SPC)** で工程を継続監視し、ばらつきの異常(特殊原因)を早期検知。
- 最適条件を**標準作業(SOP)・作業手順・管理計画(Control Plan)** に落とす。ポカヨケを本設置。
- 改善後の工程能力をベースラインと比較して効果を確定。監査・レビューの仕組みを残す。
- プロジェクトを閉じ、学びと横展開先を記録。

**道具**: 管理図(X-bar/R, p, c 等) / 管理計画 / SOP・作業標準 / ポカヨケ / 工程能力の再評価 / 監査・マネジメントレビュー。
**成果物**: 管理計画、標準、監視の仕組み、効果確認レポート、引き継ぎ。

## トールゲート（各フェーズの通過判定）
各フェーズ末で推進者/チャンピオンが「次へ進んでよいか」を確認する関所。空欄のまま先へ進まない。
- D→M: 問題・目標・CTQ・範囲・体制が確定したか。
- M→A: 測定系は信頼できるか(MSA)。ベースライン工程能力は出たか。
- A→I: 真因Xはデータで実証されたか（印象でないか）。
- I→C: 改善効果はパイロットで数値実証されたか。副作用は点検したか。
- C→完了: 管理図・標準・管理計画で戻らない仕組みができ、効果が確認されたか。

## DMADV / DFSS（新規設計向け）
既存プロセスが無い/根本から再設計する場合は DMAIC でなく **DMADV（Design for Six Sigma）** を使う。
- **D**efine: 設計目標を事業戦略・顧客要求と整合させ定義。
- **M**easure: 重要品質特性(CTQ)・リスク・設計要件を特定・測定。
- **A**nalyze: 複数の設計代替案を作り評価する。
- **D**esign: 最適案を選び詳細設計する。
- **V**erify: パイロット・試作で検証し、本番へ移管する。

判断: **既存プロセスの改善=DMAIC / 新規・ゼロからの設計=DMADV。** 無理に既存改善で新規を作らない。
