# MECE

## 概要

MECE（ミーシー）は、ある**全体集合**を **Mutually Exclusive（相互に排他的＝ダブりなし）** かつ
**Collectively Exhaustive（全体として網羅的＝モレなし）** な部分集合に分ける、分解・分類の原則。
日本では「**モレなくダブりなく**」と訳される。

| 頭字語 | 意味 | 日本語 | 崩れると起きること |
|---|---|---|---|
| **ME**（Mutually Exclusive） | 各要素が1区分にしか属さない | ダブり（重複）なし | 二重カウント・水掛け論・堂々巡り |
| **CE**（Collectively Exhaustive） | 区分の総和が全体を覆う | モレ（漏れ）なし | 重要論点の見落とし・後戻り |

- **核となる考え方**: MECEは「答え」を出す道具ではなく、分解・分類の**質を担保する規律**。
  何をどう分けるか（＝**切り口／軸**）を選び、その分け方が重複せず・漏れないかを検算する。
  MECEは**構造の正しさ**を保証するが、**洞察そのものは保証しない**（凡庸な切り口はMECEでも無価値）。
- **出自（諸説あり・要確認）**: **Barbara Minto** が1960年代後半に McKinsey で定式化したとされ、
  彼女の **ピラミッド原則**（*The Pyramid Principle*; 初版年は資料により1985/1987等と割れ要確認、増補版1996）の土台をなす。Minto自身は
  「淵源はアリストテレスで、私は初めてそれを略語にしアイデア群の分析に応用しただけ」と述べたと伝わる。
  分類・区分（division）の思想は古典論理学に遡り、図書館学の Ranganathan(1937) の網羅性・排他性の
  規範を先行例に挙げる資料もある。**考案年・発音・淵源の細部は断定せず要確認扱い**（→出典・要確認）。

## いつ使う / 使わない

**使う（適する状況）**
- 論点・原因・選択肢が絡み合い、**切り分けて整理**したいとき（会議・レポートの「話の交通整理」）。
- **抜け漏れが致命的**な検討で、網羅性を担保したいとき（リスク洗い出し、要件定義、調査設計）。
- **ロジックツリー／ピラミッドストラクチャー／イシューツリー**を作る前提の「分け方」を固めたいとき。
- 既存の分類（資料の目次、既存のKPI分解）に**ダブり・モレがないか検算**したいとき。

**使わない / よくある誤用（アンチパターン）**
- **切り口が凡庸で示唆が出ない**——最頻の失敗。あいうえお順のように技術的にMECEでも、
  意思決定に効かない軸では意味がない。「この分け方で**何が言えるか**」を軸選びの基準にする。
- **深掘りしすぎ・分解の目的化**——データを見る前に何階層も割る。目安は**2〜3階層**、
  検証する枝だけ深める。分解自体がゴールになると手が止まる（分析麻痺）。
- **完璧なMECEへの過剰固執**——MECEは手段であって目的でない。8割の網羅で意思決定に足りるなら進む。
- **フレームの機械的暗唱**——3Cや4Pを問題に合うか検証せず貼るだけ。既製枠は「MECEな切り口の候補」。
- **無理な二分でニュアンスを潰す**——重複や冗長性が本来必要な場面（創造的発散など）に強制すると、
  発想を不必要に狭める。MECEは分析・整理向きで、発散や飛躍には別の道具を使う。
- 厳密な定量最適化・優先順位づけそのものには不向き。MECEで分けた後、意思決定系フレームへ渡す。

## 前提と限界

- **前提**: 分ける対象の**全体集合と目的**が1つに定まっていること。目的が曖昧だと切り口が発散し、
  「MECEだが役に立たない分解」に堕ちる。分解して**何を判断・主張したいか**を先に言語化する。
- **限界（批判を踏まえて）**:
  - **関連性を保証しない**——MECEは重複・漏れを消すが、**無関係・冗長な項目の混入は防げない**。
    網羅的でも「効く論点」に絞れているとは限らない（Wikipedia等が指摘する批判）。
  - **切り口依存**——同じ対象でも軸の取り方で見える論点が変わる。悪い軸のMECEは思考を固定する。
  - **主観・単純化**——境界の引き方に恣意が入り、複雑な現実を割り切りすぎることがある。
  - **重複の一律排除の副作用**——本来は重なりや冗長性が有用な領域（冗長設計、多面評価）まで削る恐れ。
- これらは、**切り口を複数試して比較する / 分けた後にSo What?で示唆を出す / 発散が要る場面は発想系へ、
  優先順位は意思決定系へ渡す**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。

1. **全体集合と目的を1つに固定する。** 「何を（対象）／何のために（判断・主張）漏れなく分けるか」を明文化する。
   なぜ: 目的が無い分解はMECEでも示唆を生まない。切り口選びの基準は常に「目的に効くか」。
2. **切り口（軸）を選ぶ。** 目的に照らして、以下の型から分け方を1つ選ぶ。
   - **数式・恒等式**（例: 利益＝売上−コスト、売上＝客数×客単価）→ 恒等式は**自動的にMECE**。迷ったらまずこれ。
   - **プロセス・時系列・ステップ**（例: 認知→検討→購入→再購入、設計→製造→検査→出荷）。
   - **対照概念（二項対立）**（例: 質と量、既存と新規、内部と外部、ハードとソフト）。
   - **属性・セグメント**（例: 年齢層・地域）。境界が重ならないよう区切る。
   - **既製のMECE設計フレーム**（3C・4P・5フォース等）を「候補」として借りる（貼るだけにしない）。
   なぜ: 分け方が結論の見え方を決める。良い軸は「分けた瞬間に論点が立つ」。
3. **上位（広い視点）から top-down に分解する。** まず大きく2〜4個に割り、必要な枝だけ下位へ。
   なぜ: 下位の項目から積むと全体像を見失い、モレ・ダブりが起きやすい。
4. **階層は2〜3段に留める。** 全枝を均等に深掘りせず、**検証する枝だけ**を掘る。
   なぜ: 分解の深追いは目的化しやすい。データを見る前の過剰分解は時間を溶かす。
5. **ME（ダブり）を検算する。** 各ペアについて「同じ要素が両方の区分に入り得るか？」を問う。入るなら軸が甘い。
   なぜ: 重複は二重カウントと水掛け論を生む。ここで境界を締める。
6. **CE（モレ）を検算する。** 「例外的・突飛な事象（規制変更・会計要因など）を思い浮かべ、どこかに収まるか？」を問う。
   収まらなければ**切り口を組み直す**か、暫定で**残余の「その他」枝**を置く（「その他」が膨らむ軸は悪い軸）。
   なぜ: 漏れは後戻り（手戻り）の最大要因。恒等式や既製フレームはCEを担保しやすい。
7. **重要度で絞り、次の分析へ渡す。** 示唆に効く枝を上位数個に絞り、深掘り（ロジックツリー）や
   主張の構築（ピラミッド）、優先順位づけ（意思決定系）に接続する。
   なぜ: MECEは起点。分けて終わりにせず、そこから何を言うか・何を決めるかへ橋渡しする。

## 壁打ち質問リスト

各要素を埋めるために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。

1. いま分けたい**対象（全体集合）**は何で、**何のために**分けますか？（この分解で最終的に何を判断・主張したい？）
2. その目的に照らすと、どの**切り口（軸）**が効きそうですか？（数式／プロセス／対照概念／属性／既製フレームのどれ？）
3. 思いつく区分を挙げてください。その中で**内容が重なっていそうなペア**はどれですか？（＝ダブり検算）
4. もし**突飛な・例外的なケース**（想定外の顧客・規制・要因）が起きたら、いまの区分の**どこに収まります**か？収まらないものは？（＝モレ検算）
5. その分け方で分解すると、**どんな論点や示唆が立ちます**か？（別の切り口なら違う論点が見えませんか？）
6. 何階層まで割る必要がありますか？**今回の判断に必要な深さ**はどこまでですか？（過剰分解の抑制）
7. すでにある分類（目次・既存KPI・過去資料）はありますか？それに**モレ・ダブり**は無いと言い切れますか？

## 出力フォーマット

ALWAYS この型で出力する（切り口の明示→分解→ME/CE検算→次工程への橋渡し）。命令形で固定する。

```
【MECE分解】対象（全体集合）: <…> ／ 目的（何を判断・主張したいか）: <…>
  採用した切り口（軸）: <数式／プロセス／対照概念／属性／既製フレーム のどれか＋その軸名>

  分解（top-down・2〜3階層）:
    1. <区分A> ├─ <A-1> / <A-2> …（深掘りする枝のみ下位を展開）
    2. <区分B> ├─ …
    3. <区分C>
    （必要なら）その他: <残余。膨らむなら軸を見直す>

【検算】
  ME（ダブりなし）: <重なり得るペアと、その切り分け根拠 ／ 「重複なし」と判断した理由>
  CE（モレなし）:   <想定した例外がどこに収まるか ／ 漏れの有無>

【この分解から立つ論点・示唆】<分けた結果、何が言えるか。効く枝はどれか>
【次の一手】<掘り下げ=ロジックツリー / 主張化=ピラミッド / 優先順位=意思決定系 のどれへ渡すか>
【未確認の前提】<切り口の妥当性・境界の定義など、確認が要る点>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。ある店舗の「売上が伸び悩む原因」を切り分ける場面。

- **手順①目的**: 「どこに手を打てば売上が伸びるか」を判断するため、売上を漏れなく分解する。対象＝当店の売上。
- **手順②切り口**: 恒等式が最もMECEになりやすいので **売上 ＝ 客数 × 客単価** を軸に採る。
- **手順③top-down分解**:
  - 客数 ├─ 新規客数 ／ 既存客数（リピート）
  - 客単価 ├─ 1回あたり購入点数 ／ 商品単価
- **手順④階層**: 今回の判断に必要な2階層で止め、怪しい枝（例: 新規客数）だけ次に深掘りする方針にする。
- **手順⑤ME検算**: 「新規客」と「既存客」は同一来店で両方に入らないか？ → 定義を「初回来店＝新規、
  2回目以降＝既存」と決めれば重複しない。客数側と客単価側も掛け算の別要素で重複なし。
- **手順⑥CE検算**: 突飛な例（法人のまとめ買い、EC経由）はどこに入る？ → 客数×客単価の枠に収まる
  （まとめ買い＝客単価側、EC＝客数の一区分）。恒等式なので原理上モレは出ない。「その他」不要。
- **手順⑦絞り込みと橋渡し**: 影響が大きそうな「新規客数」を主要論点に据え、**ロジックツリー**で
  「なぜ新規客が増えないか（認知／来店動機／立地…）」へ分解を継続。打ち手が並んだら**意思決定系**で優先順位づけ。
- **未確認の前提**: 「新規/既存」の境界定義と、客単価の内訳データが取れるか——ここは実データで裏取りが要る
  （数字は挙げず、確認事項として残す）。

## 相性（組み合わせると効く）

- `logic-tree`: MECEな切り口で問題を樹形に分解する直接の続き。MECEはロジックツリーの各分岐が満たすべき原則。
- `pyramid-structure`: 結論を支える根拠グループがMECEかを検算し、抜け・重複のない主張を積む（Minto原則の土台）。
- `so-what-why-so`: MECEで分けた各枝から「で、何が言える？（So What?）」を引き出し、構造を示唆に変える。
- `fishbone`: 原因を4M等のMECE的な切り口（人・機械・材料・方法）で網羅する、原因分析版のMECE適用。
- `3c` / `5フォース(five-forces)`: 既製のMECE設計フレーム。MECEな切り口の「候補」として借りられる。
- 揺さぶり枠として `reverse-assumption`（切り口の常識を反転させ別の分け方を探す）や
  `devils-advocate`（「本当に漏れは無い？」と網羅性を疑う）を添えると、切り口固定の弊害を防げる。
