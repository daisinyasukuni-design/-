# ブレインライティング（635法）

## 概要

ブレインライティング635法は、参加者が**声を出さず紙（シート）にアイデアを書き**、一定時間ごとに隣へ回し、
他人の案を読んで**さらに書き足す**ことを繰り返す、**沈黙型のグループ発散法**。口頭ブレインストーミング（BS）の
弱点——声の大きい人の支配・発言待ちによる思考停止・批判される不安——を回避するために設計された。

- **「635」の由来**: **6人 × 3アイデア × 5分**。1ラウンド5分で各自3案、シートを回して6ラウンド行うと、
  算術上 6×3×6 = **108案を約30分**で強制的に生み出せる（108は理論値。実際の有効案数ではない）。
- **核となる考え方**: (1)**並列で書く**ことで、BSの「1人が話す間、他者は待つ」による発想阻害を無くす。
  (2)**沈黙・匿名的**にすることで、評価される不安と立場差を減らし全員を平等に参加させる。
  (3)回ってきた他者の案に**積み上げ（build-on／連想・発展）**させ、1人では出ない組み合わせを生む。
- **BSとの対比**: BS=「1人が話す→他は聞く」の**逐次・口頭**。635法=「全員が同時に書く」の**並列・書字**。
  両者は排他でなく、静かに数を稼ぐのが635法、即興の掛け合いで深めるのがBS、と使い分ける。
- **出自（諸説あり・年号に不確実性）**: ドイツのマーケティング／経営コンサルタント **Bernd Rohrbach** が
  「**Methode 635**」として発表したのが原型（発表年は資料により **1968年**（専門誌 Absatzwirtschaft）と
  **1969年** で食い違う）。「ブレインライティング」という呼称は、フランクフルトの **Battelle記念研究所**の
  **Horst Geschka** らが635法をベースに広めたとされる。日本へは **高橋誠** が紹介・普及し、6行×3列の
  「ブレインライティングシート」を回覧する形が定着した。**起源の細部は断定せず、要確認として扱う**（→出典）。

## いつ使う / 使わない

**使う（適する状況）**
- **声の大きい人・立場差でBSの意見が偏る**とき。上司の前で若手が話しにくい、特定の人が場を支配する等。
- **内向的なメンバーが多く**、口頭では発言が出ないチーム。静かに考える人の案を取りこぼさない。
- **短時間でアイデアの「数」をとにかく稼ぎたい**とき。発散の初速を最大化したい。
- **全員を平等に発想へ参加**させたい、社会的手抜き（誰かに任せる）を防ぎたいとき。
- リモート／非同期でもツール（オンライン付箋・共有シート）で実施でき、**議事録も自動で残る**。

**使わない / よくある誤用（アンチパターン）**
- **発散で終わり収束しない**——最頻の失敗。108案を出して満足し、グルーピング・選別・具体化をしない。
  635法は**発散専用**。必ずKJ法（親和性で束ねる）やペイオフマトリクス（効果×実現性で絞る）へ繋ぐ。
- **積み上げ（build-on）をせず、各自が独立に列挙するだけ**になる——635法最大の価値である「他者案への
  連想・発展」が失われ、ただの並列リストに堕ちる。「回ってきた案を読んで発展させる」を明示的にルール化する。
- **お題が悪い**——広すぎ／曖昧だと拡散し、狭すぎると3案も埋まらない。**単一の明確な問い**に絞る。
- **時間圧で埋め草が混じる**——「5分で3案」を義務化するため質より数になりやすい。**数を担保する設計と割り切り**、
  質は後段の選別で確保する（1ラウンド目から名案を求めない）。
- **可読性・意図伝達の軽視**——手書きの読みにくさや短すぎる記述で、次の人が誤解して積み上げる。一言で意図が伝わる書き方を促す。
- 深い相互議論・専門知識の擦り合わせ・合意形成が主目的の場、参加者が1〜2人で回せない場、
  すでに案が出揃い**評価・意思決定フェーズ**にある場には不向き。BSや意思決定系フレームで補う。

## 前提と限界

- **前提**: (1)発散させたい**単一の問い（お題）が1つに定まっている**こと。(2)回せる**人数（目安3〜6人）**がいること。
  (3)**沈黙・書字のルールを全員が守る**こと（途中の雑談は発想阻害の逆戻り）。(4)発散の**後段に収束工程を必ず置く**前提。
- **限界（研究と実務を踏まえて）**:
  - **その場の化学反応は起きにくい**——口頭BSの即興的な掛け合い・相互質問・その場の合意形成は苦手。
    深掘りや納得形成が要る局面では別手法（BS・議論）を併用する。
  - **重複・似た案が生まれやすい**——リアルタイムの調整が無いため、同種アイデアが衝突・重複する。収束工程での重複統合が前提。
  - **質は後段依存**——数を強制する設計上、玉石混交になる。635法単体で「良い案」は保証されない。評価・選別まで含めて初めて機能する。
  - **人数・時間は目安**——6人・3案・5分は**厳密な法則ではなく設計値**。4人→48案、5人→75案、7人→147案と規模で調整し、
    難しいお題ではラウンドの時間を延ばしてよい（後半ほど埋めにくくなるため）。
- 研究知見: 統制実験の蓄積では、書いて出す方式（や名義集団）は口頭BSに比べ **production blocking（発言待ちによる発想阻害）／
  evaluation apprehension（評価懸念）／social loafing（社会的手抜き）** を軽減し、**より多く多様な案を生む**傾向が報告される。
  ただしこれは**産出量の話**で、採否は収束工程で決まる（→相性のKJ法・ペイオフマトリクス）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。

1. **お題（発散の問い）を1つに絞って明文化する。** 「〜するにはどうすればよいか？」の形で、全員に見える場所へ掲示する。
   なぜ: お題が曖昧・複数だと発散が拡散し、収拾がつかない。単一の明確な問いが数と質の土台になる。
2. **参加人数とシートを準備する。** 目安3〜6人。各自に3列×6行（回すたびに1行ずつ埋まる）のシートを配る。進行役（モデレーター）を置く。
   なぜ: 「3案×何ラウンド」の器を先に用意すると、書く量とゴールが可視化され手が動く。
3. **ルールを宣言する。** 沈黙・批判禁止・時間厳守、そして**「回ってきた案を必ず読み、発展・連想させて書く（積み上げ）」**を強調する。
   なぜ: 積み上げを明示しないと、各自が独立に列挙するだけになり635法の核（他者案の化学反応）が死ぬ。
4. **第1ラウンド（5分）。** 各自が最上行の3マスに、お題への**3つのアイデア**を書く。発話・相談なし。
   なぜ: まず全員が同時に手を動かすことで、発言待ちゼロ・全員参加のスタートを作る。
5. **シートを一定方向の隣へ一斉に回す。** 右でも左でもよいが**全員同一方向**に。受け取ったら次の行に移る。
   なぜ: 一定方向に回すことで、全員の案が全シートを巡り、多様な視点が各案に積層する。
6. **他者の案を読んで、次の行に3案を書く（また5分）。** 上の案を**発展させる／連想する／組み合わせる**、または新規案でよい。
   なぜ: 他者の案が刺激（種）になり、1人では到達しない組み合わせが生まれる。ここが数だけでなく質の源泉。
7. **6ラウンド（シートが一巡）まで繰り返す。** 難しいお題は時間を延長してよい。埋まらない行があっても止めない。
   なぜ: 後半ほど発想が枯れるが、他者案の刺激で「絞り出し」から意外な案が出ることがある。
8. **全アイデアを一覧化する（発散の終了）。** シートを回収し、重複を許したまま全案をリスト化・可視化する。
   なぜ: ここまでが635法の守備範囲。次工程のために「素材」を全部机に並べる。
9. **収束（グルーピング→選別）へ橋渡しする。** KJ法で親和性グルーピング→ペイオフマトリクスやPMIで評価・選別し、**次の一手**を決める。
   なぜ: 発散だけでは意思決定できない。収束を必ず接続することで「108案出して終わり」の最頻失敗を防ぐ。

## 壁打ち質問リスト

各要素を埋めるために、利用者へ投げ返す問い。空欄を勝手に埋めず、まずこれで引き出す。

1. 今回**発散させたい問い（お題）**を「〜するにはどうすればよいか？」の一文にすると、何になりますか？（複数あるなら1つに絞る）
2. なぜ口頭のブレストでなく**書いて出す方式**が要るのですか？（意見の偏り・立場差・内向的メンバー・数を稼ぎたい等、狙いはどれ？）
3. **参加者は何人**で、立場や専門はどのくらいばらついていますか？（人数で案数と回し方が変わる。声が偏る要因があるか）
4. このお題は**広すぎ／狭すぎ**ませんか？——1人が5分で3案を無理なく出せる粒度か、逆に発散しすぎないか、どう感じますか？
5. 出した大量の案を、**このあと誰がどう選別・意思決定**しますか？（収束の担い手と基準＝効果/実現性などを先に決めておく）
6. 参加者に**前提知識やインプット（顧客の声・データ・現場の困りごと）**は足りていますか？不足なら発散前に何を共有しますか？
7. 「回ってきた案を**発展させて書く（積み上げる）**」ルールは徹底できそうですか？それとも各自バラバラに書く懸念がありますか？

## 出力フォーマット

ALWAYS この型で出力する（設計 → 発散シート → 収束への橋渡し）。命令形で運用する。

```
【お題】<「〜するにはどうすればよいか？」の単一の問い>
【設計】人数: <n>人 ／ 1ラウンド: 3案×5分 ／ ラウンド数: <r> ／ 想定案数: <n×3×r>（理論値）
        回す方向: <右/左（全員同一）> ／ 収束の担い手・基準: <誰が・効果×実現性 等>

【発散シート（例: 参加者ごと×ラウンド）】
  R1: <A案1> / <A案2> / <A案3>   （最初の3案）
  R2: <前の案を発展/連想した3案>   … 積み上げを明示
  …
  R<r>: <…>
  ※沈黙で記入、一定方向に回覧。他者案を読んで発展させる。

【発散の集計】総案数: <約N案> ／ 重複・類似は残したまま一覧化

【収束への橋渡し】
  グルーピング（KJ法）: <束ねたテーマ群>
  選別（ペイオフ/PMI）: <効果×実現性で上位に来た候補>
  【次の一手】: <検証・意思決定・アクションを1〜3個>
【未確認の前提】: <発散前に埋めるべき情報（壁打ちで補う）>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。社内カフェスペースの利用率を上げる案を、
立場差のあるメンバー（管理職と若手が混在）で短時間に多数出したい場面。

- **手順①お題**: 「社内カフェスペースの利用率を上げるにはどうすればよいか？」の一文に固定。
- **手順②準備**: 参加者を数名（例: 5名前後）、各自に3列×6行のシート、進行役1名。想定案数=人数×3×ラウンド数（理論値）。
- **手順③ルール宣言**: 沈黙・批判禁止・時間厳守＋「回ってきた案を読んで発展させて書く」を強調（積み上げの徹底）。
- **手順④第1ラウンド**: 各自が最上行に3案（例: 「昼の時間帯だけ飲み物を割引」「雑談用のテーマカードを置く」等、方向性の異なる3つ）。
- **手順⑤〜⑦回覧と積み上げ**: 右隣へ一斉に回す。受け取った人は上の「テーマカード」案を発展させ「業務相談カードに変える」等、
  他者案を種に新案を重ねる。これをシートが一巡するまで繰り返す。立場差があっても沈黙なので若手案も等価に残る。
- **手順⑧集計（発散終了）**: 全シートを回収し、重複を許して全案を一覧化（数十案規模の素材が机に並ぶ）。
- **手順⑨収束への橋渡し**: KJ法で「時間帯施策／空間・レイアウト／きっかけづくり／情報発信」等に束ね、
  ペイオフマトリクス（効果×実現性）で上位候補を数個に絞る。
- **次の一手**: 上位案を1つ小さく試し、利用率という仮説を検証する（誰がいつ測るかまで決める）。
- **未確認の前提**: 現状の利用率・利用者層・使われない理由——ここは発散前に現場データで共有しておくと積み上げの質が上がる。

## 相性（組み合わせると効く）

- `brainstorming`: 口頭BSと対比・使い分け。静かに数を稼ぐのが635法、即興の掛け合いで深めるのがBS。前半BW→後半BSも有効。
- `scamper`: 積み上げが枯れたとき、7動詞（代用・結合・応用…）を各行の刺激として与え、発想の切り口を補給する。
- `osborn-checklist`: 同上。9つの問いをお題脇に掲示し、案が出ない参加者のガイドにする。
- `kj-method`: 発散後の**収束の第一段**。大量の案を親和性でグルーピングし、構造を見つける直接の続き（手順⑨）。
- `payoff-matrix`: グルーピング後、効果×実現性で候補を絞り込み「次の一手」に落とす収束・選定（手順⑨）。
- `mandala-chart`: お題を先に3×3で分解しておくと、発散の観点が広がり偏りを防げる（前工程）。
- 揺さぶり枠として `reverse-assumption`（お題の常識を反転させて別のお題を立てる）や `random-word`（無関係な語を刺激に）を
  マンネリ打破に添えると、積み上げの新規性が増す。
