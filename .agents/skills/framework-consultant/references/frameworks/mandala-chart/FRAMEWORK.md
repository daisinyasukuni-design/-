# マンダラート

## 概要

マンダラートは、**3×3＝9マス**の中央に主題（テーマ/目標）を置き、**周囲8マスをすべて埋める**という
作業ルールで連想を強制し、思考を外化・整理する発想法。空白を埋める制約が「もう出ない」を超えて
アイデアを引き出す。9マスは1単位で、周囲の1マスを別紙の中央へ**転記して同じ操作を繰り返す**ことで
階層を掘り下げられる。中央に大目標を据えた**9×9＝81マス**版では、中央3×3の8マスに中目標、
外周8ブロックに小目標を書き、最大72個（中目標8＋小目標64）の**具体行動**へ分解できる。

- **核となる考え方**: 二つの機能を併せ持つ。(1) **放射状の網羅**——8方向へ広げ、思いつきの偏りや
  抜けを減らす（MECE的な広がり）。(2) **深掘り**——1マスを新たな中心に転記し、抽象を具体へ掘る。
  「広げる」と「掘る」を1枚のグリッドで往復するのが他の発想法と違う点。
- **出自（一次資料あり・諸説と混同あり）**: デザイナーの **今泉浩晃** が **1987年** に考案した
  「マンダラート（Mandal-Art）」が原型とされる（名称は曼荼羅＝マンダラ＋アートの合成、仏教曼荼羅の
  格子状構造が着想源）。考案年（1987年）は考案者・今泉自身の初の著書『創造性を高めるメモ学入門: Mandal-art』
  （日本実業出版社, 1987, →出典）で裏付けられる。ただし「着想の正確な初出年」には諸説が残る（→要確認）。
- **名称の混同に注意（重要）**: よく似た別系統が併存する。
  - **マンダラチャート**（英名 Mandala Chart）: **松村寧雄** が **1979年**（今泉より前）に考案。
    「マンダラ思考」＋3×3フレーム、A型（9マス）/B型（9×9）。**一般社団法人マンダラチャート協会の登録商標**。
  - **オープンウィンドウ64**: **原田隆史**（原田メソッド）の81マス目標達成ツール（心・技・体・生活で分解）。
  - **大谷翔平が高1で書いた「8球団からドラフト1位」の目標達成シートは、日経ビジネス等では
    オープンウィンドウ64として紹介される。「大谷のマンダラート」は通称**であり、厳密な帰属は要確認。
  本スキルは発散（ideation）ツールとしての9マス／81マス手法を扱い、上記の帰属差は断定せず併記する。

## いつ使う / 使わない

**使う（適する状況）**
- アイデアが**一つも浮かばず行き詰まった**とき。空欄8マスの制約が「もう一歩」を強制的に引き出す。
- テーマを**多方向に網羅的に広げたい**とき（発想の偏り・抜けを減らす起点）。
- 大きな目標を「**結局、何をやるか**」の**具体行動へ分解**したいとき（9×9で大→中→小へ）。
- **自己分析・進路計画・企画のとっかかり**など、頭の中を**1枚に外化**して整理したいとき。
- 一人でも、少人数でも回せる**軽量なブレスト**が欲しいとき。

**使わない / よくある誤用（アンチパターン）**
- **穴埋めが目的化する**——最頻の失敗。81マス埋めた満足で止まり、行動・検証に繋がらない。埋めた後に
  必ず「どれをやるか」へ絞る工程（→相性: payoff-matrix / decision-matrix）へ渡す。
- **8つに割れないテーマに無理やり詰める**——すべてが8分割できるわけではない。数合わせでひねり出した
  項目は不要物として混入する。埋まらない枠は空白のまま残すか、テーマの粒度を見直す。
- **テーマが抽象的/小さすぎる**——広すぎると発散し、小さすぎると即枯れる。中心の主題設定が成否の8割。
- **前提知識の不足で空欄が残る**——知らない領域は8マスが埋まらない。調べる/他者に聞く前提で使う。
- **深掘り（転記）を使わず単発9マスで終える**——それだと単なるブレストの劣化版。掘り下げてこそ価値が出る。
- **優先順位づけ・定量最適化・因果分析には不向き**——広げ切ったら別フレームへ接続する。

## 前提と限界

- **前提**: 中心に置く**主題が1つに定まっている**こと。目的（発想を広げたい／目標を行動に落としたい）が
  曖昧だと、埋めても使えないマスが並ぶ。9×9で目標分解するなら、中央の大目標が具体的であること。
- **限界**:
  - **発散専用で、収束・評価・優先順位づけの機能は無い**。72個出しても「どれをやるか」は決めてくれない。
  - **8という枠数は恣意的**。テーマによっては8で足りない/多すぎる。枠に思考が縛られる副作用がある。
  - **質より量に流れやすい**。埋まったマスの多くは凡庸で、深掘り（転記）と選別をしないと使えない。
  - **一人の知識・語彙に依存**。参加者や情報が乏しいと空欄が残り、視野の外は出てこない。
- これらは、**埋めた後にpayoff-matrix/decision-matrixで絞る／深掘りの切り口をmece・logic-treeで補強する／
  目標の質をkgi-kpi-okr・backcastingで検証する**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。まず9マス（3×3）で回し、必要なら81マス（9×9）へ拡張する。

1. **目的を1つ決める。**「発想を広げたい」のか「目標を具体行動に分解したい」のかを先に定める。
   なぜ: 目的で中心の主題の置き方（テーマ語 or 目標）と、後工程（絞る/実行する）が変わる。
2. **中央マスに主題を書く。** 発散なら核となるテーマ語、目標分解なら**具体的な大目標**を中央に置く。
   なぜ: 中心が曖昧だと8方向が発散する。粒度は「8つ関連要素が出せる」広さに調整する。
3. **周囲8マスを埋める。** 主題に関連する語・切り口・要素を、**実現可能性を問わず**思いつくまま8つ書く。
   なぜ: 判断を保留して量を出すのがブレストの原則。埋める制約が「もう一歩」を引き出す。
4. **埋まらない枠を処理する。** 出なければ (a) 一旦放置して別マスへ進む、(b) 人に聞く/調べる、
   (c) 中心の粒度を見直す。**数合わせで不要項目を捏造しない**。
   なぜ: 無理な穴埋めは後工程の判断を濁す。空白は「その方向は薄い」という情報でもある。
5. **深掘りする（転記して繰り返す）。** 8マスから掘りたい1つを選び、別紙の**新しい中央**に転記して手順3へ。
   抽象的な語ほど掘る価値がある。
   なぜ: 転記による反復が「広げる」を「掘る」に変える。マンダラートの核はここにある。
6. **（目標分解なら）9×9＝81マスに展開する。** 中央3×3の8マス＝**中目標**、外周8ブロックの各中心に
   中目標を写し、その周囲8マスに**小目標（具体行動）**を書く。中目標8＋小目標64で最大72アクションになる。
   なぜ: 大目標のままでは動けない。中→小へ二段で割ると「明日やること」まで下りる。
7. **広げ切ったら収束させる。** 出た要素・行動から、重要度×実現性で**やるものを絞る**（→payoff-matrix等）。
   目標分解なら、実行・指標づけ（→kgi-kpi-okr）や失敗の先回り（→premortem）へ渡す。
   なぜ: マンダラートはゴールでなく起点。埋めて終わると「作って満足」の典型に陥る。

## 壁打ち質問リスト

各マスを意味のある内容で埋めるために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。

1. このマンダラートの**目的**はどちらですか？——「発想を広げたい」／「大きな目標を具体行動に落としたい」。
2. **中央に置く主題**は何ですか？ それは8つの関連要素を出せる**粒度**ですか（広すぎ/狭すぎないか）？
3. （目標分解なら）中央の大目標は**いつまでに・何をどれだけ**という形で具体化できていますか？
4. その主題について、真っ先に思い浮かぶ**切り口・関連要素**を、良し悪しを問わず挙げると何がありますか？
5. 8マスのうち**埋めにくい方向**はどこですか？ それは知識不足のためですか、主題の粒度のためですか？
6. 8つの切り口は**互いに重複していませんか／大事な方向が抜けていませんか**（MECEに近いか）？
7. 8マスの中で、**さらに深掘りして具体化したい**のはどれですか（＝転記して次の中心にする候補）？
8. 埋めた後、**最終的にどれを実行に移すか**を、何の基準（効果・実現性・締切）で選びますか？

## 出力フォーマット

ALWAYS この型で出力する（グリッド提示 → 深掘り → 収束提案の3段）。9マス基本、目標分解時は81マス版を使う。

```
【マンダラート】目的: <発想拡張 / 目標分解> ／ 中央の主題: <テーマ or 大目標>

  ┌─────────┬─────────┬─────────┐
  │ ①<切り口> │ ②<切り口> │ ③<切り口> │
  ├─────────┼─────────┼─────────┤
  │ ④<切り口> │  中央:主題  │ ⑤<切り口> │
  ├─────────┼─────────┼─────────┤
  │ ⑥<切り口> │ ⑦<切り口> │ ⑧<切り口> │
  └─────────┴─────────┴─────────┘
  ※埋まらない枠は「（空白：この方向は薄い）」と明示し、数合わせで捏造しない。

【深掘り（転記）】掘る枠: <①〜⑧の1つ> → それを中心に8つ展開:
  - <具体化した小項目1> … <小項目8>   （目標分解なら中目標→小目標64まで同様に展開）

【81マス版（目標分解モードのみ）】中央3×3＝大目標＋中目標8、外周8ブロック＝各中目標を転記し小目標8を展開:
  ┌─────────┬─────────┬─────────┐
  │ Aブロック │ Bブロック │ Cブロック │  各外周ブロック=3×3。中心=中目標(中央から転記)、
  ├─────────┼─────────┼─────────┤  周囲8マス=その中目標の小目標(具体行動)。
  │ Hブロック │  中央3×3   │ Dブロック │  中央3×3: 中心=大目標、周囲8(A〜H)=中目標。
  │         │(大目標+中目標8) │         │
  ├─────────┼─────────┼─────────┤  ※中目標は「中央の1マス」と「外周ブロックの中心」の
  │ Gブロック │ Fブロック │ Eブロック │    2箇所に同じ語を書く(=転記)。
  └─────────┴─────────┴─────────┘  → ユニーク行動72(中目標8+小目標64)／総マス81。

【収束の提案】<広げた要素をどう絞る/実行に渡すか。例: payoff-matrixで効果×実現性、kgi-kpi-okrで指標化>
【次の一手】<絞った要素を試作・検証・指標化・意思決定に落とす（1〜3個）>
【未確認の前提】<埋まらなかった方向・追加で調べる前提>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。**個人が「健康的な生活習慣を身につける」**を主題にする場面。

- **手順①目的**: 「大きな目標を具体行動に落とす」＝目標分解モードを選ぶ。
- **手順②中央**: 大目標を「健康的な生活習慣を身につける」に設定（8要素が出せる粒度に調整）。
- **手順③〜④8マス（中目標）**: 食事／運動／睡眠／ストレス管理／体重・数値の把握／通院・検診／
  人間関係・環境／継続の仕組み——の8方向を埋める。どれも8つ思いつくので空白は残らなかった。
- **手順⑤深掘り（転記）**: 抽象度の高い「継続の仕組み」を新しい中央に転記して掘る。
- **手順⑥81マス展開**: 各中目標を外周ブロックの中心に写し、小目標（具体行動）へ分解する。
  - 例「睡眠」→ 就寝時刻を固定／寝る前の画面を減らす／寝室を暗くする／カフェインの時刻を見直す…（8つ）。
  - 例「継続の仕組み」→ 記録をつける／人に宣言する／小さく始める／できた日を可視化する…（8つ）。
  - 8中目標×8で最大64の小目標（＋中目標8＝72項目）が並ぶ。
  - **数の呼びぶれを解消**: 中目標8個は「中央3×3」と「各外周ブロックの中心」の2箇所に書かれ、計16マスを占有する。
    そのためユニークな行動項目は**72**（中目標8＋小目標64）だが、総マス数は大目標1＋中目標16（＝8×2重）＋小目標64＝**81**。
    「72＝ユニーク行動」「64＝小目標のみ」「81＝総マス」という数え方の違いが、資料ごとの呼びぶれの正体（同じ図の別カウント）。
- **手順⑦収束**: 72項目のうち「効果が大きく、今すぐ始められる」ものを数個に絞る（→payoff-matrix）。
  目標側は「何をどれだけ」を指標化（→kgi-kpi-okr）し、続かない要因を先回りする（→premortem）。
- **未確認/空白**: 医療・数値目標は自己判断せず専門家・実データで裏取りする（推測のまま進めない）。

## 相性（組み合わせると効く）

- `payoff-matrix`: マンダラートで広げた多数のアイデア/行動を、効果×実現性で**絞り込む**収束の直接の続き（発散→収束）。
- `decision-matrix`: 出した選択肢を複数の評価軸で採点し、実行対象を選ぶ。優先順位づけ機能の無さを補う。
- `mece` / `logic-tree`: 8マスの切り口が**重複・抜け**なく割れているかを検算し、深掘りの分解軸を補強する。
- `mind-map`: 同じ放射状の発想でも自由枝分かれ型。厳密な9枠が窮屈なテーマではこちらへ切り替える。
- `osborn-checklist` / `scamper`: 8マスが埋まらないとき、強制発想の問い（転用/応用/変更/結合…）で切り口を供給する。
- `kgi-kpi-okr`: 目標分解モードの成果（大→中→小）を、指標・実行管理へ接続する後工程。
- `backcasting`: 中央の大目標を「あるべき未来から逆算」して設定し直し、目標の質を高める前工程。
- 揺さぶり枠として `premortem`（分解した行動が失敗する要因を先回り）や `reverse-assumption`
  （中央テーマの前提を反転して発想を跳ばす）、`devils-advocate`（埋めた項目の思い込みを疑う）を添えると洞察が増す。
