# デザイン思考（Design Thinking）

## 概要

デザイン思考は、**ユーザーへの共感（Empathize）** を起点に、**定義(Define) → 発想(Ideate) → 試作(Prototype) → テスト(Test)** を
反復して、人間中心（human-centered）に解を作るイノベーション・プロセス。核は
**「人のニーズ・技術の可能性・事業の成立要件」の3つを重ねる**こと（IDEO / Tim Brown の定義）。

| モード | 問い | アウトプット |
|---|---|---|
| ① 共感 Empathize | ユーザーは実際どう動き、何に困っているか？ | 観察された事実・生の声 |
| ② 定義 Define | 本当に解くべき問いは何か？ | ユーザー中心の問題文(POV)／HMW |
| ③ 発想 Ideate | どうすれば解けるか（多数・多様に） | アイデア群＋試作候補2〜3案 |
| ④ 試作 Prototype | 速く安く試せる形は？ | 低忠実度プロトタイプ |
| ⑤ テスト Test | 実ユーザーはどう反応するか？ | 学び＋次に戻る段階 |

- **最重要の性質——非線形・反復**: 5つは順序どおりの「ステップ」ではなく並行・前後・反復する「**モード**」。
  テストの学びが定義や発想に戻る「永久ループ」。IxDF いわく *"different modes … rather than sequential steps"*。
- **向く問題**: 定式化が一つに定まらず、人の行動・体験に根ざす「**厄介な問題（wicked problem）**」（Rittel & Webber 1973）。
- **出自（諸説あり・要確認）**: 知的源流は Herbert Simon『The Sciences of the Artificial』(1969) の「満足化(satisficing)」等。
  Stanford で Robert McKim → Rolf Faste（1980-90年代）が発展させ、David Kelley が事業応用、**IDEO**(1991設立) と
  **d.school**（Hasso Plattner Institute of Design, 2004/2005頃）が普及、**Tim Brown** の HBR論文(2008)で経営に定着。
  ※「design thinking」の語や5段階モデルの起源は単一に断定できない（→出典・要確認）。
- **各モードの詳細手法は references/ に退避**（大物のため本体は「概要＋どのモードをいつ使うか＋壁打ち」に絞る）:
  `references/empathize.md` `define.md` `ideate.md` `prototype.md` `test.md`。

## いつ使う / 使わない

**使う（適する状況）**
- **顧客が本当に欲しいものが分からない**／ニーズが未知で、まず人を理解するところから始めたいとき。
- **新規サービス・製品・体験の構想**を、作り手都合でなくユーザー起点で発想したいとき。
- **課題設定そのものが曖昧**で、「何を解くべきか」から問い直したいとき（wicked problem）。
- **思い込みで作って売れなかった**後の立て直し。小さく試して学び直したいとき。
- 部門横断で**共通の顧客像と問い**を作り、対話的に進めたいとき。

**使わない / よくある誤用（アンチパターン）**
- **共感を飛ばす**——「もう顧客は分かっている」と観察を省く。最頻の失敗。基礎工事なしに家を建てるのと同じ。
- **偽の共感（false empathy）**——数字を眺めただけ・自分の枠を押し付けたまま「共感したつもり」。前提を手放す姿勢が要る。
- **儀式化（design theater）**——ポストイットとワークショップの形式だけ整え、実ユーザー・試作・**批評(crit)**・実装が伴わない。
  Natasha Jen の「デザイン思考はBS」批判の核心はこの「相互批評の欠如」。
- **試作を作り込みすぎ／解に執着**——高忠実度に時間をかけ、捨てられず反証を無視する。
- **問題と最適解がすでに明確な純技術・最適化課題**には過剰。安全性/規制で反復試作が困難な領域、
  深い構造的・政治的問題（歴史に根ざす社会課題）も、単独では射程外。他手法で補う。

## 前提と限界

- **前提**: (1)実ユーザーに会える/観察できること（会えないなら共感が成立せず作文に堕ちる）。
  (2)速く安く試作・テストを回せる余地があること。(3)反復・反証を許す時間と権限があること。
  これらが無い場ではデザイン思考は「儀式」化しやすい。
- **限界（批判を踏まえて）**:
  - **プロセス偏重・脱技能化**——Natasha Jen は「crit（相互批評）の欠如」「成果物の質が問われない」と批判。
  - **脱政治化・特権性**——Lucy Kimbell は経営実務の脱政治化を、Iskander はデザイナーの特権的地位の固定化を指摘。
  - **過大宣伝**——Lee Vinsel は能力を伴わない「creative confidence」を与えるだけになり得ると警告。
  - **共感の質に依存**——観察が浅い/誘導的だと、その上の定義・発想すべてが歪む。
- これらは、**実ユーザーでのテストと相互批評(crit)を必ず入れる／試作は低忠実度で速く回す／
  問題設定を jtbd・persona で補強する**ことで緩和できる（→相性）。

## 進め方（手順）

命令形で示す。各モードの「なぜ」を添える。**順番は目安——学び次第で前のモードへ戻る**。詳細手法は各 references を参照。

1. **課題と対象ユーザーを仮置きする。** 「誰の、どの体験を良くするのか」を1つに仮設定する。
   なぜ: 焦点が無いと観察が発散する。仮説でよい（後で問い直す前提）。
2. **共感する（Empathize）。** インタビュー・行動観察で、ユーザーが**実際どう動き何に困るか**を、思い込み抜きで集める。
   「言うこと」と「すること」のギャップを探す。なぜ: 全工程の土台。ここを飛ばすと思い込みの上に家が建つ。→ `references/empathize.md`
3. **定義する（Define）。** 観察を統合し、**ユーザー中心の問題文(POV)** と **「どうすれば〜できるか(HMW)」** に落とす。
   問いに解を混ぜない。なぜ: 問題設定の質が発想の質の上限を決める。→ `references/define.md`
4. **発想する（Ideate）。** HMWに対し、**発散（判断保留で量）→ 収束（選ぶ）を時間で分けて**多数・多様な案を出し、
   試作に進める2〜3案を残す。なぜ: 最初の無難な案に飛びつくと問題空間の縁を探れない。→ `references/ideate.md`
5. **試作する（Prototype）。** 「この試作で確かめたい仮説」を1つ決め、**低忠実度で速く安く**形にする。
   なぜ: 議論で決着しないことをモノで決着させる。作り込むほど捨てにくく判断が鈍る。→ `references/prototype.md`
6. **テストする（Test）。** 実ユーザーに使ってもらい**行動を観察**、反証を歓迎して学ぶ。作り手は黙る。
   なぜ: テストは正しさの証明でなく間違いの発見の場。→ `references/test.md`
7. **反復する。** 学びから**どの段階へ戻るか**を決める（定義やり直し／別案を試作／実装へ）。
   なぜ: デザイン思考はゴールでなくループ。1周で終わらせない。

## 壁打ち質問リスト

各モードを事実で埋めるために、利用者へ投げ返す問い。空欄を勝手に埋めず、まずこれで引き出す。

1. **誰の、どの場面の体験**を良くしたいですか？その人に実際に**会える／観察できます**か？（共感の成立条件）
2. そのユーザーについて、いま「**事実として観察したこと**」と「**まだ思い込み・仮説なこと**」はそれぞれ何ですか？
3. ユーザーが「**言っていること**」と、実際に「**やっていること**」の間に、ズレや不便な回避行動（workaround）はありますか？
4. いま解こうとしている問題は、「**ユーザーのニーズ**」が主語ですか、それとも「**自社の願望（売上・シェア）**」が主語ですか？
5. この課題は、答えが一つに定まる**技術・最適化の問題**ですか、それとも人の行動次第で見え方が変わる**厄介な問題**ですか？
6. アイデアを**速く安く試せる形**（紙・寸劇・ダミー）は何ですか？その試作で**確かめたい仮説**は1つに絞れますか？
7. テストで**都合の悪い結果**が出たら、どの段階に戻る覚悟がありますか？（反証を受け入れられるか）
8. すでに答え（作りたいもの）が決まっているなら、それは本当にユーザー起点ですか？——それとも儀式として共感を挟むだけですか？

## 出力フォーマット

ALWAYS この型で出力する（5モードの現在地＋反復の設計）。各モードは「観察された事実／仮説」を明示し、空欄は壁打ちで埋める。

```
【デザイン思考】対象ユーザー: <誰の・どの体験> ／ 現在地: <いまどのモードか>

① 共感(Empathize): <観察された事実・生の声>（※事実と思い込みを分ける／未取得は「要観察」と明記）
② 定義(Define):
   POV: <[ユーザー] は [ニーズ] を必要としている。なぜなら [インサイト] だから>
   HMW: どうすれば <…> できるか？（解を含めない）
③ 発想(Ideate): <試作に進める2〜3案（無難案／大胆案を混ぜる）>
④ 試作(Prototype): <低忠実度の形＞ ／ 確かめたい仮説: <1つ>
⑤ テスト(Test): <観察したい反応・破綻点> ／ 反証が出たら戻る先: <定義／発想／試作>

【次の一手】<次に回すモードと、確かめる仮説1〜2個>
【未確認の前提】<事実確認・実ユーザー観察が要る点（壁打ちで埋める）>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。**地域の公共図書館が「若い世代の利用を増やしたい」**と相談する場面。

- **手順①仮置き**: 対象を「近隣に住むが図書館を使っていない20〜30代」と仮設定。「利用を増やす」ではなく彼らの体験に焦点。
- **手順②共感**: 数人に同行観察・インタビュー。判明した**ズレ**——「本は好き」と言うが（言うこと）、実際は開館時間に来られず、
  そもそも「図書館＝静かで堅い場所、自分の居場所ではない」と感じている（やること・本音）。
- **手順③定義**:
  - POV: 「働く20〜30代は“気軽に立ち寄れる第三の居場所”を必要としている。なぜなら“本を借りる”より“居場所”に価値を感じるから」
  - HMW: 「どうすれば、開館時間や“堅さ”に縛られず、彼らが気軽に立ち寄れるか？」（解を含めない粒度）
- **手順④発想**: 発散→収束で候補を出し、多様性を持たせて残す——(a)夜間の交流イベント枠、(b)貸出不要の滞在スペース、
  (c)近隣店舗と連携した“持ち出し本棚”。無難案と大胆案を混ぜる。
- **手順⑤試作**: (b)を**低忠実度**で検証。既存の一角に椅子と電源を仮設置するだけ（作り込まない）。
  確かめたい仮説=「滞在できる場があれば、貸出目的でなくても来るか」。
- **手順⑥テスト**: 数日置いて**行動を観察**。滞在は増えたが「入ってよいか分からず入口で引き返す」人が出た（想定外の破綻点）。
- **手順⑦反復**: 学びから **定義には戻らず、試作に戻る**——「入りやすさ（サイン・導線）」を次の検証テーマに設定して回す。
- **未確認の前提**: 観察はごく少人数。滞在ニーズの広がりは、対象を変え複数回テストして裏取りが要る（推測のまま進めない）。

## 相性（組み合わせると効く）

- `jtbd`: 「共感／定義」の質を上げる。ユーザーが**片付けたい用事(Job)**の視点で、観察から本当のニーズを抽出する。
- `persona`: 共感で得た観察を**具体的な人物像**に束ね、チームで共有できる対象像にする。
- `customer-journey`: 体験を時系列で可視化し、共感の観察を**どの接点でつまずくか**として構造化する。
- `brainstorming` / `scamper`: 発想(Ideate)モードの発散を、判断保留の連想や強制変形で加速する具体手法。
- `kj-method`: 定義(Define)で観察の断片を**親和性でグルーピング**し、パターン・インサイトを抽出する。
- `value-proposition-canvas`: 定義した課題と、発想した解の**提供価値の対応**を検証し、独りよがりを弾く。
- `lean-startup-mvp`: 試作／テストの先で、**最小構成での市場仮説検証**へ橋渡しする（反復思想が地続き）。
- 揺さぶり枠として `premortem`（試作を出す前に「なぜ失敗したか」を先回り）、`devils-advocate`（共感が思い込みでないか反対役で疑う）、
  `reverse-assumption`（「ユーザーは◯◯を望む」の逆を置いて発想を跳ばす）を添えると、儀式化と確証バイアスを防げる。

**要ファクトチェック（Web調査で誤りが混入しやすい断定）**
- **考案者・起源の帰属**: 「design thinking」の語や思想を単一人物に帰属できない。Herbert Simon(1969) は源流の一つだが本人がこの語を作ったわけではない。McKim → Faste → Kelley の系譜、Peter Rowe(1987) の同名書、Nigel Cross・Bryan Lawson らの学術系譜は資料により強調点が異なる。
- **年号**: IDEO設立(1991)、d.school 設立(2004 か 2005 か)、Tim Brown HBR論文(2008)、Rittel & Webber(1973)——二次情報が多く、一次で要確認。
- **「5段階」は唯一の正典ではない**: d.school は5モード、IDEO は3I（Inspiration/Ideation/Implementation）、Design Council は Double Diamond（4D）、IBM は the Loop。段階数・名称はモデルで異なる。「4段階目に Implement を足す6段階版」等も流通。
- **POV/HMW の定型文・SCAMPER 等の手法名**は実務慣用で、教材により表記・区分が揺れる。
