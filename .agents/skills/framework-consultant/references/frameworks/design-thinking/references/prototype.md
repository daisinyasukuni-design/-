# 試作（Prototype）— 詳細ガイド

> FRAMEWORK.md 手順④の詳細。アイデアを「速く・安く・捨てられる形」にして学ぶモード。
> 目的は完成品を作ることではなく、**最小の投資で仮説を検証する**こと。作り込むほど捨てにくくなり判断が鈍る。

## 目的
- アイデアを手で触れる形（tangible）にし、ユーザーの反応・限界・想定外を**早く安く**学ぶ。
- 「議論では決着しないこと」をモノで決着させる。

## 主な手法（忠実度は低から）
- **ペーパープロトタイプ / スケッチ**: 紙・手書き画面で流れを試す。最速・最安。
- **ストーリーボード / 寸劇（body-storming）**: 体験の流れを絵・寸劇で再現する。サービス系に有効。
- **モックアップ / ダミー**: 見た目や手触りだけ作る。機能は未実装でよい。
- **Wizard of Oz**: 裏で人が手動で処理し、あたかも動くように見せて反応を見る。
- **忠実度は段階的に上げる**: まず低忠実度で方向性を、方向が定まってから作り込む。

## 検証したい問いを先に決める
- 「この試作で**何を確かめたいか**（どの仮説）」を1つに絞ってから作る。
- 例: 「この操作の順番でユーザーは迷わないか」「この価値提案に価値を感じるか」。

## 成果物
- 触れる試作物 ＋ 「確かめたい仮説」と「観察の観点」のメモ。
- 検証後: 受容 / 改善 / 棄却 の判断。

## つまずき所・誤用
- **作り込みすぎ**: 高忠実度に時間をかけ、捨てられず解に執着する（sunk cost）。低忠実度で十分な学びを先に。
- **テストが通りやすいよう最適化**: 試作を都合よく整えると検証の妥当性が失われる。
- **仮説なしの試作**: 何を確かめるか決めずに作ると、テストで何を見ればよいか分からない。
- **試作＝完成品と誤解**: 試作は学ぶ道具。壊れて/否定されて当然という前提を持つ。

## 壁打ちで確認すること
- この試作で確かめたい仮説は1つに絞れているか。
- どこまで作れば学べるか（それ以上作らない線引き）。
