# PMI（Plus / Minus / Interesting）

## 概要

PMIは、検討対象（1つのアイデア・提案・選択肢）を **Plus（良い点）/ Minus（悪い点）/ Interesting（面白い点・興味深い点）** の
3チャンネルに沿って**意図的に注意を向けて（scan）**多面的に評価する、Edward de Bono の判断・批判的思考ツール。

| チャンネル | 何を出すか |
|---|---|
| **P（Plus）** | 利点・良い結果・魅力。「これが良い」 |
| **M（Minus）** | 欠点・危険・悪い結果。「これが困る」 |
| **I（Interesting）** | 良し悪しの**外**にある観察・含意・可能性。「〜だとしたら面白い」「〜になるのを見てみたい」 |

- **核となる考え方**: アイデアへの自然な反応は「好き/嫌い・賛成/反対」を**即決する**こと。その感情反応が視野を狭める。
  PMIは判断を後ろにずらし、**P→M→I を一方向にスキャンしてから**最後に判断させる。de Bono曰く「PMIは決断や
  コミットを妨げるためのものではなく、それが**両面を検討した後に**起きるようにするためのもの」。
- **これは"判断"でなく"スキャン"**: 出しながら良し悪しを付けると効果が消える。**地図を作ってから地図を読む**イメージ。
  一度広げた知覚は「もう見なかったことにはできない（cannot unthink）」——これがPMIの効き目。
- **I（Interesting）が固有の価値**: 賛否の判断枠の**外**へ出て、興味・可能性・まだ分類できない点を拾う。
  「嫌いだが、この点は面白い」と言えるのは通常きわめて稀。ここを取りにいくから、単なる賛否リストで終わらない。
- **主観的で、網羅ではない**: 常に「そのPMIをしている人の視点」から。既知の全事実を並べるのでなく、
  P/M/Iのチャンネルを通して**その人に見えた点**を、短時間で広く出す。
- **出自（年号・書名は要確認扱い）**: de Bono（1933–2021、「水平思考」の提唱者）の **CoRT（Cognitive Research Trust）
  思考プログラム**の一部で、**CoRT I「Breadth（広さ）」の第1レッスン**（プログラム最初のツール）。
  CoRTの公表年は **1973年**とされる資料が有力だが異説もある（→出典・要確認）。

## いつ使う / 使わない

**使う（適する状況）**
- 単一のアイデア・提案・施策の**是非を短時間で多面評価**したいとき（採用/見送りの前の一次判断）。
- 自分や集団に**即座の好き嫌い・賛成反対**が生じ、視野が狭まっている恐れがあるとき（PMIが最も効くのは"すでに好悪が
  はっきりしている"場面）。
- 会議で意見が**二分**し、双方に**同じ土俵で全アスペクトを見させたい**とき。
- ブレストや発想法で出た案を**ふるいにかける一次スクリーニング**。
- 低コスト・数分で「open-minded」を強制したいとき（重い分析の前段でも単独でも使える）。

**使わない / よくある誤用（アンチパターン）**
- **賛否の"数"で決める**——最頻の誤り。P/Mを数え多い方を採るのは誤り。**重みが違う**（巨大な1つのマイナスが多数の
  小さなプラスを上回ることがある）。PMIは定性スキャンであって点数集計器ではない。判断は数でなく重みで行う。
- **アイデア生成に使う**——PMIは**既存アイデアの評価**ツール。案を生む段階には向かない（→ brainstorming/scamper）。
- **スキャン中に評価してしまう**——出しながら良し悪しを付けると視野拡大が消え、原理に反する。判断は最後にまとめて。
- **Interesting列を軽視・省略**——単なる賛否リストに退化し、PMI固有の価値（判断枠の外への探索）を失う。ここが最重要。
- **一人・単一視点の偏り**——常に思考者の視点なので1人だと偏る。他者視点（OPV）や複数人、devils-advocateで補う。
- **過剰精緻化**——「側面を大量に足す／延々と再分類する」ことをしない。3分のスキャンを重い分析に膨らませない。
- **多数の選択肢を重み付き基準で比較**する用途には不向き（→ decision-matrix / payoff-matrix）。

## 前提と限界

- **前提**: 評価する**対象（アイデア/提案/選択肢）が1つに定まっている**こと。対象が曖昧だとチャンネルが機能しない。
  複数案を天秤にかけたいなら、各案に別々のPMIをかけるか、比較用の別フレーム（decision-matrix等）へ。
- **限界（誤用の裏返しとして）**:
  - **決めてはくれない**——PMIは情報を3チャンネルに整理するだけ。最終判断（各点の**重み付け**）は思考者が行う。
    出力の最後に「重みづけと総合判定」を必ず自分で置くこと。
  - **主観的・非網羅**——見落としは起こりうる。網羅性が要る局面では CAF（Consider All Factors）的な視点や他者レビューで補う。
  - **Interestingが空回りしやすい**——訓練しないと「良い点/悪い点」に吸収され I が痩せる。「〜だとしたら面白い」「〜を
    見てみたい」という**問いの形**で意図的に引き出す（手順④）。
  - **深掘りには浅い**——短時間の広いスキャンが持ち味。因果分析（fishbone/five-whys）や失敗の先読み（premortem）ほど
    深くはない。深掘りが要る点は別フレームへ渡す。
- これらは、**判断枠の最後に重み付けを置く / Minusを premortem で深める / 主観を devils-advocate・OPV で補う /
  多案比較は decision-matrix へ橋渡しする**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。時間は各対象 **3〜5分**を目安に、速く広くスキャンする。

1. **評価対象を1つ、1文で固定する。** 「〈何を〉すべきか」を明文化する（例: この施策を導入すべきか／この案を採るか）。
   なぜ: 対象が曖昧だとP/M/Iが発散する。PMIは"1対象の多面評価"であって多案比較ではない。
2. **P（Plus）を意図的にスキャンする。** 利点・良い結果・魅力だけに注意を向けて列挙する。**批判せず**出し切る。
   なぜ: 一方向に注意を絞るのがPMIの肝。ここで賛否を戦わせると、次のM/Iへの注意が濁る。
3. **M（Minus）を意図的にスキャンする。** 欠点・危険・悪い結果だけに注意を向けて列挙する。ここも**批判せず**出す。
   なぜ: 好き嫌いが既にある人ほど、反対側（嫌いなら P、好きなら M）が見えなくなる。意図的に反対側へ注意を向ける。
4. **I（Interesting）を意図的にスキャンする。** 良し悪しの**外**にある点を、「〜だとしたら面白い」「〜になるのを
   見てみたい」「これは〜につながるかもしれない」という**問いの形**で引き出す。まだP/Mに分類できない点もここへ。
   なぜ: I は判断枠の外へ思考者を連れ出す、PMI唯一無二の装置。ここを飛ばすと単なる賛否リストになる。
5. **スキャン中は判断を保留する。** 各点に良し悪しの結論を付けない。3チャンネルが出そろうまで評価を我慢する。
   なぜ: 「地図を作ってから読む」。作りながら反応すると地図が歪む。
6. **重み付けして総合判定する。** 数ではなく**各点の重み**で見る。決定打になるP/Mはどれか、Iが判断を変えるかを問う。
   なぜ: 「多い方が勝ち」は誤用。1つの重大なMが多数のPを、あるいは1つのIが結論を、ひっくり返し得る。
7. **次の一手に落とす。** 採用/見送り/条件付き採用/保留（追加調査）を決め、確かめるべき前提や次アクションを1〜3個出す。
   なぜ: PMIは判断の起点。整理で止めず、決定と行動へ接続する。

## 壁打ち質問リスト

各チャンネルを事実で埋め、即断バイアスを外すために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。

1. PMIをかける**対象は具体的に何**ですか？（評価したいアイデア/提案/選択肢を1文で言い切ってください）
2. その案について、**今この瞬間に感じている印象は「賛成寄り」か「反対寄り」か**？（＝どちら側の視点が抜けやすいかを先に把握する）
3. **Plus**: この案が**うまくいったら得られる良いこと・利点**は何ですか？（誰にとって、どんな良さ？）
4. **Minus**: この案の**困る点・リスク・悪い結果**は何ですか？その中で「これが致命的」という**決定打級のマイナス**はありますか？
5. **Interesting**: 良し悪しとは別に、「**〜だとしたら面白い／見てみたい／意外な展開になりそう**」と感じる点は何ですか？
   （この案は何につながり得ますか？　まだ良し悪しを判断できない点は？）
6. 挙がったP/Mのうち、**重みが大きい（結論を左右する）のはどれ**ですか？　数ではなく重要度で選ぶと？
7. この評価は**あなた一人の視点**ですか？　**別の立場の人（顧客/現場/反対者）なら**、P・M・Iはどう変わりそうですか？
8. すでに分かっている事実は何で、まだ**確認できていない前提**はどれですか？（推測と事実を分ける）

## 出力フォーマット

ALWAYS この2段構えで出力する（3チャンネルのスキャン → 重み付け判定）。**P/M/Iを埋めるまで判定を書かない**。

```
【PMIスキャン】対象: <評価する1つのアイデア/提案/選択肢を1文で> ／ 初期印象: <賛成寄り/反対寄り/中立>
  Plus(P 良い点):        - <利点・良い結果> …（批判せず広く）
  Minus(M 悪い点):       - <欠点・リスク・悪い結果> …
  Interesting(I 面白い点): - <良し悪しの外の観察・含意・可能性「〜だとしたら面白い」> …

【重み付けと判定】
  決定打: <結論を左右する重いP/M/Iはどれか（数でなく重み）>
  総合判定: <採用 / 見送り / 条件付き採用 / 保留（追加調査）> — <理由>
  視点の補正: <一人視点の偏り。別の立場ならどう変わるか>

【次の一手】<確かめるべき前提・意思決定・アクションを1〜3個>
【未確認の前提】<事実確認が要る点（壁打ちで埋める）>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。ある企業が「**全社を週4日勤務に移行すべきか**」を検討する場面。

- **手順①対象**: 「自社を週4日勤務へ移行すべきか」を1文で固定。初期印象=現場は"賛成寄り"に傾いている。
- **手順②P（良い点）**: 従業員満足・定着の向上、採用競争力、集中して働く動機、光熱費など固定費の一部削減の可能性。
- **手順③M（悪い点）**: 総稼働時間の減少による生産・対応力の低下懸念、顧客・取引先の営業日とのズレ、
  同じ成果を4日に詰める負荷、部門間で公平に適用できない業務（交代制・窓口）の存在。
- **手順④I（面白い点）**: 「成果を時間でなく**アウトプットで測る**運用に変えたら面白い」「特定部門だけ**試験導入**して
  差を観察したら面白い」「休業日を全社一律にせず**分散**させたらどうなるか見てみたい」——良し悪し未確定だが探る価値。
- **手順⑤判断保留**: ここまで評価を付けず、3チャンネルを出し切る。
- **手順⑥重み付けと判定**: 「顧客の営業日ズレ（M）」と「アウトプット測定への移行（I）」が**決定打**。数の多寡でなく、
  この2点が結論を左右する。→ **条件付き採用**（全社一斉でなく、顧客接点の薄い部門で試験導入し測定基準を先に設計）。
- **手順⑦次の一手**: 試験導入する部門と成功指標（生産性・顧客影響）を決め、一定期間の効果を検証してから全社判断する。
- **未確認の前提**: 顧客側の実際の不便度、部門ごとの業務のばらつき——ここは推測でなく実データで裏取りが要る。

> 補足（歴史的逸話）: de Bonoは学童に「登校したら金銭を与える案」をPMIさせ、最初は全員賛成だったのが、
> M/I（年上の子に取られる・学校が費用を転嫁する等）に気づいて**大多数が意見を変えた**と伝える。
> 即断が視野を狭めることの実演例だが、**具体的な人数・金額は資料で揺れるため数値は断定しない**（→要ファクトチェック）。

## 相性（組み合わせると効く）

- `brainstorming` / `scamper` / `osborn-checklist`: 発想系で案を"生んだ"後、PMIで一次評価する直接の後工程（発散→収束の収束側）。
- `six-hats`: 同じ de Bono のツール。P≈黄帽子・M≈黒帽子に対応し、Iは緑帽子（可能性）に近い。事実（白）や感情（赤）まで含めて多面的に検討したいなら六帽子へ拡張。
- `payoff-matrix` / `decision-matrix`: PMIで各案を一次評価した後、**複数案を効果×実現性や重み付き基準で比較**して絞る後工程。
- `premortem`: Minus列を「この案は失敗した——なぜ？」の視点で深掘りし、リスクの解像度を上げる（Mの深化）。
- `devils-advocate`: PMIの弱点である"一人視点・即断バイアス"に反対役をぶつけ、賛成寄りの偏りを崩す（揺さぶり枠）。
- `reverse-assumption`: 前提を反転させた挑発を Interesting 列の種にすると、判断枠の外の発想が増える（揺さぶり枠）。
