# 4C（マーケティングの4C）

## 概要

4Cは、マーケティング・ミックスを **売り手（企業）視点の4P** から **買い手（顧客）視点** へ翻訳し直し、
施策を顧客起点で組み替えるためのフレームワーク。4つのCは 4P と一対一で対応する。

| 顧客視点（4C） | 意味 | 売り手視点（4P） |
|---|---|---|
| **Customer value（顧客価値）** | 顧客が本当に求める便益・満たしたいニーズ | Product（製品） |
| **Cost（顧客コスト）** | 顧客が支払う**総**負担（価格＋非金銭コスト） | Price（価格） |
| **Convenience（利便性）** | 必要な時・場所で最小の手間で買えるか | Place（流通） |
| **Communication（コミュニケーション）** | 一方通行の販促でなく**双方向の対話** | Promotion（販促） |

- **核となる考え方**: 「何を売りたいか（4P）」ではなく「顧客は何を・どんな負担で・どう買い・どう対話したいか」から発想する。
  4Cは方向づけ（顧客起点の設計思想）、4Pは施策（実装）——両者は表裏で、片方だけでは完結しない。
- **各Cの原義（誤読しやすい点）**:
  - Customer value = 単なる製品スペックでなく、顧客が得る価値・解決される用事。
  - Cost = **価格だけではない**。探索・移動・時間・学習・心理/身体的負担・乗り換え・使用/廃棄まで含む「顧客が支払う総和」。
  - Convenience = **「立地」ではない**。買い手にとっての買いやすさ（いつでも・どこでも・手間なく）。
  - Communication = **push（一方向広告）ではない**。顧客の声を聞き、求める情報を届ける双方向のやり取り。
- **出自（要確認）**: **Robert F. Lauterborn** が **1990年**、業界誌 *Advertising Age* の記事
  「New Marketing Litany: Four Ps Passé; C-Words Take Over」で、McCarthyの4Pへの対案として提示したとされる。
  一部の日本語資料は「1993年提唱」とするが、これは同氏らの書籍『Integrated Marketing Communications』(1993) との
  混同の可能性があり、初出は1990年のAd Age記事が通説（→出典・要確認）。
- **同名異物に注意**: **清水公一**が1970年代に提唱した別の4C（**Commodity/Cost/Channel/Communication**、
  後に7Cs Compass Modelへ拡張）が同じ「4C」の名で流通する。本スキルが扱うのは**Lauterborn版**
  （原語は Consumer wants and needs。本スキルでは Customer value（顧客価値）と表記）。検索・引用時に両者が混在するため区別する（→出典・要確認）。

## いつ使う / 使わない

**使う（適する状況）**
- 4Pで作った施策（製品・価格・流通・販促）を**顧客目線で点検・棚卸し**し、ズレを見つけたいとき。
- 「売り方が顧客に刺さっていない」「買いにくい」「伝わっていない」といった、**売り手都合と買い手実感の乖離**が疑われるとき。
- サービス/サブスク/SaaS/小売/EC/検討期間が長い商材など、**購買体験全体（探索〜購入〜再購入）**が成果を左右する領域。
- 価格競争に陥る前に、**非金銭コスト（手間・時間・心理）**まで含めて価値を組み替えたいとき。
- 製品・サービスの企画/リニューアルで、**顧客中心の設計思想**をチームで共有したいとき。

**使わない / よくある誤用（アンチパターン）**
- **4Pの単なる言い換えで終わる**——最頻の失敗。「Product→顧客価値」とラベルを貼り替えるだけで施策を組み替えない。翻訳は手段、目的は施策の変更。
- **Costを価格だけに矮小化**——非金銭コスト（探索・時間・学習・心理・乗り換え）を落とすと4Cの意味が消える。
- **Communicationをpushに戻す**——「広告をどう打つか」に戻ると双方向対話という肝を外す。
- **Convenienceを「立地」と誤読**——Placeの直訳に戻り、買い手の買いやすさ視点を失う。
- **ターゲット未設定で分析**——「誰にとっての価値/コスト/利便性か」が無いと空論化。先にSTP/ペルソナで顧客を1つに定める。
- **4Cだけで完結させる**——実装（製品仕様・課金・流通・販促）は4P側の設計が要る。4Cは方向づけ、4Pは施策。
- 事業ポートフォリオ選別・業界構造分析・マクロ環境分析には不向き（PPM/5フォース/PESTの領域）。

## 前提と限界

- **前提**: **ターゲット顧客が1つに定まっている**こと（「誰の4Cか」）。曖昧なら先にSTP/ペルソナで固定する。
  4要素は独立でなく相互に整合が要る（高利便性を謳うなら相応のCost/価格設計が要る、等）。
- **限界（批判を踏まえて）**:
  - **4Pの強調点を変えただけ、という批判**——顧客視点への"言い換え"に留まると新情報を生まない。施策の組み替えまで行って初めて価値が出る。
  - **供給側の制約を軽視しがち**——顧客視点に寄せるあまり、コスト構造・オペレーション・実現可能性が抜ける。必ず4Pへ戻して実装可能性を検算する。
  - **顧客の声の鵜呑み**——Communication（傾聴）を「顧客の要望をそのまま実装」と誤ると、表層ニーズに引きずられる。裏の用事（JTBD）で深掘りする。
  - **静的・網羅的でない**——市場・競合・自社の環境分析は3C、購買行動の時系列はカスタマージャーニーが担う。4Cは施策設計のレンズであり環境分析ではない。
- これらは、**4Pへ橋渡しして実装可能性を検算する / STP・ペルソナで対象を定める / JTBD・VPCで価値を深掘る / カスタマージャーニーで利便性と対話を段階分解する**
  ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。

1. **対象（誰の4Cか）を1つに固定する。** ターゲット顧客/セグメント/ペルソナを明文化する。
   なぜ: 「誰にとっての」価値・コスト・利便性かが定まらないと、4要素すべてが空論化する。
2. **Customer value（顧客価値）を言語化する。** 顧客が本当に得たい便益・満たしたい用事を、機能・情緒・自己表現の面から書く。
   なぜ: 自社が売りたい機能ではなく、顧客が価値と感じるものが起点。ここがずれると残り3Cもずれる。
3. **Cost（顧客コスト）を総和で洗い出す。** 価格に加え、探索・比較・移動・時間・学習・心理/身体的負担・乗り換え・使用/廃棄コストを列挙する。
   なぜ: 顧客の意思決定は価格だけで決まらない。非金銭コストを見落とすと「安いのに売れない/高いのに売れる」を説明できない。
4. **Convenience（利便性）を購買段階で評価する。** 認知→検討→購入→受取→再購入の各段で「買いやすさ・手間」を点検する。
   なぜ: Convenienceは「立地」ではなく購買体験全体。どの段でつまずくかを段階で見ると打ち手が具体化する。
5. **Communication（双方向対話）を設計する。** 顧客の声を聞く経路と、顧客が求める情報を届ける経路の両方を書く。
   なぜ: 一方通行の販促でなく、傾聴と提供の往復が信頼と再購入を生む。pushだけに戻さない。
6. **4要素の一貫性を検算する。** 価値・コスト・利便性・対話が互いに矛盾しないかを確認する（例: 高価値×低コスト×高利便を同時に無理なく成立させられるか）。
   なぜ: 4Cは連動する。一つを動かすと他が崩れる。整合していない4Cは実装で破綻する。
7. **4P（売り手視点の施策）へ橋渡しする。** 各Cを対応する4Pの施策に翻訳し戻す（顧客価値→製品仕様、Cost→価格/課金、Convenience→流通/UX、Communication→販促設計）。
   なぜ: 4Cは方向づけ。実装は4P側で行う。ここで供給・コスト・実現可能性の制約を検算し、現実の施策に落とす。

## 壁打ち質問リスト

各Cを事実で埋めるために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。

1. この4Cは**誰（どんな顧客・セグメント・ペルソナ）**を対象にしていますか？ その人が抱える満たしたい用事は何ですか？
2. **Customer value**: その顧客が本当に価値と感じるのは何ですか？（機能／情緒／自己表現）自社が「売りたい機能」と、顧客が「欲しい価値」がズレていませんか？
3. **Cost**: 価格以外に、顧客が支払っている負担は何ですか？（探す手間・比較・移動・待ち時間・学習・不安・今の手段からの乗り換え）——非金銭コストで見落としはありませんか？
4. **Convenience**: 認知→検討→購入→受取→再購入のどの段で、顧客は手間や不便を感じていますか？ 一番つまずいている段はどこですか？
5. **Communication**: 顧客の声を**聞く**経路はありますか？ 販促が一方通行（push）になっていませんか？ 顧客が本当に欲しい情報を届けられていますか？
6. 現状の4P施策（製品・価格・流通・販促）のうち、**顧客視点に立つと最も違和感がある**のはどれですか？ なぜですか？
7. 4つのC同士で**矛盾・トレードオフ**はありますか？（例: 利便性を上げるとコストが上がる、価値を高めると価格が上がる）どこで折り合いをつけますか？
8. すでにある顧客データ・声は何で、まだ**推測で埋めている前提**はどこですか？（事実と仮説を分ける）

## 出力フォーマット

ALWAYS この2段構えで出力する（顧客視点の棚卸し→4Pへの施策変換）。型を固定し、常にこの形で返す。

```
【4C（顧客視点の棚卸し）】対象顧客: <誰の4Cか＝セグメント/ペルソナ>
  Customer value（顧客価値）:   - <顧客が求める便益・用事＋根拠/顧客の声>
  Cost（顧客コスト）:           - <価格＋非金銭コスト（時間/手間/心理/乗り換え）>
  Convenience（利便性）:        - <認知〜再購入の各段の買いやすさ/つまずき>
  Communication（双方向対話）:  - <聞く経路＋届ける経路（pushに偏っていないか）>

【一貫性チェック】<4C間の矛盾・トレードオフと、その折り合わせ方>

【4Pへの橋渡し（施策化）】
  Product   ← Customer value: <製品/サービス仕様への反映>
  Price     ← Cost:           <価格/課金/総コスト低減の打ち手>
  Place     ← Convenience:    <流通/購買動線/UXの打ち手>
  Promotion ← Communication:  <双方向コミュニケーション設計>

【次の一手】<検証すべき仮説・意思決定・アクションを1〜3個>
【未確認の前提】<顧客データで裏取りが要る点（壁打ちで埋める）>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。地域の学習塾が、4Pで作った施策が振るわず顧客視点で見直す場面。

- **手順①対象**: 「近隣に住む共働き家庭の小学生保護者」を対象に固定。満たしたい用事＝「子の学力と、送迎/管理の負担軽減」。
- **手順②Customer value**: 保護者が本当に求めるのは「合格実績」だけでなく「安心して任せられる・手間が減る」こと（情緒/自己表現の価値も含む）。
- **手順③Cost（総コスト）**: 授業料（金銭）に加え、送迎の時間・入退室の不安・教材選びの手間・他塾との比較検討の労力（非金銭コスト）。
- **手順④Convenience**: 認知（存在を知る）→検討（比較）→入会（手続き）→通塾（送迎/連絡）→継続、のうち「送迎」と「日々の様子把握」で手間が大きい。
- **手順⑤Communication**: これまで折込チラシ中心（push一方向）。保護者の声を聞く経路や、学習状況を届ける双方向の仕組みが弱い。
- **手順⑥一貫性チェック**: 「安心という価値」と「送迎/把握の手間コスト」が噛み合っていない——利便性改善が価値に直結する。
- **手順⑦4Pへ橋渡し**:
  - Product←価値: 学力指導に加え、入退室通知や学習報告など「安心・手間軽減」を商品価値に組み込む。
  - Price←Cost: 授業料の見せ方だけでなく、送迎/管理の負担軽減で総コストを下げる。
  - Place←Convenience: オンライン併用や連絡アプリで通塾・把握の手間を減らす。
  - Promotion←Communication: チラシ一辺倒をやめ、保護者面談や連絡アプリで双方向の対話に変える。
- **次の一手**: 「学習報告＋入退室通知」を小さく試し、継続率と紹介の変化という仮説を検証する。
- **未確認の前提**: 保護者が最も負担に感じている点はどれか——アンケート/面談で裏取りが要る（推測のまま進めない）。

## 相性（組み合わせると効く）

- `4p`: 売り手視点の施策設計。4C（顧客視点の方向づけ）と表裏一体で、手順⑦の橋渡し先。両者を往復させて使う。
- `stp`: 「誰の4Cか」を定める前工程。セグメント/ターゲット/ポジションが決まって初めて4Cが具体化する。
- `persona`: 対象顧客を一人の人物像に具体化し、Customer value/Cost/Convenience の解像度を上げる。
- `customer-journey`: Convenience と Communication を購買段階（認知〜再購入）で時系列分解し、つまずき所を特定する。
- `jtbd`: Customer value の裏にある「顧客が片付けたい用事」を深掘りし、表層ニーズの鵜呑みを防ぐ。
- `value-proposition-canvas`: 顧客の課題・利得と提供価値の対応を精緻化し、Customer value を検証する。
- 揺さぶり枠として `devils-advocate`（「その価値は自社の思い込みでは？」と顧客不在を疑う）や `reverse-assumption`（4Pの常識を反転して発想を広げる）を添えると、言い換えで終わる誤用を防げる。
