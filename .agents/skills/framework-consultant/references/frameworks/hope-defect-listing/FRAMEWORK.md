# 希望点列挙法／欠点列挙法

## 概要

希望点列挙法と欠点列挙法は、対象（既存の商品・サービス・業務・アイデア）について思いつくことを
**まず自由に列挙し、その中から主要なものを選び、実現策・改善策へ変換する**、姉妹関係にある発散型のアイデア発想法。
起点の符号が逆なだけで、骨格（列挙→選別→変換）は共通する。

| 手法 | 起点（列挙するもの） | 得やすい成果 | 性格 |
|---|---|---|---|
| **希望点列挙法** | 「あったらいいな」「もっとこうだったら」＝**理想・希望** | 革新的・飛躍的なアイデア | ポジティブ・未来起点 |
| **欠点列挙法** | 「不満」「不便」「使いにくい」＝**"不"のつく欠点** | 堅実・現実的な改善案 | 現実・足元起点 |

- **核となる考え方**: 発想を「列挙（発散）」と「変換（実現/改善策づくり）」の2段に**分離**する。
  列挙段では常識・実現可能性を一旦棚上げして量を出し、変換段で初めて具体化・実現性を検討する。
  希望点は現状を切り捨てて飛ぶための燃料、欠点は"不"を起点に足元を掘るための燃料。**両輪で回すと補完し合う**。
- **出自（諸説あり・要確認）**: 日本語の解説では「**GEの子会社ホットポイント社(Hotpoint)が考案**」と紹介されることが多いが、
  この帰属を裏付ける一次資料は確認できていない（二次情報で反復されている通説）。
  **英語圏の創造技法文献（Crawford 1954／VanGundy 1988 ほか、→出典の一次資料）を追検証したが、Hotpoint社への考案帰属を記した記述は確認できなかった**——
  現状この帰属は日本語二次情報のみに存在する通説であり、鵜呑みにせず「諸説あり」として扱う。系譜としては
  **属性列挙法（Attribute Listing, Robert P. Crawford／原典は1954年刊、技法自体は1930年代の講義に遡るとされる）**の変種・親戚に位置づけられることが多く、
  西洋にも類似の「Wishful Thinking（願望思考／VanGundy 1988）」「Bug listing」がある。**起源・年号は断定せず要確認として扱う**（→出典・要ファクトチェック）。

## いつ使う / 使わない

**使う（適する状況）**
- **既存の商品・サービス・業務がある**改善/リニューアル/新機能着想。「叩き台」があるほど列挙が回る。
- 顧客・現場の**不満や要望の声が拾える**とき（欠点列挙＝不満の構造化、希望点列挙＝要望の理想化）。
- **ブレストのテーマはあるが切り口が見つからない**とき。「希望点は？」「欠点は？」という問いが強制的に視点を作る。
- 発想が行き詰まり、**現状の延長でない視点**が欲しいとき（希望点列挙で常識を外す）。
- 属性列挙法・SCAMPER・オズボーンのチェックリストと**並べて発散の量を稼ぎたい**とき。

**使わない / よくある誤用（アンチパターン）**
- **列挙で止まり、実現策・改善策（変換段）に繋げない**——最頻の失敗。ただの「不満大会」「願望大会」で終わる。
  列挙は手段。必ず主要点を選び、打ち手へ変換して初めて成果になる。
- **テーマが漠然**——「良い商品にしたい」では希望/欠点が発散して収集がつかない。対象・観点を1つに絞る（手順①が要）。
- **列挙段で批判が出る**——「それは無理」と否定した瞬間に量が縮む。判断保留（ブレストの原則）を徹底する。
- **欠点列挙が人・部門の非難合戦になる**——攻めるのは「対象・仕組み」であって人ではない。ここを外すと心理的安全性が壊れる。
- **欠点列挙が対症療法に終始**——「その作業・機能はそもそも必要か（＝根本から無くせないか）」まで踏み込まないと小手先で終わる。
- **希望点を実現可能性で早すぎる段階に潰す／逆に非現実な願望だけ並べて放置**——飛ばすのは列挙段だけ。変換段で実現の芯を抜き出す。
- ゼロから概念を立ち上げる完全な新規着想や、精緻な定量評価・因果分析そのものには不向き（列挙は発散であり、選別・検証・分析は別技法で補う）。

## 前提と限界

- **前提**: 列挙の的になる**対象**（既存の物・事、または明確なテーマ）が要る。無ければ属性列挙法やジョブ理論で対象を立ててから使う。
  外部から不満/要望を集めるなら、顧客ヒアリング・アンケート・利用シーン観察などの入力があると質が上がる。
- **限界（批判を踏まえて）**:
  - **欠点列挙は視野が狭く・後ろ向きになりがち**——目の前の不満に引きずられ、対症療法・短期最適に寄る。全体最適や長期の視点が抜けやすい。
  - **希望点列挙は実現可能性の壁**——革新的な案が出る反面、実行が伴わないと「言うだけ」で信頼を失う。多様な希望が互いに**対立**することもある（誰の希望を優先するか）。
  - **精緻な優先順位づけの基準は内蔵しない**——手順⑤に「効果×着手容易さ」の2軸で足切りする簡易選別は内蔵するが、複数案の厳密な比較・重みづけ・合意形成の仕組みは持たない。そこは PMI・ペイオフマトリクス等で補う。
  - **量は出るが質は保証しない**——参加者の顔ぶれに強く依存する。同質メンバーだと似た希望/欠点しか出ない。
- これらは、**選別・評価を別技法で補う（PMI・payoff-matrix）／根本に踏み込む問いを足す（five-whys・reverse-assumption）／視点の多様性を確保する（性格・専門の異なる人を混ぜる）**
  ことで補える（→相性・進め方）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。希望点／欠点で共通の骨格に、符号ごとの差分を付す。

1. **対象とテーマを1つに固定する。** 「何について」「どの観点で」希望/欠点を出すかを明文化する（例: この製品の"使い勝手"／この業務の"手戻り"）。
   なぜ: 漠然テーマは発散して収集がつかない最頻の失敗に直結する。観点を絞ると列挙の密度が上がる。
2. **どちらの符号で回すかを決める（または両方）。** 足元を堅実に直したいなら**欠点列挙**、現状を飛び越えたいなら**希望点列挙**。
   迷えば「欠点で足場を固め→希望点で飛ばす」の二段を推奨。
   なぜ: 起点の符号が成果の性格（現実的改善／革新）を決める。目的に合わせて選ぶ。
3. **メンバーと場を整える。** 5〜6人程度、**性格・専門の異なる人**を混ぜる。テーマによっては専門家と"全くの専門外"を意図的に同席させる。
   列挙段は**批判禁止・質より量・便乗歓迎**（ブレストの4原則）を宣言する。
   なぜ: 同質だと同じ希望/欠点しか出ない。異質さが視点を増やし、批判の抑制が量を守る。
4. **列挙する（発散）。** 対象を触り・使い・眺めながら、希望点（「〜だったらいいな」）または欠点（「〜が不便/不満」）を**手を止めず量産**する。
   顧客の声・アンケート・利用シーンからも吸い上げる。実現可能性はここでは問わない。
   なぜ: 実現性を考えた瞬間に量が止まる。発散と評価を混ぜないのが列挙法の肝。
   - 欠点列挙のコツ: **"不"（不便・不満・不足・不安・不明）**を頭に付けて機械的に洗う。人でなく対象・仕組みを攻める。
   - 希望点列挙のコツ: 「予算・技術・常識が無いなら？」と制約を外して理想像を描く。
5. **主要なものを選ぶ（収束の入口）。** 出た項目から、**影響が大きい／頻度が高い／本質的**なものを数個に絞る。
   本手法単体で選別まで回すなら、各項目を「**効果の大きさ（大／小）× 着手の容易さ（易／難）**」の2軸で4象限に落とす簡易スコアを内蔵の物差しに使う——
   **効果大×着手易＝最優先（即やる）／効果大×着手難＝本命だが仕込みが要る（変換段⑥で重点的に攻める）／効果小×着手易＝すきま時間の埋め草／効果小×着手難＝いったん捨てる**。
   まず各象限に振り分け、右上（効果大×着手易）と本命（効果大×着手難）から数個を採る。厳密な多案比較や合意形成が要るときだけ、この2軸の結果をPMI・ペイオフマトリクスへ渡して精緻化する。
   なぜ: 全項目を等価に扱うと変換段が薄まる。効くものに資源を集中する。内蔵の2軸で先に足切りしておけば、外部技法を呼ばずとも列挙法単体で選別まで完結する。
6. **変換する（実現策・改善策づくり）。** 選んだ希望点は「どうすれば実現できるか」、欠点は「どう直すか」を具体化する。
   欠点は「そもそもこの作業・機能は要るか（根本から無くせないか）」まで問い、対症療法で止めない。
   なぜ: ここが列挙法を"成果"にする核。列挙だけでは何も動かない。
   - 運用のコツ: 列挙段と変換段は**時間を分ける**とよい（例: 希望点を出した翌日に、それを種に改善ブレストを別途実施）。頭の熱を冷ますと現実的な芯が見える。
7. **次の一手に落とす。** 変換で出た案から、試作・検証・意思決定すべき候補を1〜3個決める。
   なぜ: 発想はゴールでなく起点。ここで止めると「作って終わり」になる。

## 壁打ち質問リスト

各段を埋めるために利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。

1. 今回の**対象は何**ですか？（どの商品／サービス／業務／既存アイデア）そして**どの観点**（使い勝手／コスト／速さ／体験など）で見ますか？
2. 目的は**堅実に直す**ことですか、それとも**現状を飛び越える**ことですか？（→欠点列挙／希望点列挙／両方のどれで回すか）
3. **欠点**として、あなた自身や顧客・現場が「不便・不満・不足・不安」と感じている点は具体的に何ですか？（"不"で洗い出す）
4. その中で、**影響が大きい・頻度が高い・本質的**な欠点はどれですか？逆に、些末で後回しにしてよいものはどれですか？
5. 予算・技術・常識の制約が**一切無いとしたら**、この対象は「本当はどうあってほしい」ですか？（希望点＝理想像）
6. その希望が実現したら、**誰が・どんな場面で**一番うれしいですか？（希望の受益者と利用シーンを具体化）
7. 挙がった希望点／欠点のうち、**すでに部分的に手を打っている**ものと、**まったく未着手**のものはどれですか？
8. 列挙した不満/理想は、**あなたの推測**ですか、それとも**顧客の声・データ**で裏が取れていますか？（推測と事実を分ける）

## 出力フォーマット

ALWAYS この3段構え（列挙→選別→変換）で出力する。希望点・欠点のどちらか、または両方を回した結果を型に流し込む。

```
【設定】対象: <何を> ／ 観点: <どの切り口> ／ モード: 希望点 / 欠点 / 両方

■ 列挙（発散・批判なし）
  希望点: - <「〜だったらいいな」> …（思いつく限り／後で選別）
  欠点:   - <「〜が不便・不満」（"不"起点）> …

■ 選別（主要点）
  - <影響大・高頻度・本質的なものを数個。なぜ選んだか一言>

■ 変換（実現策・改善策）
  希望点→実現策: <選んだ理想 → どう実現するか（実現の芯を抜き出す）>
  欠点→改善策:   <選んだ欠点 → どう直すか（対症療法で止めず「そもそも要るか」まで）>

【次の一手】<試作・検証・意思決定すべき候補を1〜3個>
【未確認の前提】<推測で埋めた箇所・顧客の声/データで裏取りが要る点>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。地域の書店が来店客数の伸び悩みに向き合う場面。

- **手順①対象・観点**: 対象＝自店の店舗体験、観点＝「また来たくなるか（再来店）」。
- **手順②モード**: まず欠点列挙で足元を固め、次に希望点列挙で飛ばす二段構え。
- **手順③場**: 店長・アルバイト・常連の視点を混ぜ、列挙段は批判禁止を宣言。
- **手順④列挙（発散）**:
  - 欠点（"不"起点）: 目当ての棚が"不"明瞭で探しにくい、滞在中に座る場所が"不"足、レジ待ちが"不"快、新刊の入荷が"不"透明。
  - 希望点（理想）: 気になる本をその場で試し読みしながら過ごせたら、店員の"推し"がすぐ分かったら、来るたび新しい発見があったら。
- **手順⑤選別**: 影響が大きい「棚が探しにくい（欠点）」と「滞在して過ごせる場（希望点）」を主要点に据える。
- **手順⑥変換**:
  - 欠点→改善策: 探しにくさは「そもそも既存の分類が客の探し方と合っているか」に遡り、テーマ棚やスタッフの手書き案内へ組み替える（対症療法で終えない）。
  - 希望点→実現策: 「滞在して過ごせる」の芯は"居場所"。大規模改装でなく、既存什器の一部を試し読み用の一角に転用して小さく試す。
- **手順⑦次の一手**: 「テーマ棚」と「試し読みの一角」を数週間だけ試し、再来店・滞在時間の変化という仮説を検証する。
- **未確認の前提**: 客が本当に"居場所"を求めているか、探しにくさが来店減の主因か——ここは客の声・行動データで裏取りが要る（推測のまま拡大しない）。

## 相性（組み合わせると効く）

- `attribute-listing`: 対象を属性（名詞/形容詞/動詞的）に分解してから各属性の欠点/希望点を問うと、列挙の網羅性が跳ね上がる。列挙系の親戚で前工程に最適。
- `osborn-checklist` / `scamper`: 選んだ欠点/希望点を「転用・応用・変更・拡大・削除…」の問いで具体策へ展開する変換段のドライバ。
- `brainstorming` / `brainwriting-635`: 列挙段（発散）の場の運用そのもの。沈黙で量を稼ぐなら635法、声で膨らますならブレスト。
- `kj-method`: 大量に出た希望点/欠点を親和性でグルーピングし、主要点の選別（手順⑤）を助ける。
- `jtbd`: 希望点を「顧客が片付けたい未充足のジョブ」として捉え直すと、願望が事業機会に化ける。
- `pmi` / `payoff-matrix`: 手順⑤の内蔵2軸（効果×着手容易さ）を超えた厳密な選別・優先順位づけ（本手法が持たない精緻な多案比較）を補う。効果×実現性で絞る。
- `five-whys`: 欠点を「なぜ起きるか」で掘り、対症療法から真因対策へ引き上げる。
- 揺さぶり枠として `reverse-assumption`（欠点を裏返して常識を反転）や `devils-advocate`（希望点の実現性を疑う）を添えると、列挙の質が締まる。
