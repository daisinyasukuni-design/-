# ジョブ理論（Jobs To Be Done）

## 概要

ジョブ理論は、「顧客は製品・サービスを**買う**のではなく、ある状況で成し遂げたい**進歩（progress）**のために
それを**"雇う（hire）"**」という見方で需要を捉え直すフレームワーク。中心の問いはただ1つ——
**「この顧客は、どんな状況で、何を片付けるために、これを雇ったのか？」**

- **ジョブの定義**: 「特定の**状況(circumstance)**において、顧客が成し遂げようとする**進歩**」。
  進歩＝問題の解決や状況の改善、状況＝それが生じる文脈（いつ・どこで・誰と・何の途中で）。
- **視点の転換（核）**: 顧客の**属性（年齢・性別・企業規模）ではなく、片付けたいジョブ**で市場を切る。
  有名な比喩——「顧客はドリルが欲しいのではなく“壁の穴”が欲しい」。解決策ではなくジョブを見る。
- **ジョブの3次元**: **機能的(functional)**（実務的タスク）/ **感情的(emotional)**（自分がどう感じたいか）/
  **社会的(social)**（他者からどう見られたいか）。機能だけ見ると深い動機を取りこぼす。
- **真の競合が変わる**: 競合は同カテゴリの製品とは限らない。同じジョブを片付ける**あらゆる代替**
  （他業種の製品、自前の工夫、“何もしない”）が競合になる。
- **出自（諸説・論争あり）**: 単一起源ではなく2系統が併存する。
  (a) **Tony Ulwick**（Strategyn）が着想し、後に **Outcome-Driven Innovation (ODI)** として体系化——
      ジョブを機能的タスクに分解し**測定可能な成果指標**で捉える定量・プロセス志向。
  (b) **Clayton Christensen** が一般に普及（『The Innovator's Solution』2003、HBR 2016、
      『Competing Against Luck』2016）。**Bob Moesta** らが需要側で**Switch インタビュー**と
      **4つの力**を展開——**進歩と“雇う/解雇する”意思決定の物語**を重視する質的志向。
  この「同名で別物」の2解釈が実務の混乱源。本スキルは両系統を併記して使い分ける（→出典・要確認参照）。

## いつ使う / 使わない

**使う（適する状況）**
- 新規事業・新製品の**機会発見**。「誰に何を売るか」の前に「どんなジョブが未充足か」を探したいとき。
- 製品が**刺さらない/売れない/差別化できない**とき。機能追加でなく、雇われる理由を問い直す。
- **解約・乗り換え・非購入**の理由を知りたいとき（なぜ旧手段を"解雇"し、何を"採用"したのか）。
- **真の競合**を捉え直したいとき（同カテゴリ外の代替・自前対処・無行動まで含めて）。
- ペルソナや属性データが**打ち手に繋がらない**とき。属性の相関でなく因果（動機）へ掘り下げる。
- 価値提案(VPC)やコンセプトの**上流の切り口**が欲しいとき。

**使わない / よくある誤用（アンチパターン）**
- **抽象化しすぎて実装に落ちない**——ジョブが哲学的・高レベルになり、機能要件や優先順位に変換できない。
  最頻の失敗。必ず「望ましい成果」や具体的な打ち手まで降ろす。
- **既存機能からの逆算(retrofit)**——手持ち機能を正当化するジョブを後付けする。発見したジョブが
  現行機能と綺麗に一致したら要警戒（発見でなく追認になっている）。
- **ジョブと解決策の混同**——「動画を見る」は解決策、ジョブは「移動時間を退屈せず過ごす」。
  自社製品を唯一解と決めつけると代替競合が見えなくなる。
- **機能ジョブへの偏り**——感情的・社会的ジョブを取りこぼし、なぜ選ばれるかの核心を外す。
- **属性でのセグメントに逆戻り**——「30代女性は…」に戻ると、ジョブ理論の意味が消える。
- **少数インタビューを統計代表と誤認**——JTBDは質的手法。規模の検証は別途データで行う。
- 需要が自明で実装・最適化フェーズ、純粋なUI微調整、統計的代表性が必須の場面には不向き。他フレームで補完。

## 前提と限界

- **前提**: 実在の顧客（特に**最近スイッチした人／非利用者**）の“状況と動機”に接触できること。
  ジョブは机上でなく、顧客の実際の文脈から抽出する。接触できないなら、まず壁打ちで仮説を明示し
  検証対象として扱う（仮説を事実と混同しない）。
- **限界（批判を踏まえて）**:
  - **抽象度の罠**——ジョブは高レベルに書けてしまうため、そのままでは開発判断に使えない。
    Ulwick系の「望ましい成果（測定可能な指標）」へ降ろすと実装に繋がる。
  - **2解釈の混在**——「ジョブ＝進歩の物語」(Christensen–Moesta) と「ジョブ＝機能タスク＋成果指標」(ODI/Ulwick)
    は別物。どちらを使っているかを宣言しないと議論が噛み合わない。
  - **確証バイアス**——インタビュー設計や解釈で、見たい結論に寄せやすい。旧手段を解雇した瞬間の
    事実（いつ・何が引き金）を時系列で押さえ、解釈と事実を分ける。
  - **定量の欠如**——ジョブの“大きさ・頻度・市場規模”はJTBD単体では測れない。定量調査で裏取りする。
- これらは、**成果指標へ降ろす（ODIのジョブマップ）／VPCで価値提案に具体化する／
  定量調査・SWOT・3Cで市場側を裏取りする**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。需要側（進歩/物語）を主軸に、必要に応じてODIで成果へ降ろす。

1. **対象と検討目的を1つに固定する。** 「機会発見か／既存製品の非購入・解約理解か／競合再定義か」を明確化する。
   なぜ: 目的が曖昧だとジョブが発散し、抽象論で終わる（最頻の失敗）。
2. **状況（circumstance）を特定する。** 顧客が“片付けたい何か”に直面する具体的な場面（いつ・どこで・何の途中で）を描く。
   なぜ: ジョブは状況とセットで初めて意味を持つ。状況を欠くと一般論になる。
3. **ジョブを解決策から切り離して言語化する。** 「〜したい」を製品名抜きの動詞で書く（例:「移動時間を有意義に使いたい」）。
   なぜ: 解決策で書くと代替競合が見えず、既存機能の追認に堕ちる。ジョブ＝解決策手段から独立させる。
4. **3次元でジョブを厚くする。** 機能的（何を成し遂げる）／感情的（どう感じたい）／社会的（どう見られたい）を並べる。
   なぜ: 機能だけでは“なぜ選ぶか”の核心（不安・見栄・安心）を外す。
5. **「雇用と解雇」を再構成する。** 何を雇い、何を解雇したか。旧手段を捨てた**引き金の瞬間**を時系列で押さえる。
   なぜ: 購入は“乗り換え”の物語。引き金を掴むと訴求点と競合が同時に見える（Switch インタビューの核）。
6. **4つの力で綱引きを分析する。** 乗り換えは **Push（現状の不満）＋ Pull（新手段の魅力）＞ Anxiety（新しさへの不安）＋ Habit（既存習慣の慣性）** で起きる。各力を洗い出す。
   なぜ: 多くの打ち手は Pull（魅力訴求）に偏る。実際に契約を殺すのは Anxiety と Habit。ここを設計で潰す。
7. **真の競合を“同じジョブを片付ける全代替”で捉え直す。** 他業種・自前の工夫・“何もしない”まで列挙する。
   なぜ: 競合をカテゴリ内に限ると、非消費（何もしない層）という最大の機会を見落とす。
8. **（必要なら）成果へ降ろす。** ジョブを ODI 流の**望ましい成果**（「最小化/最大化＋指標＋文脈」）に分解し、
   未充足（重要度高×満足度低）を特定する。なぜ: 抽象なジョブを開発判断・優先順位に使える形にするため。
9. **打ち手と検証仮説に落とす。** 未充足ジョブ／潰すべき Anxiety・Habit から、コンセプト案と検証すべき仮説を1〜3個決める。
   なぜ: JTBDは起点であってゴールではない。ここで止めると“面白い洞察止まり”になる。

## 壁打ち質問リスト

各要素を顧客の事実で埋めるために、利用者へ投げ返す問い。空欄を勝手に埋めず、まずこれで引き出す。

1. この検討で**最終的に決めたいこと**は何ですか？（新機会の発見／非購入・解約の理解／競合の再定義など、目的を1つに）
2. 顧客が“**片付けたい何か**”に直面するのは、具体的に**どんな状況**（いつ・どこで・何の途中）ですか？
3. その状況で顧客が成し遂げたい**進歩**を、**製品名を使わず**に言うと何ですか？（機能面）そして、その裏で
   顧客が**どう感じたい／どう見られたい**のですか？（感情面・社会面）
4. 直近でこれを採用した人は、それまで**何を使っていて（＝何を"解雇"したか）**、
   **どの瞬間に「変えよう」と思った**のですか？（引き金・きっかけ）
5. 乗り換えを**後押しした力**（現状の不満・新手段の魅力）と、**引き止めた力**（不安・既存習慣の慣性）は
   それぞれ何ですか？（4つの力）
6. 同じジョブを、顧客は**他にどんな手段**で片付けられますか？（別カテゴリの製品／自前の工夫／“何もしない”を含む）
7. そのジョブが**満たされていない度合い**（重要なのに不満が大きい点）はどこですか？根拠となる顧客の声は？
8. いま手元にある**事実**（顧客の実際の発言・行動）と、まだ**仮説にすぎない前提**はどれとどれですか？

## 出力フォーマット

ALWAYS この2段構えで出力する（ジョブの解像度 → 機会と打ち手）。需要側を主軸に、必要時のみ成果分解を足す。

```
【ジョブの解像度】目的: <この検討で決めたいこと> ／ 対象顧客・状況: <いつ・どこで・何の途中で>
  中核ジョブ（解決策抜きの動詞で）: <「〜したい」＝目指す進歩>
  ├ 機能的: <成し遂げたい実務的タスク>
  ├ 感情的: <どう感じたいか（安心・自尊など）>
  └ 社会的: <他者からどう見られたいか>
  ジョブ・ストーリー: When <状況>, I want to <動機>, so I can <期待する成果>。
  雇用/解雇: 採用したもの=<…> ／ 解雇したもの=<旧手段> ／ 引き金=<変えようと思った瞬間>

【4つの力（乗り換えの綱引き）】
  Push（現状の不満）:   <…>
  Pull（新手段の魅力）: <…>
  Anxiety（採用の不安）: <…>   ← 設計で潰す対象
  Habit（既存の慣性）:   <…>   ← 設計で潰す対象

【真の競合】<同じジョブを片付ける全代替：別カテゴリ／自前の工夫／“何もしない”>
【未充足ジョブ】<重要なのに満たされていない点（＝機会）>
【次の一手】<コンセプト案・訴求・検証すべき仮説を1〜3個。Anxiety/Habit の潰し方を含む>
【未確認の前提】<顧客の事実で裏取りが要る点（壁打ちで埋める）>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。**社会人向けオンライン学習サービス**が、
無料登録は多いのに継続しない、という相談を受けた場面。

- **手順①目的**: 「なぜ続かないか」を非継続者のジョブから理解し、継続の打ち手を出す。
- **手順②状況**: 平日の通勤中や就業後の疲れた夜、キャリアの停滞に漠然とした不安を感じた瞬間に登録している。
- **手順③ジョブ（解決策抜き）**: 「動画を見る」ではなく「**先が見えないキャリアに、前進している感覚を取り戻したい**」。
- **手順④3次元**: 機能的＝新スキルの習得、感情的＝取り残される不安の解消・自己効力感、社会的＝
  同僚や市場に対し“学んでいる人”と見られたい。
- **手順⑤雇用/解雇**: 書籍やSNSの情報収集を“解雇”して登録。引き金＝昇進を逃した／後輩の活躍を見た等の一撃。
- **手順⑥4つの力**:
  - Push: 停滞への焦り、独学の非効率。
  - Pull: 体系化された講座、修了証。
  - Anxiety: 「続けられるか」「本当に身につくか」「時間を取れるか」。
  - Habit: 疲れた夜はつい動画・SNSに流れる既存の習慣。
- **手順⑦真の競合**: 他社講座だけでなく、書籍・無料動画・社内勉強会、そして「**何もしない（先延ばし）**」。
- **手順⑧成果へ（任意）**: 望ましい成果の例＝「学習を再開するまでの時間を最小化」「1回あたりの達成実感を最大化」。
- **手順⑨次の一手**: 「継続の Anxiety と Habit を潰す設計」を検証する——例: 極小の初回体験で早期の“前進実感”を作り、
  疲れた夜の既存習慣に割り込むリマインド導線を試す。継続率という仮説を小さく検証する。
- **未確認の前提**: 上記のジョブ・引き金は仮説。実際の非継続者インタビューで、解雇の瞬間と不安の中身を裏取りする
  （推測のまま施策化しない）。

## 相性（組み合わせると効く）

- `value-proposition-canvas`: 抽出したジョブ／ペイン／ゲインを、提供価値（ペインリリーバー・ゲインクリエイター）に
  直接マッピングする最短の続き。ジョブ理論の出力の受け皿。
- `persona`: 属性でなく“ジョブ”で顧客像を締め直す。JTBDはペルソナが打ち手に繋がらない弱点を補う。
- `customer-journey`: 状況・引き金・雇用/解雇の瞬間を時系列に配置し、力が働く接点を可視化する。
- `swot` / `3c`: JTBDが示す未充足ジョブを、自社の強み・市場・競合という供給側の現実で裏取りする（機会の実在性検証）。
- `five-forces`: 「真の競合（代替・非消費含む）」を業界構造として掘り下げ、脅威の広さを補正する。
- `lean-startup-mvp`: ジョブ仮説と Anxiety/Habit の潰し方を、最小構成で実地検証する。
- 揺さぶり枠として `reverse-assumption`（“このジョブは実在する”という前提を反転）や
  `premortem`（この新コンセプトが1年後に失敗したと仮定し、外したジョブ／潰せなかった不安を先回り）を添えると洞察が増す。
