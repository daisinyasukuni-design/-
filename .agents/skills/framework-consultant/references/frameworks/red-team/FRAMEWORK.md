# レッドチーム（Red Teaming）

## 概要

レッドチームは、自社の計画・戦略・意思決定を **独立した「敵・競合・批判者」の視点** から
意図的に攻撃し、当事者には見えない **脆弱性・未検証の前提・失敗シナリオ** を実行前に
炙り出す構造化技法。ねらいは、強い合意や同質な組織に生じる **集団浅慮(groupthink)** と
**認知バイアス**、そして「起こり得たのに誰も想像しなかった」失敗＝**想像力の失敗
(failure of imagination)** を防ぐこと。

- **核となる考え方**: 計画を作った側（ブルーチーム＝守り手）と、それを壊しにいく側
  （レッドチーム＝攻め手）を **分離** し、後者が敵になりきって攻撃する。単なる粗探しでは
  なく「自分が敵ならどうこの計画を潰すか」を一人称で追い込むのが本質。
- **最大の敵はミラーイメージング(mirror-imaging)**: 敵に自分の動機・価値観・思考を投影し、
  「相手も自分と同じように動く」と暗黙に仮定してしまう誤り。これを外すことが価値の源泉。
- **出自（諸説あり・要確認）**: 単一の考案者はいない。しばしば挙げられる系譜は——
  (a) カトリック教会の **悪魔の代弁者(advocatus diaboli)**（列聖審査、16世紀に遡るとされる）、
  (b) プロイセン軍の演習 **クリークスシュピール(Kriegsspiel)**（青＝自軍/青い軍服、赤＝敵、
  が「レッドチーム」の色分けの語源とされる）、(c) RAND研究所の冷戦期シミュレーション
  （赤＝ソ連、青＝米）、(d) イスラエル軍情報部 **Ipcha Mistabra（「その逆が正しい」の意）**
  （ヨム・キプール戦争(1973)の情報失敗後に設置とされる）。**9.11後** に米陸軍UFMCSや
  CIAレッドセルが体系化し、ビジネスへは **Bryce Hoffman『Red Teaming』(2017)** が普及させた。
  **起源・年号・組織名は資料により食い違うため断定を避ける**（→出典・要確認項目参照）。

## いつ使う / 使わない

**使う（適する状況）**
- **高リスク・不可逆・大きな賭け** の意思決定を実行に移す前（市場参入、大型投資、M&A、
  基幹製品の投入、重要提案の役員会付議前など）。壊れて困るものほど、事前に壊しにいく。
- **合意が強すぎる/同質なチーム** で、反対意見が出にくく集団浅慮のリスクが高いとき。
- **実在の競合・敵対者の動き** が結果を左右するとき（「競合ならどう妨害してくるか」を読む）。
- 計画・仮説を **反証で叩いて頑健にしたい**（stress-test）とき。

**使わない / よくある誤用（アンチパターン）**
- **低リスク・可逆な小さな決定に持ち出す**——資源と時間を食う重い技法。オーバースペック。
  戻せる決定は素早く試して学ぶ（→lean-startup-mvp / ooda）方が速い。
- **独立性の欠如＝追認装置化**——最頻の失敗。「自分と似た考えの人」でレッドチームを組むと
  確認バイアスが入り、結論を追認するだけになる。計画を作った本人だけで回すのも同じ罠。
- **人を攻撃する**——対象は常に **計画・前提・論理** であって人ではない。逸脱すると対人攻撃・
  怨恨・不信を生み、組織が壊れる。「攻撃するのは計画、守るのは全員の目的」を明文化する。
- **発見を報告して終わり**——一方向の分厚いレポートを投げるだけで、守り手が反論・修正
  できないと意味がない。必ず **ブルーチームの応答（対策）と計画への統合** までやる。
- **最悪シナリオへの過度な固執**——全部を脅威に見立てると意思決定が麻痺する。影響度×蓋然性で
  重み付けし、致命的な少数に絞る。
- **過信**——レッドチームの成果は説得力があるが、敵の全行動を捕捉できるわけではない。
  「これで安全」という誤った安心(false sense of security)を戒める。
- 事実確認・定量最適化そのものや、既に方針が固まった実行フェーズには不向き。他フレームで補う。

## 前提と限界

- **前提**: (1)攻撃対象＝守るべき計画/意思決定が1つに定まっていること、(2)レッドチームに
  **本物の独立性** と **心理的安全性** が与えられ、経営陣が「反証を歓迎する」姿勢を示すこと、
  (3)攻撃の材料（競合・市場・技術・規制の基礎情報）があること。無ければ壁打ちで補うか、
  5フォース/PESTを先に回して敵の土俵を持ち込む。
- **限界（批判を踏まえて）**:
  - **資源・時間集約的**——英国国防省(MoD)系の記述でも「time-consuming／resource hungry」と
    される。頻度・規模は賭け金に見合わせる。
  - **万能ではない(not a panacea)**——特定時点の評価にすぎず、計画や環境が動けば陳腐化する。
    リスク評価の代替ではなく補完。
  - **標準化が弱い**——組織ごとに手法がばらつき、質が属人的になりやすい。手順とルールを固定して補う。
  - **敵の行動は完全には予測不能**——「自分の上司の判断すら確実には読めない」。出力は
    「起こり得る攻撃の一部」であって全網羅ではない、と前提を明示する。
- これらは **独立性とグラウンドルールの徹底 / 影響度×蓋然性での優先順位付け / ブルーチーム
  応答での計画統合 / プレモータム・悪魔の代弁者との併用** で補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。

1. **攻撃対象とスコープを1つに固定する。** 「何を壊しにいくのか」（例: この新規参入計画／
   この価格戦略／この提案の前提）と、成功の定義・制約を明文化する。
   なぜ: 対象が曖昧だと攻撃が発散し、ただの粗探しに堕ちる。
2. **グラウンドルールを宣言する。** 「攻撃するのは計画・前提であり人ではない」「守り手も含め
   全員の目的は計画を強くすること」「反証は歓迎、報復しない」を先に合意する。
   なぜ: 独立性と心理的安全性がレッドチームの生命線。対人攻撃化と追認装置化を同時に防ぐ。
3. **独立したレッドチームを組む。** 計画立案者から切り離し、**外部/中立の視点** と、**敵側を
   知る視点**（競合・顧客・規制・その領域の経験者）を混ぜる。同質・イエスマンで固めない。
   なぜ: 「自分と似た考え」を選ぶと確認バイアスで結論を追認する。多様性が攻撃の質を決める。
4. **前提を棚卸しして脆さを判定する（キーアサンプション・チェック）。** 計画が暗黙に依存する
   前提を列挙し、各前提に「これが崩れたら計画はどうなるか」「根拠は事実か願望か」を問う。
   なぜ: 失敗の多くは「当然そうなる」と思い込んだ前提から生まれる。ここが攻撃の入口。
5. **敵になりきって攻撃する（ミラーイメージングを外す）。** 採用する視点（例: 最有力競合／
   離反しかけの顧客／規制当局）ごとに一人称で問う——「自分がこの競合なら、この計画を
   どう潰すか」。相手の動機・制約・世界観で考え、自社の常識を投影しない。
   なぜ: 相手が自分と同じに動く前提こそ最大の盲点。視点を替えて初めて見えない攻撃口が出る。
6. **脆弱性を影響度×蓋然性で格付けする。** 出た攻撃・失敗シナリオを、致命度と起こりやすさで
   並べ、上位の「効く」ものに絞る。
   なぜ: 全部を等価に脅威扱いすると麻痺する。致命的な少数に資源を集中させる。
7. **ブルーチームが応答し、計画に統合する。** 守り手が各脆弱性へ対策（回避・緩和・監視・
   受容）を返し、計画を改訂する。報告で終わらせない。
   なぜ: レッドチームはゴールでなく起点。統合しなければ「作って終わり」の典型に陥る。
8. **最も危険な前提を先に検証する次の一手を決める。** 崩れたら致命的な前提を1〜3個選び、
   小さく試す実験や情報収集を計画する。
   なぜ: 攻撃で見えた「賭けの核」を、実行前に安く検証しておくのが最大の見返り。

## 壁打ち質問リスト

各要素を事実で埋めるために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。

1. 今回 **攻撃対象にする計画・意思決定** は具体的に何で、**成功の定義** は何ですか？
   （壊れて一番困るものは？その決定は取り返しがつきますか＝可逆/不可逆）
2. その計画が **「当然こうなる」と暗黙に前提していること** は何ですか？そのうち、**崩れたら
   計画全体が破綻する前提** はどれですか？根拠は事実ですか、それとも願望・期待ですか？
3. この計画で **最も痛手を被る相手・最も得をする競合** は誰ですか？その相手の **動機・制約・
   持っている手札** は何ですか？（自社の常識でなく、相手の立場で）
4. **自分がその競合/敵なら、この計画をどう潰しますか？** 最も効く一手は何だと思いますか？
5. 社内で **今この計画に反対している人／違和感を口にしていない人** はいますか？その懸念は何で、
   なぜ表に出てこないのですか？（集団浅慮・心理的安全性のチェック）
6. 過去に自社や同業が **似た計画で失敗した事例** はありますか？そのとき効かなかった前提は？
7. レッドチームを **誰で組めますか**（計画立案者から独立しているか／外部・異分野・敵側を
   知る人を入れられるか）？経営陣は反証を歓迎する姿勢を示せますか？
8. 洗い出した脆弱性のうち、**実行前に一番先に潰す／検証すべきもの** はどれだと考えますか？

## 出力フォーマット

ALWAYS この型で出力する（攻撃→格付け→対策の一気通貫）。粗探しの羅列で止めず、必ず対策と
次の一手まで書く。

```
【設定】攻撃対象: <壊しにいく計画/意思決定> ／ 成功の定義: <…> ／ 可逆性: <可逆|不可逆>
        採用する敵視点: <競合A / 離反顧客 / 規制当局 …（複数）>
        グラウンドルール: 攻撃対象は計画であり人ではない／目的は計画の強化

【前提の棚卸し（キーアサンプション）】
  - <前提> ｜ 根拠: <事実|願望> ｜ 崩れた時の影響: <致命|中|小>

【攻撃（レッドチーム視点）】視点ごとに
  ◤視点: <競合Aなら…>
    - 攻撃口/失敗シナリオ: <どう潰すか> ｜ 影響度: <高|中|低> ｜ 蓋然性: <高|中|低>

【総合診断（致命的な脆弱性・上位順）】
  1. <影響度×蓋然性が最大の脆弱性> — なぜ致命的か
  2. …

【対策（ブルーチームの応答）】上位脆弱性ごとに
  - <脆弱性> → 対応方針: <回避|緩和|監視|受容> ／ 具体策: <…>

【次の一手】<崩れたら致命的な前提を、実行前に検証する小さな実験/情報収集を1〜3個>
【未確認の前提】<事実確認が要る点（壁打ちで埋める）>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。既存の実店舗中心の小売企業が、
サブスク型の定期宅配サービスへ新規参入する計画を、役員会付議前に検証する場面。

- **手順①対象**: 「定期宅配サブスクへの参入計画」。成功の定義＝一定期間で黒字化。可逆性＝
  在庫・物流投資を伴うため **不可逆性が高い** → レッドチーム向き。
- **手順②ルール**: 「攻撃するのは計画、目的は計画を強くすること」を宣言。
- **手順③編成**: 立案の事業部から独立させ、EC経験者・物流の実務者・懐疑的な現場社員を入れる。
- **手順④前提の棚卸し**:
  - 「既存客はそのままサブスクに移る」｜根拠=**願望**｜崩れた時=**致命**。
  - 「大手ECは同カテゴリに本気参入してこない」｜根拠=願望｜崩れた時=致命。
  - 「想定の解約率に収まる」｜根拠=薄い｜崩れた時=中〜致命。
- **手順⑤敵視点で攻撃（ミラーイメージング回避）**:
  - ◤最有力の大手EC: 「自分がこの大手なら、価格と配送速度で被せ、参入直後に消耗させる」。
    → 影響度=高／蓋然性=中。
  - ◤離反しかけの顧客: 「実店舗の良さ（選ぶ楽しさ・即時性）が消えるなら継続理由がない」。
    → 影響度=高／蓋然性=高。
  - ◤規制/データ視点: 「定期課金の同意・解約導線が不備なら苦情・行政指摘のリスク」。
    → 影響度=中／蓋然性=中。
- **手順⑥格付け**: 上位は「顧客がそもそも移らない（前提の崩壊）」と「大手の価格攻勢」。
- **手順⑦対策（ブルーチーム応答）**:
  - 顧客移行 → **緩和**: 全面移行でなく、まず一部商品・一部地域で小さく検証してから拡大。
  - 大手の価格攻勢 → **回避**: 価格勝負を避け、実店舗連動の体験や品揃えで差別化。
  - 同意/解約導線 → **緩和**: 解約を明快にし、同意設計を最初から作り込む。
- **手順⑧次の一手**: 最も致命的な前提「既存客が移るか」を、限定エリアの先行トライアルで
  実データ検証してから本格投資を判断する（不可逆な投資の前に、安く賭けを確かめる）。
- **未確認の前提**: 実際の移行意向・解約率・大手の出方——ここは推測のまま進めず実データで裏取り。

## 相性（組み合わせると効く）

- `premortem`: 「計画は既に失敗した」と仮定し **内部視点** で理由を逆算するプレモータムと、
  **外部の敵視点** で能動的に攻撃するレッドチームは補完関係。両輪で失敗網羅性が上がる。
- `devils-advocate`: 悪魔の代弁者は同じ枠内で1人が反対役を担う軽量版。まず悪魔の代弁者で
  当たりを付け、賭けが大きければ独立チームのレッドチームへ格上げする、という段階運用が効く。
- `five-forces`: 「敵になりきる」ための入力。競合・新規参入・代替品・買い手/売り手の力を
  先に構造化しておくと、攻撃口の洗い出しが精緻になる。
- `reverse-assumption`: 前提を反転させる逆設定法は、キーアサンプション・チェック（手順④）の
  発想を広げ、暗黙の前提を炙り出す前工程として噛み合う。
- `payoff-matrix`: 洗い出した対策を効果×実現性で並べ、どの脆弱性から潰すか（手順⑦〜⑧）の
  優先順位付けに使う。
- 揺さぶり枠として `six-hats` の黒帽子（慎重・リスク）を添えると、攻撃視点の抜けを補える。
