# なぜなぜ分析（5 Whys）

## 概要

なぜなぜ分析は、発生した問題に対して **「なぜ？」を繰り返し**、直前の答えにさらに「なぜ」を重ねることで、
表面的な**症状（現象）から根本原因（真因）**へ因果連鎖をたどる問題解決手法。真因に対策を打つことで、
対症療法でなく**再発防止**を実現する。トヨタ生産方式（TPS）を構成する代表的手段の一つで、
カイゼン／リーン／シックスシグマの根本原因分析（RCA）ツールとして世界的に普及した。

- **核となる考え方**: 目に見える不具合は氷山の一角。「だから→だから」と因果を下方向に掘り、
  **それを除去すれば再発が止まる水準（＝真因）**に到達して初めて有効な対策が打てる。逆に浅い所で止めると
  「ヒューズを交換する」式の対症療法になり、問題は必ず戻ってくる。
- **「5回」の意味**: 5は大野耐一の経験則に基づく**目安**であり固定ルールではない。3回で真因に届くことも、
  10回以上要することもある。**回数でなく、各リンクが事実と論理でつながっているか**が本質（→出典・要確認）。
- **出自（諸説あり・断定回避）**: トヨタ生産方式の中で **大野耐一（Taiichi Ohno）** が体系化・重視し、
  著書『トヨタ生産方式――脱規模の経営をめざして』（ダイヤモンド社, 1978）で「なぜを5回」を説いたことで普及した。
  英語圏では原型を **豊田佐吉（Sakichi Toyoda）** に帰す記述もあるが（1930年代説）、一次資料での確証は弱く、
  **佐吉起源は断定しない**。日本の実務解説では大野の発案として紹介されることが多い（→出典・要確認項目参照）。

## いつ使う / 使わない

**使う（適する状況）**
- **同じトラブル・不良・ミスが再発**し、対症療法（その場しのぎ）で終わっている問題の真因を突き止めたいとき。
- 製造不良・オペレーションの失敗・クレーム・事故・ヒューマンエラーなど、**因果が比較的たどれる具体的な事象**。
- 打った対策が効かず、「そもそも何が本当の原因か」を**素早く一次分析（RCA）**したいとき。
- ヒューマンエラーを**個人のせいにせず、仕組み・プロセスの原因**に落として恒久対策を作りたいとき。

**使わない / よくある誤用（アンチパターン）**
- **個人の責任追及で終わる**——最頻の失敗。「担当者が確認を怠った→教育する／注意する」で止めると、別の人が同じ
  ミスを繰り返す。「なぜ確認できない仕組みだったのか」と**仕組みに戻す**（→前提と限界）。
- **精神論に落とす**——真因が「意識が低い」「気をつける」になる。それは対策にならない。行動・仕組みで是正可能な水準まで下げる。
- **症状で止める（浅い）／飛躍する（深すぎ・無関係）**——1回で止めると症状対処、逆に真因を越えて掘ると論理が飛ぶ。
- **憶測でつなぐ**——各「なぜ」を事実（現地現物）で裏取りせず想像で埋める。1人・主観で作り検証しない。
- **単一の真因に無理やり収束**——複数原因が枝分かれする問題を一本道に押し込む（→特性要因図で分岐させる）。
- **前向きの発想やアイデア創出**、多数要因が複雑に絡む事象、統計解析が要る事象には不向き。他フレームで補完する。

## 前提と限界

- **前提**: 問題が**具体的な事象**として定義でき（いつ・どこで・何が・どれだけ）、因果をたどれること。
  各「なぜ」の答えを**事実で裏取り**できること（現場・データにアクセスできる）。曖昧な問題設定のままでは掘れない。
- **限界（批判を踏まえて）**:
  - **調査者の既知を超えられない**——知らない原因は出てこない。正しい「なぜ」を導く支援が手法自体には無い。
  - **再現性が低い**——人が違えば違う真因に至る。ファシリテーターのバイアスや、複雑問題の過度な単純化が起きやすい。
  - **単一真因への収束バイアス**——実際は各「なぜ」で原因が複数枝分かれし得る。線形の手法を非線形の事象に当てる限界がある。
    Alan J. Card（BMJ Quality & Safety, 2017）は「貧弱なRCAツール」と批判し代替を提案。Teruyuki Minoura（元トヨタ役員）も
    「基本的すぎる」と述べたとされる（→要確認）。
  - **「5回目」という深さは恣意的**——5で真因に一致する保証はない。回数を目的化しない。
- これらは、**特性要因図で要因を面に広げてから縦に深掘りする／複数系統（発生原因・流出原因）で回す／
  導いた真因をso-what-why-soや悪魔の代弁者で検算する**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。

1. **問題を具体的に定義する。** 「いつ・どこで・何が・どれだけ」を事実で書く（例:「特定工程で当月、規格外品が通常より多く流出した」）。
   なぜ: 主語や範囲が曖昧だと因果がたどれず、掘る方向が発散する。悪い問題設定は悪い真因を生む。
2. **メンバーと事実を集める。** その現象の**当事者・現場の関係者**を入れ、現物・データ・記録を手元に置く（現地現物）。
   なぜ: 憶測でつなぐと分析全体が崩れる。1人・伝聞だけで作らない。意見を言いやすい場を作る。
3. **1つ目の「なぜ」を問い、事実で答える。** 「なぜこの現象が起きたか」に、確認できた事実で答える。
   なぜ: 最初のなぜが症状の言い換えだと以降が空回りする。観測された事実に紐づける。
4. **答えにさらに「なぜ」を重ねる（真因まで反復）。** 各答えを次の問いの対象にし、因果を1段ずつ下げる。
   なぜ: 1段飛ばすと論理が飛躍する。「オーバーロード→潤滑不足→ポンプ摩耗→…」と刻む。
5. **各リンクを逆読みで検算する。** 下から「〈真因〉だから〈上位〉、だから〈現象〉」と読み、飛躍・すり替え・分岐漏れが無いか点検する。
   なぜ: 因果でなく相関や時系列を混同していないかを弾く。ここが分析の品質を決める。
6. **分岐を見極める。** その段で原因が複数あり得るなら枝を分ける（1つに絞らない）。多要因なら特性要因図に切り替える。
   なぜ: 単一真因への収束バイアスが最大の落とし穴。重要な枝を切り捨てない。
7. **停止条件で止める。** 「それを除去すれば再発が止まり、かつ自組織で対処可能」な水準に達したら止める。
   なぜ: 回数でなく質で止める。人・精神論（意識/気をつける）に落ちたら**掘り方が誤っている**サイン——仕組みに戻す。
8. **（品質・製造では）2系統で回す。** 「なぜ発生したか（発生原因）」と「なぜ検出・防止できなかったか（流出原因）」を別々に掘る。
   なぜ: 発生を潰しても、流出を止めないと次は別要因で漏れる。両輪で恒久対策になる。
9. **真因に対策を紐づけ、実行へ渡す。** 各真因に恒久対策を割り当て、担当・期限・効果確認をPDCA/QCストーリーに接続する。
   なぜ: 真因特定はゴールでなく起点。対策と検証まで繋げないと「分析して終わり」になる。

## 壁打ち質問リスト

各段を事実で埋めるために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。

1. 今回の問題を、**いつ・どこで・何が・どれだけ**の事実で言うとどうなりますか？（曖昧な主語を具体化する）
2. それは**再発している問題**ですか？ 過去に打った対策と、なぜ効かなかったか分かる範囲で教えてください。
3. その現象について、**実際に確認できている事実・データ・現物**は何ですか？ 逆に、まだ**推測に留まっている**部分はどこですか？
4. 最初の「なぜ」に対する答えは、**症状の言い換え**になっていませんか？（例:「不良が出た→品質が悪いから」は掘れていない）
5. いま挙げた原因について、**「だから〜」と逆から読む**と現象まで無理なくつながりますか？ 飛躍や別要因はありませんか？
6. この段で、原因は**1つですか、複数に枝分かれ**しますか？ 見落としている枝はありませんか？
7. 掘った先が「**担当者が不注意だった／意識が低い**」に向かっていませんか？ それを「**なぜ気づけない/防げない仕組みだったか**」に言い換えられますか？
8. （製造・品質なら）**なぜ起きたか（発生）**と**なぜ止められなかったか（流出）**の両方を分けて掘れていますか？
9. どこまで掘れば、**それを直せば再発が止まり、自分たちで対処できる**と言えますか？（停止条件の合意）

## 出力フォーマット

ALWAYS この型で出力する（因果連鎖→真因→対策の一気通貫）。回数は5に固定せず、真因到達で止める。

```
【問題（事実）】いつ/どこで/何が/どれだけ: <具体的な事象>
【前提となる事実】<確認済みの事実・データ> ／ 【未確認】<推測に留まる点>

【なぜなぜ連鎖】（発生系統）
  現象:   <観測された問題>
  なぜ1 → <事実に基づく直接原因>
  なぜ2 → <…>
  なぜ3 → <…>
  （必要なだけ継続。分岐する場合は 3a / 3b と枝を明示）
  真因:   <除去すれば再発が止まり、自組織で対処可能な原因>

【なぜなぜ連鎖】（流出系統・品質/製造で該当時）
  なぜ検出・防止できなかったか → … → 真因: <検出/防止の仕組みの欠落>

【逆読み検算】<真因>だから…だから<現象>。—飛躍/分岐漏れの有無: <所見>
【真因→対策】<各真因に対する恒久対策（仕組みの是正。人・精神論に落とさない）>
【次の一手】<担当・期限・効果確認の方針（PDCA/QCストーリーへ接続）>
【未確認の前提】<事実確認が要る点（壁打ちで埋める）>
```

## 具体例（ワークスルー）

大野耐一が『トヨタ生産方式』(1978) で示した**機械停止の正典例**を、上記フォーマットに沿って再現する
（架空の数値・企業名は用いない）。

- **問題（事実）**: ある機械が稼働中に停止した。
- **前提となる事実**: 停止時にヒューズが切れていた。未確認: 停止に至る内部要因は現物点検で確認する。
- **なぜなぜ連鎖（発生系統）**:
  - 現象: 機械が止まった。
  - なぜ1 → オーバーロードがかかり、ヒューズが切れた。
  - なぜ2 → 軸受部の潤滑が十分でなかった。
  - なぜ3 → 潤滑ポンプが十分にくみ上げていなかった。
  - なぜ4 → ポンプの軸が摩耗してガタガタになっていた。
  - なぜ5 → ストレーナー（濾過機）が付いておらず、切粉が入り込んでいた。
  - 真因: ストレーナーが無く、異物（切粉）がポンプに侵入する仕組みだった。
- **逆読み検算**: 「ストレーナーが無い**だから**切粉が入り**だから**軸が摩耗し**だから**くみ上げ不足になり
  **だから**潤滑不足で**だから**オーバーロードで停止した」——飛躍なくつながる。
- **真因→対策**: **ストレーナーを取り付ける**（恒久対策）。もし「なぜ1」で止めて**ヒューズを交換するだけ**なら、
  切粉が入り続けて**再発する**。真因まで下げて初めて再発が止まる。
- **次の一手**: 対策後、同型機の停止再発の有無を一定期間モニタし、効果を確認（PDCAで回す）。
- **未確認の前提**: 他機にも同じ濾過機欠落が無いかの横展開点検——ここは現物で裏取りが要る（推測のまま進めない）。

## 相性（組み合わせると効く）

- `fishbone`: 特性要因図で要因を4M等の**面**に広げてから、主要な枝を なぜなぜ で**縦**に深掘りする。単一真因への収束バイアスを補う定番の前工程。
- `logic-tree`: 問題を Why ツリーとして構造化し、なぜなぜの各分岐を漏れなく扱う（分岐の抜けを防ぐ）。
- `so-what-why-so`: 各リンクの「だから／なぜなら」を検算し、因果の飛躍やすり替えを弾く論理チェックに使う。
- `pdca`: 導いた真因への対策を計画→実行→評価→改善で回し、効果を確認して定着させる後工程。
- `qc-story`: 品質改善の標準手順（現状把握→要因解析→対策）の「要因解析」に なぜなぜ を組み込む。
- 揺さぶり枠として `premortem`（打つ対策が失敗する未来を先回りして真因の取りこぼしを検出）や
  `devils-advocate`（「本当にそれが真因か／別の枝ではないか」を意図的に反証）を添えると、収束バイアスと過信を防げる。
