# 属性列挙法（Attribute Listing）

## 概要

属性列挙法は、対象を **属性（特性）に分解**し、**各属性ごとに「変える・なくす・強める・代替する」**
ことで改善案やアイデアを生み出す発散技法。漠然と「良い案を出せ」と考えるより、属性という
**切り口を強制的に用意**するため、網羅的かつ体系的に発想できるのが核。

日本の実務で標準的に使われる属性の3分類（上野陽一が特性列挙法として日本に紹介した際の整理。3分類自体の発案は産能大・橋本講師とされる→要確認）:

| 分類 | 見るもの | 例（コーヒーカップ） |
|---|---|---|
| **名詞的属性** | 全体・部分・材料・製法 | 陶器製、取っ手、底、二重構造 |
| **形容詞的属性** | 性質・状態・形・色 | 白い、重い、割れやすい、円筒形 |
| **動詞的属性** | 機能・働き・動作 | 飲む、保温する、持つ、置く |

- **核となる考え方**: 属性を洗い出せば「いじれる場所（変数）」が可視化される。各属性に変化を加えると、
  そこが新しいアイデアの起点になる（例: 「割れやすい(形容詞)」→割れない素材へ、「保温する(動詞)」→
  保冷も、「取っ手(名詞)」→無くして直持ちできる形へ）。
- **出自・系譜（諸説あり・年号は要確認／詳細と裏取りは出典・要確認節）**: 考案者は米ネブラスカ大学の
  **Robert P. Crawford（クロフォード）**。技法の起点は1930年代前半とされるが初出年は諸説ある。日本では
  **上野陽一**（産業能率大学 創立者）が1957年頃「特性列挙法」として紹介し、名詞的/形容詞的/動詞的の3分類は
  同大学の橋本講師の発案とされる（いずれも要確認）。原典の核は別事物の属性を移す **「AX→BX 転移」** だが、
  日本普及版は対象自身を改良する **「自己改良型」** へ組み替えられた——本スキルは自己改良型を主軸に、
  転移型を上級バリエーションとして扱う。

## いつ使う / 使わない

**使う（適する状況）**
- **既存の製品・サービス・業務プロセスの改良/差別化**アイデアを出したいとき。属性列挙法は
  ゼロからの新概念より、既にあるものの「どこをどういじれるか」に最も強い。
- **発想が堂々巡りで止まった**とき。切り口（属性）を強制的に並べると、盲点だった変数が見える。
- **機能やスペックを見直したい**とき（動詞的属性＝機能に着目するのはVE/バリューエンジニアリング的）。
- **モレなく網羅的に**アイデアを洗い出したいとき。頭字語系の発想法より対象に密着して漏れが少ない。
- 後段の**形態分析法（属性を軸に総当たり）**の入力（各属性と代替案）を用意したいとき。

**使わない / よくある誤用（アンチパターン）**
- **属性の分解が粗い/偏る**——最頻の失敗。分解が凡庸だと出るアイデアも凡庸（GIGO）。人は利益・省力・
  健康・美/デザインなど**無意識に選びがちな属性に偏る**ため、3分類で強制的に幅を出す。
- **列挙して満足し、変化・評価に進まない**——列挙は手段。各属性を実際に「変える/なくす/代替」して
  初めてアイデアになる。棚卸しで止めない。
- **組合せ爆発を放置**——量産した案を絞らず全部を追おうとする失敗（爆発の定量 M^N とその含意は「前提と限界」節に集約）。
  原法は絞り込み指針が弱いので、評価軸（効果×実現性）や payoff-matrix で有望案を数個に絞る工程を必ず持つ。
- **対象がゼロから未定義**なのに使う——改良の土台が無いと属性が挙がらない。新規概念の創出には不向き
  （jtbd・デザイン思考・アナロジー系を先に）。
- **漸進的改善に寄りがち**——既存の延長線上の改良に強い反面、非連続なブレイクスルーは出にくい。
  破壊的な発想が要る局面では視点転換系（reverse-assumption 等）を併用する。

## 前提と限界

- **前提**: 改良・発想の**対象が1つに具体的に定まっている**こと（「自社の商品X」「この受付業務」など）。
  対象が抽象的・複数だと属性が発散し、列挙が機能しない。まず対象を1つに絞る（手順①が要）。
- **限界（調査に基づく）**——「いつ使わない」節が*やってしまう失敗*（分解の偏り・列挙で満足・漸進バイアス）を
  扱うのに対し、この節は技法に内在し回避しきれない**構造的限界**に絞る（両節で役割を分担）:
  - **成果が分解の質に上限づけられる**——出るアイデアの天井は属性の切り出しの質で決まるが、原法自体に
    それを保証する仕組みは無い（3分類＋抜け点検は担保策であって保証ではない）。
  - **組合せは定量的に爆発する（M^N）→ゆえに評価工程が必須**——N属性×各M代替案で **M^N** 通り
    （5属性×各4案なら 4^5＝1024通り）。列挙を増やすほど探索空間は指数で膨れ、原法に絞り込み指針は無い
    （Mycoted も同旨）。したがって**手順⑥の評価・優先づけ（効果×実現性／payoff-matrix）は省略不可の工程**で、
    発想（手順⑤）と評価（手順⑥）は必ずワンセットで回す。
- これらは、**属性を軸に総当たりする形態分析法へ発展させる / 変化の動詞をSCAMPER・オズボーンで増やす /
  出たアイデアを payoff-matrix で絞る / 破壊枠に reverse-assumption を混ぜる**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップに「なぜ」を添える。**基本は自己改良型（①〜⑥）**。転移型は上級バリエーション。

1. **対象を1つに固定し、狙いを言語化する。** 何を（商品X／この業務）どうしたいか（改良・差別化・
   コスト削減）を明文化する。
   なぜ: 対象が曖昧だと属性が発散し、羅列で終わる。動詞的属性を見るときの「機能の目的」もここで定まる。
2. **属性を3分類で洗い出す。** 名詞的（全体・部分・材料・製法）／形容詞的（性質・状態・形・色）／
   動詞的（機能・働き）の3観点で、できるだけ多く挙げる。
   なぜ: 3つの窓を強制することで、人が見落としがちな切り口（特に動詞的＝機能）まで拾える。
3. **重複を削り、矛盾を整理し、分類に振り分ける。** 同じ属性の言い換えをまとめ、どの分類か曖昧なものを
   確定する。
   なぜ: 重複は組合せ爆発を悪化させ、分類の曖昧さは後の変化発想をぶらす。
4. **各分類の「抜け」を点検し、追加する。** 「材料は？製法は？」「他にどんな状態が？」「まだ挙げていない
   機能は？」と各窓を埋める。差異への注目（同種の他製品と何が違うか）で隠れ属性を炙り出す。
   なぜ: 網羅性が属性列挙法の生命線。ここの抜けが最終アイデアの盲点に直結する。
5. **属性ごとに変化を発想する。** 各属性に対し「変える／なくす／強める・弱める／逆にする／他の値に
   代替する」を当てて案を出す。動詞（変化操作）が尽きたら SCAMPER・オズボーンのチェックリストを借りる。
   なぜ: これが属性列挙法を「列挙」から「発想」に変える核。属性×変化操作の交点がアイデア。
6. **出た案を評価し、次の一手に落とす。** 効果×実現性（コスト・技術・独自性）で有望案を数個に絞り、
   検証すべき仮説やプロトタイプを決める。
   なぜ: 組合せ爆発を抑え、列挙で終わる失敗を防ぐ。属性列挙は起点であってゴールではない。

**（上級）転移型 AX→BX バリエーション:** ステップ5で自分の対象内に閉じず、**別の事物の魅力的な属性を
借りてくる**。手順: (a) 参考にしたい別事物Bを選ぶ→(b) Bの際立った属性Xを抜き出す→(c) その属性Xを
対象Aに適用する（例: スマホの「通知が届く」属性を傘に移す→置き忘れ通知付きの傘）。アナロジー発想に近く、
非連続な案が出やすい（→ analogical-thinking / synectics と相性）。

## 壁打ち質問リスト

各属性・変化案を具体で埋めるために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。

1. 改良・発想したい**対象は具体的に何**で、**どうなったら成功**ですか？（改良／差別化／コスト削減など狙いを1つに）
2. その対象を構成する**部品・材料・製法（名詞的属性）**を、思いつく限り挙げてください。見落としがちな内部構造は？
3. その対象の**性質・状態・形・色・大きさ（形容詞的属性）**はどうですか？「当たり前すぎて気にしていない」特徴は？
4. その対象が**果たしている機能・働き（動詞的属性）**は何ですか？主機能のほか、副次的にこなしている働きは？
5. **同種の他社製品やライバルと、どの属性が違い**ますか？（差異への注目が隠れ属性を炙り出す）
6. 挙げた属性のうち、**顧客が最も価値を感じている/最も不満を持っている**のはどれですか？
7. 「**この属性は無くせない/変えられない**」と思い込んでいるものはどれですか？（そこにこそ転換の余地）
8. 出したアイデアを絞る**評価軸**は何ですか？（効果の大きさ・実現コスト・独自性・自社らしさ など）

## 出力フォーマット

ALWAYS この型（棚卸し→変化アイデア→評価→次の一手）で出力する。属性表は3分類を必ず埋める。

```
【属性表（棚卸し）】対象: <改良したいもの> ／ 狙い: <改良/差別化/コスト削減 等>
  名詞的属性（全体・部分・材料・製法）: - <…> - <…> …
  形容詞的属性（性質・状態・形・色）:   - <…> - <…> …
  動詞的属性（機能・働き）:             - <…> - <…> …

【変化アイデア（属性 × 変化操作）】
  <属性1> → 変える/なくす/強める/代替 → <出たアイデア>
  <属性2> → …                          → <出たアイデア>
  …（有望な属性を優先に、量を出す。行き詰まったら他事物の属性を借りる転移型を追加）

【有望案（効果 × 実現性で絞る）】
  1. <アイデア>：効果<高/中/低> 実現性<高/中/低> 一言<なぜ有望か>
  2. …（2〜3案に絞る）

【次の一手】<検証すべき仮説・試作・意思決定を1〜2個>
【未確認の前提】<事実確認が要る点（壁打ちで埋める）>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。日用品の **折りたたみ傘** の改良を検討する場面。

- **手順①対象・狙い**: 「折りたたみ傘」を、既存の延長で**差別化**する。
- **手順②属性を3分類で列挙**:
  - 名詞的: 生地、骨（親骨/受骨）、シャフト、開閉部、持ち手、収納袋、ボタン。
  - 形容詞的: たためる、軽い/重い、濡れる、黒い、コンパクト、折り目がつく。
  - 動詞的: 雨を防ぐ、たたむ、広げる、持ち運ぶ、（濡れたら）水を含む、置き忘れる。
- **手順③整理**: 「たためる（形容詞）」と「たたむ（動詞）」は視点違いの重複→役割を分けて残す。
- **手順④抜け点検（差異への注目）**: 大型傘との差＝「収納袋が要る」「開閉が手間」→ 収納袋・開閉部を属性に追加。
- **手順⑤属性 × 変化操作で発想**:
  - 生地（名詞）× 代替 → 速乾素材にして「濡れる→すぐ乾く」に。
  - 収納袋（名詞）× なくす → 袋不要で本体が自動で閉じて自己収納する構造に。
  - 濡れる（形容詞）× 逆にする → 水を弾いて振れば乾く撥水強化。
  - 置き忘れる（動詞）× なくす → （転移型）スマホの「通知」属性を借り、置き忘れ通知を付ける。
- **手順⑥評価→次の一手**: 「袋不要の自動収納」と「置き忘れ通知」を効果×実現性で比較し、実現性の高い
  「速乾素材」から小さく試作して受容性を検証する。
- **未確認の前提**: 各案のコスト・製造可否・実際の顧客不満の大きさ——ここは実データで裏取りが要る
  （推測のまま製品化しない）。

## 相性（組み合わせると効く）

- `morphological-analysis`: 列挙した属性を**軸(パラメータ)**に、各属性の代替値を総当たりで組み合わせる直接の
  発展形（属性列挙法はその前工程・入力づくり）。
- `scamper`: 各属性に当てる**変化の動詞**（Substitute/Combine/Adapt…）を7つ供給し、手順⑤の発想を加速する。
- `osborn-checklist`: 「他に転用は？拡大/縮小は？逆は？」の9チェックで、属性ごとの変化案の抜けを埋める。
- `hope-defect-listing`: 希望点/欠点の列挙で属性の「不満・理想」を炙り出し、優先して変えるべき属性を特定する兄弟技法。
- `analogical-thinking` / `synectics`: 転移型(AX→BX)で**他事物の属性を借りる**ときの発想を支える（非連続案に効く）。
- `payoff-matrix`: 量産したアイデアを**効果×実現性**で絞り、組合せ爆発を制御する評価工程。
- 揺さぶり枠として `reverse-assumption`（「変えられない」と決めつけた属性を反転）や `premortem`
  （有望案が失敗する要因を先回り）を添えると、漸進バイアスを突き破れる。
