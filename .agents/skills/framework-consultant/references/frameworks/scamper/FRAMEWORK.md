# SCAMPER

## 概要

SCAMPERは、**既存の対象（製品・サービス・業務プロセス・企画）を出発点に、7つの動詞で強制的に
変形して改善・応用アイデアを大量に出す**発散系の発想フレーム。頭字語の各文字が「切り口」になる。

| 文字 | 動詞（和） | 主な問い |
|---|---|---|
| **S** | Substitute（代替） | 何を別のもの（材料・人・方法・場所・ルール）に置き換えられるか |
| **C** | Combine（結合） | 何と何を組み合わせ・統合・融合できるか |
| **A** | Adapt（応用/適応） | 他分野・既存の何かを借りて合わせられないか |
| **M** | Modify（修正） | 大きさ・形・色・頻度・意味をどう変えるか（Magnify=拡大 / Minify=縮小 を含む） |
| **P** | Put to another use（転用） | 別の用途・別のユーザー層・別の市場で使えないか |
| **E** | Eliminate（削除） | 何を省く・減らす・単純化できるか |
| **R** | Reverse / Rearrange（逆転・再配置） | 順序・役割・因果を逆に、または入れ替えたらどうか |

- **核となる考え方**: 白紙から発想するのは難しいが、既存の叩き台に「7つの決まった問い」を
  当てて**強制連想（forced connection）**すれば、思考の慣性を破って多数の切り口が出る。
  順序に固定はなく、往復してよい。違和感のある案も一旦拾う **force-fit** が肝。
- **出自（要確認扱い）**: 源流は Alex F. Osborn（「ブレインストーミングの父」）の
  「アイデア触発チェックリスト」（著書『Applied Imagination』1953）。これを **Bob Eberle**（教育者）が
  子ども向けに覚えやすい7語の語呂へ凝縮し、1971年の著書
  『SCAMPER: Games for Imagination Development』で提示したとされる。
  Eberle は **Osborn の設問に加え、Frank E. Williams ら（子どもの創造性教育の研究者）の知見も取り込んで7語に再構成した**とされる。
  ビジネス文脈での普及は Michael Michalko『Thinkertoys』(初版1991) の寄与が大きい。
  **考案者・年号・書誌は資料間で細部が食い違うため断定を避ける**（→出典・要確認項目）。
- **位置づけ**: ラテラルシンキング（水平思考）系のチェックリスト法。`osborn-checklist`（親）を
  実務で使いやすく7動詞に再整理した版にあたる。

## いつ使う / 使わない

**使う（適する状況）**
- 既存の製品・サービス・業務・企画を**改良・差別化・コスト削減・転用**したいとき。
- ブレストが**行き詰まり、切り口が尽きた**とき。決まった問いで発想を再点火したい。
- マンネリ化した売り方・オペレーション・企画に**別の角度を強制注入**したいとき。
- デザイン思考の Develop（展開）段階など、**叩き台があってそれを膨らませる**局面。

**使わない / よくある誤用（アンチパターン）**
- **叩き台が無いゼロイチに使う**——SCAMPERは既存物の変形が前提。起点が無いと問いが空回りする。
  純粋な新規概念の探索は `jtbd` や `design-thinking` で問題を捉え直してから使う。
- **発散したまま絞り込まない**——最頻の失敗。SCAMPERは案の質・実現性を保証しない。
  非現実的・非倫理的な案も混じる前提で、**必ず評価軸で選別**する（→`payoff-matrix`/`pmi`）。
- **漸進改善に閉じる**——既存物いじりのため、放っておくと **incremental（小改良）** に偏り、
  破壊的イノベーションは出にくい。破壊が要る局面では視点転換系や `triz` を併用する。
- **分解が粗いまま動詞を当てる**——「対象」を丸ごとにSCAMPERしても浅い案しか出ない。
  構成要素（部品・工程・登場人物・チャネル）に分けてから各要素に動詞を当てる。
- **7動詞を一律に軽く流す**——出にくい動詞（削除・逆転）ほど非常識な良案が眠る。粘りが要る。
- 系統的・多ステークホルダーの複雑な制度設計や、精緻な定量最適化には不向き。他フレームで補う。

## 前提と限界

- **前提**: 変形の起点となる**既存の対象が1つ定まっている**こと。対象と狙い（改善/差別化/削減/転用）が
  曖昧だと、出したアイデアを評価できず羅列に終わる。発散段階では予算・技術・法規制などの制約を
  一旦棚上げできること（force-fitのため）。
- **限界（批判を踏まえて）**:
  - **漸進性バイアス**——既存物の変形が前提のため、根本的・破壊的な発想には弱い。
  - **質を保証しない**——量は出るが玉石混交。実現性・倫理性は別途の評価工程に依存する。
  - **知識・経験依存**——発想の幅が参加者の引き出しに左右される。多様な知識・視点の投入が要る。
  - **単一手法依存のリスク**——SCAMPERだけに頼ると探索が狭まる。他の発想法との併用が前提。
- これらは、**発散後に評価軸で絞る（`payoff-matrix`/`pmi`）／破壊が要るなら視点転換系や `triz` を混ぜる／
  問題設定自体を疑うなら `jtbd`・`reverse-assumption` を前段に置く**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップに「なぜ」を添える。

1. **対象と狙いを1つに固定する。** 何を（製品/サービス/工程/企画のどれの、どの部分か）、
   何のために（改善/差別化/コスト削減/転用/マンネリ打破）SCAMPERするかを明文化する。
   なぜ: 対象と評価軸が無いとアイデアを選別できず、発散が空回りする。
2. **対象を構成要素に分解する。** 部品・素材・工程・登場人物・提供チャネル・価格・体験などに割る。
   なぜ: 各動詞は「要素に対して」効く。分解が細かいほど代替・削除・再配置の切り口が増える
   （`attribute-listing`・`mece` を援用してよい）。
3. **7つの動詞を順に強制適用する（判断保留）。** 各動詞で例質問を複数投げ、要素ごとに案を出す。
   質より量、突飛でも却下しない。なぜ: 評価しながら出すと発想が萎む（ブレストの分離原則）。
4. **出にくい動詞ほど粘る／force-fitする。** 特に「削除（何を無くせるか）」「逆転（役割・順序・因果を反対に）」は
   無理やりにでも1案ひねり出す。なぜ: 違和感のある動詞ほど非常識な良案が眠っている。
5. **順序に縛られず往復する。** Combineで出た案にSubstituteを重ねる等、動詞を相互に触発させる。
   なぜ: SCAMPERに固定の流れはない。組み合わせから跳ねる案が出る。
6. **発散を止め、評価軸で絞り込む。** 狙い（手順1）に照らし、インパクト×実現性などで上位2〜3案を選ぶ。
   軸の当て方は狙いで変える——差別化狙いならインパクト（顧客価値）を、コスト削減狙いなら実現性・投資回収を重く配点する。
   採点の前に「自社の強みと無関係」「法規制で不可」等は**足切り**で先に落とし、残った案だけ採点する。最後に1案あたりの**検証コスト**
   （試作費・所要期間・巻き込む人数）をざっと見積もり、"効果÷検証の重さ"で並べ替えると次の一手に繋げやすい。
   なぜ: 発散と評価を混ぜると失速する。ここで初めて質を問う（`payoff-matrix`/`pmi`へ）。
7. **force-fitの奇抜案を1つ意図的に残す。** 実現性だけで刈ると平凡な小改良に収束する。
   なぜ: 跳ねる種を1つ残すことが、漸進性バイアスへの歯止めになる。
8. **次の一手（試作・検証・意思決定）に落とす。** 選んだ案を、検証できる仮説やアクションに変換する。
   なぜ: アイデアは検証されて初めて価値になる。「出して終わり」を避ける。

## 壁打ち質問リスト

各動詞に素材を供給し、評価軸を引き出すための問い。空欄は勝手に埋めず、まずこれで引き出す。

1. 今回 SCAMPER をかける**対象を1つに絞る**と何ですか？（製品/サービス/業務/企画のどれで、その中の具体的にどの部分か）
2. 今回の**狙い**は何ですか？（改善／コスト削減／差別化／新用途の開拓／マンネリ打破——出したアイデアの**評価軸**になります）
3. その対象を**構成要素に分解**すると何がありますか？（部品・素材・工程・登場人物・チャネル・価格・顧客体験など）
4. これまで「当たり前」「動かせない」と思って**触れてこなかった前提**はどれですか？（＝逆転・削除の狙い目）
5. 遠い業界・他分野で「うまくいっている仕組み」で、**借りてこられそうなもの**はありますか？（＝応用/適応の種）
6. 逆に、この対象で**絶対に外せない核**は何ですか？（削除・代替してはいけない部分を先に決めると、残りを大胆に崩せます）
7. 出たアイデアを選ぶとき、**何を最重視**しますか？（実現コスト／スピード／自社の強みとの整合／顧客価値のどれか）
8. 発散の段階で、**一旦無視してよい制約**（予算・技術・法規制）はどれですか？（force-fit で奇抜案を拾うため）

## 出力フォーマット

ALWAYS この型で出力する（対象固定 → 7動詞で発散 → 絞り込み → 次の一手）。命令的に守る。

```
【SCAMPERの対象】改善対象: <既存の製品/サービス/業務/企画のどこ> ／ 狙い: <改善/差別化/削減/転用 など>
【7つの切り口で発散】（各動詞1つ以上。出にくい動詞も force-fit で必ず埋める）
  S 代替:        - <何を何に置き換えるか>
  C 結合:        - <何と何を組み合わせるか>
  A 応用/適応:   - <他分野の何を借りるか>
  M 修正・拡縮:  - <大きさ/形/頻度/意味をどう変えるか>
  P 転用:        - <別の用途/相手/市場>
  E 削除:        - <何を省く/減らす/単純化するか>
  R 逆転・再配置:- <順序/役割/因果をどう反転・入替するか>
【有望案の絞り込み】<狙いに照らしインパクト×実現性で上位2〜3案／force-fitの奇抜案を1つ残す>
【次の一手】<試作・検証・意思決定するアクション（1〜3個）>
【未確認の前提】<裏取りが要る点（壁打ちで埋める）>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。**従来型の折りたたみ傘**を改良する場面。

- **手順①対象と狙い**: 対象=一般的な折りたたみ傘、狙い=差別化と使い勝手の改善。
- **手順②分解**: 骨組み（素材）／生地／持ち手／開閉機構／留め具／たたむ動作／濡れた面の扱い。
- **手順③〜⑤ 7動詞で発散**:
  - **S 代替**: 金属骨をカーボン/樹脂に代え軽量化。留めボタンをマグネットに代える。
  - **C 結合**: 傘＋LEDライト（夜間の視認）、傘＋簡易バッテリー、傘＋防犯ブザー。
  - **A 応用/適応**: ワンタッチテントの展開機構を借りて開閉を速く。日傘の高遮光素材を借用。
  - **M 修正・拡縮**: 極小に畳める超軽量版（Minify）と、2人が入る大型版（Magnify）を用途別に。
  - **P 転用**: 使わない時に杖・自撮り棒・簡易物干しとして使える兼用設計。
  - **E 削除**: 骨の本数を減らす、持ち手を無くして装着式にし手ぶら化する。
  - **R 逆転・再配置**: 閉じると濡れた面が内側に来る「逆折り式」（車内・室内で濡れない）。
- **手順⑥絞り込み**: 狙い（差別化×使い勝手）に照らし「逆折り式(R)」「手ぶら化(E)」を上位に。
- **手順⑦奇抜案を残す**: 「傘＋LEDライト(C)」は用途が限定的だが、跳ねる種として保持。
- **手順⑧次の一手**: 「逆折り式」の試作を1つ作り、車利用者に濡れ問題の解消度を検証する。
- **未確認の前提**: 逆折り機構のコスト増、手ぶら化の安全性——ここは試作・実データで裏取りが要る。

（※「逆折り式傘」は既に市場に存在する。ここでは SCAMPER の R（逆転）から同種の発想へ
どう到達するかを示すための一般化した例であり、特定製品・数値の主張ではない。）

## 相性（組み合わせると効く）

- `osborn-checklist`: SCAMPERの親。より広い設問群で、SCAMPERで拾い切れない切り口を補完する。
- `attribute-listing`: 対象を属性に分解してから各属性に7動詞を当てると、切り口が体系的に増える（手順②の強化）。
- `morphological-analysis`: 「代替・結合」で出た要素バリエーションを直交表で総当たり組合せし、網羅性を上げる。
- `payoff-matrix`: 発散した多数の案をインパクト×実現性で絞り込む収束の受け皿（手順⑥）。
- `pmi`: 有望案を Plus/Minus/Interesting で多面評価し、force-fitの奇抜案の芽を摘まずに検討する。
- `jtbd`: 前段に置き「顧客が本当に片付けたい用事」で対象と狙いを再定義してから発散すると、的外れな改良を防ぐ。
- 揺さぶり枠として `reverse-assumption`（前提反転でRを深掘り）や `premortem`／`devils-advocate`
  （選んだ案の失敗要因・過信を先回りで潰す）を添えると、漸進性バイアスと楽観に歯止めがかかる。
