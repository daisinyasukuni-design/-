# 緊急度・重要度マトリクス

## 概要

緊急度・重要度マトリクスは、タスクや活動を **緊急度(Urgent)** と **重要度(Important)** の2軸で
4象限に仕分けし、各象限に「取るべき行動」を割り当てて優先順位を決めるフレームワーク。

| | 緊急 | 緊急でない |
|---|---|---|
| **重要** | Q1 危機・締切（**Do 今すぐやる**） | Q2 計画・予防・自己投資（**Schedule 予定に組む**） |
| **重要でない** | Q3 割り込み・他者都合（**Delegate 任せる/断る**） | Q4 浪費・暇つぶし（**Delete やめる**） |

- **核となる考え方**: 「緊急」と「重要」は**別の軸**であり、人は放っておくと緊急に流される。
  緊急(Urgent)=即時対応を迫られ遅延に目に見える結果が出る受動的性質、重要(Important)=長期の目標・使命・
  価値に寄与し結果への影響が大きい能動的性質。両者を分離し、**重要だが緊急でない第2領域(Q2)**へ
  意図的に時間を投じることが長期成果を生む——これが最大の主張（Q2への投資は将来のQ1危機を減らす）。
- **各象限の行動(4D)**: Q1=Do（今すぐ着手）、Q2=Decide/Schedule（日時を決めて予定化）、
  Q3=Delegate（任せる・断る・仕組み化）、Q4=Delete（やめる・減らす）。
- **出自（通説・一部に不確実性あり）**: 名称は米大統領 **Dwight D. Eisenhower**（第34代）に由来する。
  有名な句「私の抱える問題には二種類ある——緊急なものと重要なもの。緊急なものは重要でなく、重要なものは
  決して緊急ではない」は、Eisenhower が**1954年の演説**で「ある元大学学長」の言葉として引用したもの
  （演説内では**発言者を匿名で紹介**。後年 Northwestern 大学学長 J. Roscoe Miller への名指しが流布したが
  一次資料での確証は弱い）。**Eisenhower 自身は2×2マトリクスを作っていない**。今日の「時間管理マトリックス」＝
  4象限グリッドは **Stephen R. Covey** が『7つの習慣』(1989) の第3の習慣「最優先事項を優先する」で定式化し、
  続編『First Things First』(1994) で詳述した。「Eisenhower Matrix」は後年に広まった通称。
  **起源は断定せず、通説と不確実性を前提に扱う**（→出典・要確認項目参照）。

## いつ使う / 使わない

**使う（適する状況）**
- タスクが多すぎて**何から手をつけるか分からない**、頭の中が渋滞しているとき。
- 一日中**火消し（Q1）や割り込み（Q3）に追われ**、重要な仕事が前に進まないと感じるとき。
- 個人・チームの**ToDoやプロジェクトの優先順位づけ**をしたいとき。
- 重要だが緊急でない投資（計画・勉強・健康・人間関係・仕組み化）の**時間を確保したい**とき（Q2確保）。
- 週次・日次で**時間配分を棚卸し・レビュー**し、緊急に流されていないか点検したいとき。

**使わない / よくある誤用（アンチパターン）**
- **仕分けて満足し、行動が変わらない（実装ギャップ）**——最頻の失敗。5分で理解でき象限に振り分けられるが、
  「Do First に置く」ことと「実際にやる」ことは別。仕分け後に**行動と時間割り当て**へ必ず落とす。
- **緊急の罠(Mere Urgency Effect)**——Zhu, Yang & Hsee (2018) は、報酬が小さくても締切の短いタスクを
  報酬の大きい重要タスクより優先する傾向を実証した。Q3をQ1と混同し、緊急なだけの雑務に一日を溶かす。
- **主観・勘での分類**——待てる仕事が「緊急」に、締切があるだけの雑務が「重要」に膨張する。
  **重要度は目標・使命という外部基準に照らして判定**する（勘で貼らない）。
- **借り物の緊急性(borrowed urgency)**——他者の都合・古い慣習・惰性で「緊急」に見えるだけの場合がある。
  ラベルを貼る前に「本当に締切と実害があるか」を問い直す。
- **Q1過積載・Q2放置**——すべてが緊急に見えQ1が肥大。やらなかった予防(Q2)が将来の危機(Q1)に化ける。
- **2軸だけで押し切る**——工数・ROI・依存関係など他の判断材料を捨象する。2軸で足りなければ他フレームで補う。
- **緊急対応が本業の反応型ロール**（カスタマーサポート・IT ヘルプデスク・オンコール等）には不向き。
  全件を4象限化するより**重大度別トリアージ**（重大度レベル・応答時間目標）の方が速い。

## 前提と限界

- **前提**: 「重要」を判定するための**基準（目標・使命・価値）が先に定まっている**こと。基準がないと
  重要度は勘に堕ち、マトリクス全体が崩れる（後述の手順①②が要）。判定対象のタスクを**漏れなく洗い出せる**
  ことも前提（隠れたタスクは仕分けできない）。
- **限界（批判を踏まえて）**:
  - **静的で陳腐化しやすい**——緊急度は速く変わる（月曜にQ3が木曜にQ1になる）。定期メンテ前提で使う。
  - **2軸への還元**——重要度・緊急度以外の基準（工数・費用対効果・所要時間・依存関係）が落ちる。
    大きなタスクは1マスに置くだけでは動けず、分解や別軸での評価が要る。
  - **分類が動機に直結しない**——「重要と分かっているのにやれない」構造（緊急の罠・先延ばし）は
    仕分けだけでは解けない。Q2を**カレンダーに先取りブロック**するなど行動設計で補う必要がある。
  - **象限の境界は連続的**——緊急/重要は二値でなく程度問題。境界付近のタスクは判定がぶれる。
- これらの限界は、**「重要」の基準を目標・指標で固める（kgi-kpi-okr）／効果×実現性の別軸で絞る（payoff-matrix）／
  週次レビューで回し続ける（pdca）**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。

1. **目的とスコープを定める。** 「何のための優先順位づけか」（今週の仕事／プロジェクト／人生の時間配分）と
   対象期間・粒度を1つに決める。なぜ: 混在すると象限がノイズだらけになり判定できない。
2. **「重要」の判断基準を先に固定する。** 自分/チームの目標・使命・価値を明文化し、「重要=これに寄与するか」の
   物差しにする。なぜ: 基準がないと重要度が勘で膨張する（誤用の筆頭）。基準が曖昧なら先に目標設定を行う。
3. **タスク・活動を全部洗い出す。** 頭の中・受信箱・カレンダーから抱えている項目を残さず書き出す。
   なぜ: 隠れたタスクは仕分けできず、優先順位が現実とずれる。
4. **重要度を先に、緊急度を後に判定する。** 各タスクに「①目標に寄与するか（重要度）→②遅延に実害/締切があるか
   （緊急度）」の順で問う。なぜ: 緊急度から入ると緊急の罠にはまり、緊急なだけの雑務を重要と錯覚する。
5. **4象限に配置する。** Q1(緊急×重要)/Q2(重要×緊急でない)/Q3(緊急×重要でない)/Q4(どちらでもない)へ振り分ける。
   なぜ: 可視化して初めて偏り（Q1肥大・Q2空白）が見える。
6. **各象限に行動(4D)を割り当てる。** Q1=今すぐ着手し順に片づける／Q2=カレンダーに時間を先取りブロックする／
   Q3=任せる・断る・仕組みで自動化する／Q4=やめる・減らす。なぜ: 仕分けは手段、行動が目的。ここで止めない。
7. **Q3とQ1を検算する（緊急の罠・借り物の緊急性を疑う）。** 各「緊急」に「本当に締切と実害があるか、
   他者都合や惰性で緊急に見えるだけか」を問う。なぜ: Q3をQ1に誤分類すると一日が緊急な雑務に溶ける。
8. **Q2の時間を先に確保する。** 予防・計画・自己投資(Q2)を、緊急タスクで埋まる前にカレンダーへブロックする。
   なぜ: Q2は緊急でないため放置され、これが将来のQ1危機を生む最大の原因。ここが本フレームワークの肝。
9. **定期的に見直す。** 日次/週次で仕分けを更新し、Q1・Q3に取られた時間とQ2に割けた時間を振り返る。
   なぜ: 緊急度は速く変わり、静的なマトリクスはすぐ現実とずれる。

## 壁打ち質問リスト

各象限を事実で埋めるために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。

1. この優先順位づけで**最終的に達成したいこと・守りたい目標**は何ですか？（＝「重要」を測る基準を1つに定める）
2. いま抱えている**タスク・気になっていることを全部**挙げると何がありますか？（頭の中・受信箱・カレンダーから棚卸し）
3. 各タスクは、その**目標・使命にどれだけ寄与**しますか？やらないと長期でどんな損失が出ますか？（重要度の判定材料）
4. その「緊急」は本当に**締切と実害**がありますか？それとも他者都合・古い慣習・惰性で緊急に見えるだけですか？（借り物の緊急性の検出）
5. 一日の時間のうち、**Q1(火消し)とQ3(割り込み)にどれだけ取られて**いますか？Q2(重要な投資)に割けている時間は？
6. Q3(緊急だが重要でない)のうち、**任せられる相手・断れる相手・仕組みで自動化できるもの**はありますか？
7. 重要だが緊急でないこと(Q2: 計画・勉強・健康・関係づくり)で、**後回しにし続けている**ものは何ですか？
8. すでに事実として分かっている締切・依存関係は何で、まだ**確認できていない前提**は何ですか？（推測と事実を分ける）

## 出力フォーマット

ALWAYS この2段構えで出力する（仕分け→行動計画）。命令形で埋める。

```
【仕分け】目的: <達成したいこと/重要度の基準> ／ 対象期間: <今週/このプロジェクト等>
  Q1 緊急×重要（Do 今すぐ）:            - <タスク＋締切/実害>
  Q2 重要×緊急でない（Schedule 予定化）: - <タスク＋なぜ重要か>  ← 最も投資すべき象限
  Q3 緊急×重要でない（Delegate 任せる/断る）: - <タスク＋誰に/どう断る>
  Q4 どちらでもない（Delete やめる）:    - <タスク＋やめ方>

【行動計画】
  今すぐ(Q1):   <着手順・締切順>
  予定化(Q2):   <カレンダーに先取りブロックする時間帯>
  任せる/断る(Q3): <委任先・断り方・自動化案>
  やめる(Q4):   <やめる/減らすもの>

【検算】<Q1に化けそうなQ2予防／借り物の緊急性で外したQ3／緊急の罠に注意する点>
【次の一手】<最初の1アクションと、次に見直すレビュー日>
【未確認の前提】<締切・依存関係・重要度基準で事実確認が要る点（壁打ちで埋める）>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。あるチームリーダーが、日々の割り込み対応に追われ、
来期の計画づくりが進まない場面。

- **手順①目的**: 「今週の時間を、来期の成果につながる形で配分する」。対象=今週の自分のタスク。
- **手順②重要の基準**: 「チームの来期目標の達成に寄与するか」を重要度の物差しに固定する。
- **手順③棚卸し**: 顧客からのクレーム対応、来期計画の作成、定例会議への出席依頼、部下の育成面談、
  受信トレイの通知処理、業界ニュースのだらだら閲覧——などを全部書き出す。
- **手順④重要度→緊急度で判定**: 「来期計画」は目標に強く寄与（重要）だが今日の締切はない（緊急でない）。
  「クレーム対応」は重要かつ緊急。「通知処理」は緊急に見えるが目標への寄与は薄い。
- **手順⑤配置**:
  - Q1(緊急×重要): 顧客クレーム対応。
  - Q2(重要×緊急でない): 来期計画の作成、部下の育成面談。
  - Q3(緊急×重要でない): 出席必須でない定例会議、受信トレイの通知処理。
  - Q4(どちらでもない): 業界ニュースのだらだら閲覧。
- **手順⑥⑦⑧行動(4D)＋検算＋Q2確保**:
  - Do(Q1): クレームに今すぐ着手。
  - Schedule(Q2): 来期計画に**先に**カレンダーの午前ブロックを確保（緊急に埋められる前に）。
  - Delegate/断る(Q3): 定例会議は議事録共有に切替を打診、通知処理は時間帯を決めてまとめ処理。
  - Delete(Q4): だらだら閲覧はやめ、情報収集は目的を持って短時間に限定。
  - 検算: 「定例会議は本当に自分が緊急に出る必要があるか（借り物の緊急性）」を疑い、Q3へ落とせた。
- **手順⑨次の一手**: 「来期計画のQ2時間ブロックを今日カレンダーに入れる」を最初の1アクションにし、金曜に振り返る。
- **未確認の前提**: クレームの実際の締切、定例会議を欠席してよいか——ここは事実確認してから確定する（推測で進めない）。

## 相性（組み合わせると効く）

- `kgi-kpi-okr`: 「重要」の基準（目標・指標）を先に定め、重要度判定の主観を減らす前工程。手順②を強化する。
- `payoff-matrix`: 効果×実現性という別の2軸。Q1/Q2内にタスクが多いとき、さらに絞り込む続きに使う。
- `decision-matrix`: 緊急度・重要度の2軸で足りず、複数の評価軸で選択肢を採点したいときへ拡張する。
- `pdca`: 週次レビューで仕分けを回し続ける実行ループ。緊急度の変化に追随し、静的化（陳腐化）を防ぐ。
- `logic-tree`: Q1/Q2の大きなタスクを、着手可能な単位へ分解して1マスに置けるようにする。
- 揺さぶり枠として `premortem`（Q2の予防を怠った未来の失敗を先回りし、Q2着手の動機にする）や
  `devils-advocate`（「本当に緊急か/重要か」を反対役で疑い、借り物の緊急性・錯覚の領域Q3を暴く）を添えると
  「緊急の罠」への耐性が増す。
