# 形態分析法（Morphological Analysis）

## 概要

形態分析法は、対象（商品・サービス・仕組み・問題）を**互いに独立した少数のパラメータ（軸／独立変数）**に分解し、
各パラメータが取りうる**値（選択肢）**を列挙して、それらの**組み合わせ**の総体からアイデアを体系的に生み出す発想法。
組み合わせを一覧化した多次元の表を **形態フィールド（morphological field）／形態ボックス（Zwicky box）／形態分析表** と呼ぶ。

| | 選択肢1 | 選択肢2 | 選択肢3 | … |
|---|---|---|---|---|
| **パラメータA** | A1 | A2 | A3 | |
| **パラメータB** | B1 | B2 | B3 | |
| **パラメータC** | C1 | C2 | C3 | |

- **核となる考え方**: 各パラメータから値を1つずつ選ぶ「経路」が1つのアイデア案になる。人は無意識に「いつもの組み合わせ」しか見ないが、
  表にすると**まだ試していない組み合わせ（空白のセル経路）**が可視化され、発想の抜け漏れと固定観念を破れる。
- **総当たりで終わらせない（最重要）**: 単純な全組み合わせは膨大になる（組み合わせ爆発）。矛盾する値の組を消し込む
  **クロス整合性評価（Cross-Consistency Assessment, CCA）**で、非現実的な組み合わせを削り、内的に整合した「解空間」に絞る。
  ここが「ただの総当たり表」と「使える発想法」の分かれ目。
- **出自（諸説あり・要確認）**: カリフォルニア工科大学(Caltech)の天体物理学者 **Fritz Zwicky（フリッツ・ツヴィッキー）** が
  **1940年代**頃に体系化したとされる（航空宇宙・天文だけでなく政策・倫理にも適用）。ただし開発年代は資料により幅がある。
  CCA という手続き・用語は後年 **Tom Ritchey**（スウェーデン形態分析学会）が整備したもので、Zwicky 本人の原典用語ではない。
  **年代・団体名・帰属は断定せず要確認扱い**にする（→出典・要確認）。

## いつ使う / 使わない

**使う（適する状況）**
- 新商品・新サービス・新コンセプトを、**要素の組み合わせから体系的に発想**したいとき。
- アイデアが**既存の延長でマンネリ化**し、「まだ試していない組み合わせ」を見つけたいとき。
- 思いつきや声の大きい人に頼らず、**発想の網羅性（抜け漏れの無さ）を担保**したいとき。
- パラメータ間に因果より**論理的関係**があり、定量モデルが効きにくい非定量・複雑な問題。
- 属性列挙・ブレストで出た要素を、**掛け合わせて構造的に展開**したいとき。

**使わない / よくある誤用（アンチパターン）**
- **CCAを省いて総当たりで放置**——最頻の失敗。5軸×各4値でも 4^5=1,024 通りと爆発し、手に負えなくなる。
  必ず矛盾組を消し込んで解空間を絞る。数値上は10万超の構成でも、ペア評価は二次関数的にしか増えないので絞り込みは可能。
- **疑似網羅（pseudo-completeness）の罠**——「全部洗い出した」と錯覚しつつ、無意識に**自分の好きな案を正当化する形**で
  表を組んでしまう。値の列挙で「理論上は可能な変わり種／他業界の値」を必ず入れて、都合の良い箱にしない。
- **パラメータが独立でない**——値Xを他パラメータの全値と自由に組み合わせられないなら、その軸は独立でない。
  依存した軸を並べると表が破綻し、組み合わせが意味を持たなくなる（後述の独立性テストで弾く）。
- **軸/値の網羅に失敗**——重要な軸や選択肢が抜けると、以降の探索全体が不完全になる。列挙は発散、評価は後で分離する。
- **創造フェーズに実現性・コストを持ち込みすぎる**——値の列挙段階で「無理」と切ると発想が縮む。実現性評価はCCA/後工程に回す。
- 相互依存が強く分解できない問題、定量最適化・因果分析が適する問題、軸が自明で少数な小規模発想には不向き（素朴なブレストで足りる）。

## 前提と限界

- **前提**: 対象と「発想のゴール（何のためのアイデア出しか）」が1つに定まっていること。ゴールが曖昧だと軸が発散し、表が意味を失う。
  対象を**独立したパラメータに分解できる**こと（分解できない一枚岩の問題には使えない）。
- **限界（批判を踏まえて）**:
  - **組み合わせ爆発**——軸・値を増やすほど構成数は指数的に増える。CCA と優先順位づけで縮約しない限り実用にならない。
  - **疑似網羅と恣意性**——「網羅した」外見に反し、軸・値の選び方に作り手のバイアスが入る。誤った意思決定を自動では防げない
    （工学設計の実証研究でも「産業実務に定着しづらく、教育現場で不適切適用されがち」と批判される）。
  - **軸の独立性の担保が難しい**——現実の要素は絡み合う。独立に見えて依存している軸を見抜けないと表が破綻する。
  - **値の粒度が揃わない**——抽象度がバラバラの値を並べると組み合わせが噛み合わない。粒度を揃える。
- これらの限界は、**CCAを必ず回す / 属性の洗い出しを attribute-listing で厚くする / 残った案を payoff-matrix・decision-matrix で
  客観評価する / premortem・reverse-assumption で揺さぶる**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。分析（分解）→ 整合性評価 → 統合（絞り込み）の3局面で回す。

1. **問題をオープンな問いに定義する。** 「〜のための新しい○○はどんな形があり得るか？」と、答えを狭めない問いにする。
   なぜ: 最初から解を絞ると発想が縮む。この段階では財務・技術的実現性を意図的に脇に置く（評価は後工程）。
2. **独立したパラメータ（軸）を洗い出す。** 対象を構成する本質的な次元を **5〜7個**を目安に挙げる（機能・形状・素材・対象者・
   提供方法・場面など）。まず各自で黙って書き出し→統合すると偏りが減る。
   なぜ: ここが最も誤りが起きやすい肝。軸は後の全経路を規定する。抽象度を揃え、目的に効く軸を選ぶ。
3. **軸の独立性を検算する。** 各軸について「この軸の値を、他の軸の全値と自由に組み合わせられるか？」を問う。No なら独立でない
   ——軸を統合/再定義する。なぜ: 依存した軸を並べると組み合わせが破綻し、表が嘘をつく。
4. **各パラメータの値（選択肢）を列挙する。** 1軸あたり **3〜5個**を目安に、①既存の選択肢 ②理論上は可能な変わり種
   ③他業界・他文脈からの値、を混ぜて出す。なぜ: 既存値だけだと「いつもの箱」になり疑似網羅に陥る。粒度は揃える。
5. **形態分析表（形態ボックス）を作る。** 軸を行、値を列に並べ、全体の発想空間を一覧化する。
   なぜ: まだ試していない組み合わせ（空白）が可視化され、探索の抜け漏れが分かる。
6. **クロス整合性評価（CCA）で矛盾組を消す。** 全パラメータ**値のペア**を総当たりで見て、両立できるかを ✓（整合）/
   ×（矛盾）/ ?（条件付き）で判定する。矛盾は3種——**論理的矛盾**（同時に成立不能）/ **経験的矛盾**（現実に成立しない）/
   **規範的矛盾**（戦略・規制・倫理に反する）。なぜ: ペア評価は軸を増やしても二次関数的にしか増えず、指数的な全構成を
   現実的な手間で絞り込める。※最初のCCAでは「好き嫌い（規範判断）」を持ち込みすぎない——先に論理・経験の矛盾で削る。
7. **整合する組み合わせ経路を抽出する（統合）。** 各軸から値を1つずつ選び、×を含まない経路を「アイデア案」として取り出す。
   なぜ: 矛盾を除いた「解空間」の中にこそ、現実的で新しい組み合わせが残る。
8. **有望案を優先順位づけして絞る。** 残った案を新規性・実現性・目的適合などの軸で相対比較し、**3〜5案**に絞って次に進める。
   なぜ: 形態分析はアイデアを「出す」ところまで。選抜と磨き込みは payoff-matrix / decision-matrix / PMI 等の後工程に渡す。

## 壁打ち質問リスト

各要素を埋めるために、利用者へ投げ返す問い。空欄を勝手に埋めず、まずこれで引き出す。

1. この発想で**最終的に生み出したいもの**は何ですか？（新商品／新サービス／新しい仕組み／課題の打開策など、対象とゴールを1つに）
2. その対象を分解するなら、**どんな軸（次元）**で説明できますか？（例: 機能・形状・素材・対象ユーザー・提供方法・利用場面）5〜7個挙げるとどれですか？
3. 挙げた軸は**互いに独立**していますか？——「Aの値を、Bのどの値とも自由に組み合わせられるか」を確かめると、どこが依存していますか？
4. 各軸について、**今世の中にある選択肢**は何ですか？そして**まだ誰もやっていない/他業界にはある選択肢**を足すと、どんな値が入りますか？
5. 組み合わせの中で、**論理的・現実的にあり得ない（矛盾する）ペア**はどれですか？逆に、**意外だが両立しそうなペア**は？
6. アイデアを絞る際に**重視する基準**は何ですか？（新規性／実現性／コスト／自社の強みとの相性／市場性）
7. 既に「これしかない」と思い込んでいる**前提の組み合わせ**はありますか？それを1つ**あえて外す/反転させる**と、どんな案が見えますか？

## 出力フォーマット

ALWAYS この3段構えで出力する（分解 → 整合性評価 → 有望案）。総当たり表を出して終わりにしない。

```
【形態分析表（分解）】ゴール: <生み出したいもの> ／ 対象: <…>
  パラメータA(<軸名>):  A1 <値> | A2 <値> | A3 <値> | …
  パラメータB(<軸名>):  B1 <値> | B2 <値> | B3 <値> | …
  パラメータC(<軸名>):  C1 <値> | C2 <値> | C3 <値> | …
  （軸は5〜7個・各3〜5値目安／軸は独立・値は粒度を揃える）

【クロス整合性評価（CCA）】除外した矛盾ペア:
  - <値X> × <値Y> = ×（論理/経験/規範のどれか＋理由）
  - <値P> × <値Q> = ?（条件付き：<条件>なら可）

【有望なアイデア案（整合経路）】※×を含まない組み合わせを2〜4案
  案1: A? + B? + C? + … → <一言コンセプト／新しさの核>
  案2: …
  案3: …

【次の一手】<選抜基準で3〜5案に絞る／検証すべき仮説・試作>
【未確認の前提】<軸の独立性・値の網羅・実現性で確かめる点（壁打ちで埋める）>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。「新しい傘（雨具）のコンセプトを発想する」場面。

- **手順①問い**: 「持ち歩きたくなる新しい傘はどんな形があり得るか？」（実現性・コストは一旦棚上げ）。
- **手順②③軸（独立性を確認して選定）**: **構造** / **携帯性** / **付加機能** / **主な対象** / **入手方法** の5軸。
  「構造」と「携帯性」は独立か？——長傘でも折り方次第で携帯性は変えられるので概ね独立、と判断。
- **手順④値の列挙（既存＋変わり種＋他業界）**:
  - 構造: 標準骨 / 逆折り（内側にたたむ）/ ドーム型 / 骨なし（新素材）
  - 携帯性: 長傘 / 折りたたみ / 極小（手のひら）/ ウェアラブル一体
  - 付加機能: なし / 送風・速乾 / 発光・反射（安全）/ センサー（雨予測連動）
  - 主な対象: 通勤者 / 子ども / 高齢者 / アウトドア
  - 入手方法: 購入 / サブスク / 街中シェア / 使い捨て
- **手順⑤形態分析表**: 上記を行×列で一覧化（4×4×4×4×4 は理論上多数）。空白の経路＝未探索の組み合わせが見える。
- **手順⑥CCA（矛盾を消す）**:
  - 「使い捨て」×「センサー内蔵」= ×（経験的：コスト・環境面で両立しにくい）。
  - 「街中シェア」×「発光・反射（安全）」= ?（条件付き：紛失・破損管理ができれば可）。
  - 「高齢者」×「ウェアラブル一体」= ?（条件付き：操作が簡単なら可）。
- **手順⑦整合経路（案）**:
  - 案1: ドーム型 + 折りたたみ + 発光・反射 + 子ども + 購入 → 「視認性で守る通学用ドーム傘」。
  - 案2: 骨なし新素材 + 極小 + センサー連動 + 通勤者 + サブスク → 「雨予測と連動する常時携帯ミニ傘の定期便」。
- **手順⑧絞り込み**: 新規性×自社の作りやすさで2案を比較し、まず案2を試作仮説として選ぶ。
- **未確認の前提**: 「センサー連動」の技術的成立性、サブスクの需要——ここは実データ/試作で裏取りが要る（思い込みで進めない）。

## 相性（組み合わせると効く）

- `attribute-listing`: 対象を属性に分解する姉妹技法。**手順②③（軸出し）**の前工程として、パラメータ候補を厚く洗い出す。
- `osborn-checklist` / `scamper`: 各セルの**値（選択肢）を発想で埋める**補助。既存値に「代用/結合/逆転」等の変換をかけ変わり種を足す。
- `mandala-chart`: 軸と値を放射状に広げ、抜けている選択肢を炙り出す発散の相棒。
- `payoff-matrix`: 残った有望案を**効果×実現性**で二次元評価し、絞り込む後工程（手順⑧の実装）。
- `decision-matrix`: 有望案を複数の評価軸で採点して1案に決める、より精緻な後工程。
- `triz`: CCAで「矛盾ペア」が出たとき、その技術的矛盾を**発明原理で解消**して両立案を作る接続先。
- 揺さぶり枠として `reverse-assumption`（当然視している値の組み合わせを反転）や `premortem`（選んだ案が失敗する要因を先回り）、
  `devils-advocate`（疑似網羅・都合の良い箱化を疑う）を1つ添えると、思い込みの箱を壊せる。
