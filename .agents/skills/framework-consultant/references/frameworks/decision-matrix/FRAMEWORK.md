# 意思決定マトリクス

## 概要

意思決定マトリクスは、**複数の選択肢（行）** を **複数の評価基準（列）** に対して採点し、
基準の**重要度（重み）**で加重して合計することで、「どの案が最も良いか」を体系的に比較する意思決定支援ツール。
複雑で属人的になりがちな選択を「測れる次元」に分解し、トレードオフを一枚の表で見える化して**説明可能**にする。

|  | 基準1（重み） | 基準2（重み） | … | 加重合計 |
|---|---|---|---|---|
| **案A** | 素点×重み | 素点×重み | … | Σ |
| **案B** | 素点×重み | 素点×重み | … | Σ |

- **核となる考え方**: 各セルの `加重点 = 素点 × 重み` を選択肢ごとに合計し、最大の案を第一候補とする（加重加算型）。
  重要なのは「点数を出すこと」自体でなく、**基準・重み・採点を明示して合意し、トレードオフと選定根拠を残す**こと。
- **別名（同じ道具の呼び分け）**: 加重決定マトリクス / 加重スコアリングモデル / Pughマトリクス /
  グリッド分析（Grid Analysis）/ 選定マトリクス / 多基準意思決定分析（MCDA/MCDM）。ASQは「L字型マトリクス」の一種とする。
- **出自（諸説あり・要確認）**: 概念選択マトリクスは **Stuart Pugh**（英国の設計工学者、生没年 1929–1993 とされる）が
  体系化。1981年 ICED（国際工学設計会議・ローマ）の論文 "Concept Selection – A Method that Works" に始まり、
  1991年の *Total Design* で整理された（表題・年号は要確認）。ただし**Pugh原法は非数値**——基準案（datum）に対し
  各案を **+（優る）/ −（劣る）/ S（同等）** で相対評価し、収束と発散を反復する「controlled convergence（制御された収束）」。
  一方、本スキルが主に扱う**加重数値型はPugh単独の発明ではなく**、より広い意思決定分析（MCDA/MAUT/Kepner-Tregoe 等）と
  重なる系譜。両系統を前提に扱う（→出典・要確認）。

## いつ使う / 使わない

**使う（適する状況）**
- **離散した複数の選択肢**（ツール/業者/候補地/採用候補/施策案/事業案など）から**1つ（少数）を選ぶ**とき。
- **競合する複数の基準**（コスト・効果・スピード・リスク・実現性…）があり、単一の物差しでは決められないとき。
- 「なんとなく」で決めず、**上司・チーム・顧客に選定根拠を示す**必要があるとき（属人性・声の大きさを排したい）。
- 全案が甲乙つけ難く、**トレードオフを明示的に俯瞰**して合意形成したいとき。

**使わない / よくある誤用（アンチパターン）**
- **選択肢がまだ無い/貧しい**——選ぶ前に案を作る段階なら発想系（brainstorming/scamper 等）が先。マトリクスは"選ぶ"道具。
- **点数の合計を絶対視する**——最頻の失敗。**些末な基準が積み重なって必須要件を上回り**、致命的欠陥のある案が多数の小加点で
  1位になる（補償型集計の罠）。必ず必須条件で足切りし、僅差は感度チェックで「決まらない」と扱う。
- **結論を先に決めて重み・採点を逆算する**——motivated reasoning。基準と重みは**採点の前に**確定・合意する。
- **疑似的な精度感**——素点は測定でなく主観的見積り。小数点以下の差に意味を持たせない。「当て推量に精密な演算」を戒める。
- **順位逆転（rank reversal）を無視**——選択肢の追加・削除や尺度・正規化の変更で残りの順位が入れ替わりうる（独立性公理IIAに反する）。
  1位が入れ替わる程度の僅差なら、マトリクスだけで断定しない。
- 単一の支配的基準しかない/基準が強く相互作用する/不確実性が大きくシナリオ・意思決定木が要る場合には不向き。

## 前提と限界

- **前提**: (1) 比較する**選択肢が出そろっている**、(2) **評価基準が洗い出せる**（できれば MECE で重複・漏れを抑える）、
  (3) 各案を各基準で**採点できる材料（データ・見積り）がある**。材料が薄い基準は壁打ちで埋めるか、素点に確信度を添える。
- **限界（批判を踏まえて）**:
  - **基準選定が恣意的**——網羅性の保証がなく、何を基準に入れる/入れないかで結論が動く。
  - **補償型集計の欠陥**——加重加算は「弱みを他の強みで埋め合わせ」できてしまう。必須条件（must-have）は
    加点で救えないため、**先に足切り（knockout gate）**で外す。
  - **重みの主観・操作性**——重みを弄れば結論を正当化できる。だからこそ採点前に固定し、根拠を残す。
  - **順位逆転・手法依存**——加重加算/TOPSIS/AHP 等で同一データでも順位が食い違う、選択肢の増減で順位が動くことがある。
  - **静的で不確実性に弱い**——時間変化・相互作用・確率を織り込めない。
- これらは、**必須条件の足切り＋感度分析で補い、選定後は premortem / devils-advocate で1位案を stress-test する**ことで
  緩和できる（→相性）。マトリクスは「決める道具」でなく「**思考を構造化し、根拠を残す**道具」と捉える。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。加重数値型を基本とし、初期スクリーニングには Pugh の datum 相対型も使う。

1. **決めたいこと（意思決定の問い）と選択肢を確定する。** 「何を選ぶのか」を一文にし、比較する案を2〜6個に絞って行に並べる。
   なぜ: 問いが曖昧だと基準も採点も発散する。案が多すぎると比較が破綻するので、明らかに劣るものは事前に落とす。
2. **評価基準を洗い出し、列にする（目安3〜8個）。** 目的に効く観点を MECE に。重複・漏れ・粒度不揃いを削る。
   なぜ: 基準の質がマトリクスの質を決める。似た基準の重複は、その観点を二重に重みづけしてしまう。
3. **必須条件（must-have）を分離し、先に足切りする。** 満たさなければ即失格の条件で候補を絞る。
   なぜ: 加点で救えない要件を採点に混ぜると、補償型集計で致命的欠陥が覆い隠される（最頻の誤用の防波堤）。
4. **各基準に重みを付ける（採点の前に確定）。** 例: 1〜5 や 1〜10。重要度の根拠（誰が/なぜ）を残す。合計を一定にする配分法でもよい。
   なぜ: 採点後に重みをいじると結論の逆算になる。重みは意思決定の"価値観"そのものなので、ここで合意する。
5. **採点尺度の向きを揃える。** 高得点＝常に望ましい（コスト等は「安いほど高得点」に反転して定義）。
   なぜ: 向きが混在すると合計が意味を失う。「高い＝良い」で統一して初めて加算が正しくなる。
6. **列方向（基準ごとに全案を横断）で採点する。** 1つの基準で案A・B・Cを続けて比較してから次の基準へ。確信度が低い素点は印を付ける。
   なぜ: 1案ずつ縦に採点するとハロー効果・アンカリングで甘辛が伝播する。横断採点が相対評価の精度を上げる。
7. **加重点＝素点×重みを計算し、案ごとに合計する。** 表に加重点と合計を書き出す。
   なぜ: ここで初めてトレードオフが可視化される。合計だけでなく「どの基準で勝ち、どこで負けたか」を読む。
8. **感度分析で結論の頑健さを確かめる。** 上位案が僅差なら、重みや確信度の低い素点を少し動かして順位が変わるか試す。
   なぜ: 僅差の1位は誤差の産物かもしれない。動かして順位が反転するなら「マトリクスは決めない」と判断する。
9. **結論と根拠を残し、次の一手へ。** 選んだ案・僅差だった論点・未確認の前提・追加検証すべき点を明記する。
   なぜ: マトリクスはゴールでなく合意と説明のための土台。根拠を残さなければ再現も再議論もできない。

> **Pugh datum型（初期スクリーニング）**: 基準案（datum、既存案でよい）を置き、各案を各基準で **+/−/S** で相対評価し、
> `スコア = Σ(+) − Σ(−)`。強い要素を組み合わせ、弱い案を落として datum を更新し反復する（controlled convergence）。
> 数値の精度を装わずに素早く絞りたいとき、または重みの合意が難しいときに有効。

## 壁打ち質問リスト

各要素を事実で埋めるために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。

1. この意思決定で**最終的に決めたいこと**は何ですか？（何を1つ選ぶのか、いつまでに、誰が決裁するか）
2. 比較する**選択肢**は何と何ですか？その中に、比較するまでもなく**必須条件を満たさず失格になる案**はありませんか？
3. 「良い選択」を分ける**評価基準**は何ですか？（コスト/効果/スピード/リスク/実現性/戦略適合など）——重複や抜けはありませんか？
4. その基準のうち、**絶対に妥協できない必須条件（must-have）**と、**あると嬉しい程度（nice-to-have）**を分けるとどうなりますか？
5. 各基準の**重要度（重み）**は？——なぜその重みなのか、誰の価値観・どの目標に基づきますか？（採点前に確定したいので）
6. 各案を各基準で採点する**根拠となるデータ・実績・見積り**はありますか？ 確信が持てない（当て推量の）セルはどれですか？
7. もし上位2案が**僅差**だったら、どの基準の重みや点数が動けば結論が変わりますか？（感度チェックの当たりをつける）
8. この表に**表れていない要素**（定性的な直感、政治的制約、時間変化、案同士の相互作用）はありませんか？

## 出力フォーマット

ALWAYS この2段構えで出力する（採点→判定と感度チェック）。数値は**手順説明用の例示**であり、確定値でないことを明示する。

```
【意思決定マトリクス（採点）】決めたいこと: <一文> ／ 決裁者・期限: <…>
  必須条件の足切り: <満たさず失格にした案と理由／無ければ「なし」>

  | 選択肢＼基準(重み) | 基準1(w1) | 基準2(w2) | … | 加重合計 |
  |---|---|---|---|---|
  | 案A | 素点(→加重) | … | … | Σ |
  | 案B | 素点(→加重) | … | … | Σ |
  ※尺度: 素点は<0〜5 等・高いほど望ましい向きに統一>。確信度の低いセルには(?)を付す。

【判定と感度チェック】
  第一候補: <合計最大の案> ／ 次点との差: <僅差か明確か>
  勝因・敗因: <どの基準で差がついたか（合計だけでなく内訳を読む）>
  感度: <重み/素点を動かすと順位が変わるか。変わるなら「マトリクスは決めない」>

【次の一手】<選定の確定 or 追加検証すべき仮説・データを1〜3個>
【未確認の前提】<当て推量だったセル・表に入れられていない定性要素（壁打ちで埋める）>
```

## 具体例（ワークスルー）

一般化した例（特定企業・実データではなく、手順を示すための**例示値**）。チームで使う業務ツールを3案から選ぶ場面。

- **手順①問い・選択肢**: 「チームの案件管理ツールをどれにするか」。候補=案A/案B/案C（既存併用の案Aを datum とする）。
- **手順②基準**: 「機能適合」「使いやすさ」「コスト」「導入負荷」「セキュリティ要件適合」を列に。粒度・重複を確認。
- **手順③足切り**: 「セキュリティ要件適合」を必須条件に格上げ。要件を満たさない案があれば**採点前に失格**にする（この例では全案通過）。
- **手順④重み**: 目的（納期遵守の改善）に効く順に、機能適合=5・使いやすさ=4・コスト=3・導入負荷=2 と合意（**採点前に確定**）。
- **手順⑤尺度**: 0〜5、高いほど望ましい。コストは「安いほど高得点」に反転して定義。
- **手順⑥⑦採点と加重**（例示値。列＝基準ごとに横断採点）:
  - 案A: 機能4×5＋使い3×4＋コスト2×3＋導入5×2 = 20+12+6+10 = **48**
  - 案B: 機能5×5＋使い4×4＋コスト2×3＋導入2×2 = 25+16+6+4 = **51**
  - 案C: 機能3×5＋使い5×4＋コスト4×3＋導入4×2 = 15+20+12+8 = **55**
- **手順⑧感度**: 案Cと案Bは僅差（55対51）。機能適合の重みを動かして再計算すると、5→6 で B=56/C=58（まだC優位）、
  7 で 61対61 の同点、8 で B=66/C=64 と逆転する。**「機能重視か使いやすさ重視か」で結論が動く**——
  ここが本当の論点だと判明する（点数ではなく価値観の問題。感度分析の結論は必ず再計算で確かめる）。
- **手順⑨結論**: 「使いやすさ・コスト重視なら案C、機能最優先なら案B」。次の一手=機能適合の重みをチームで再合意し、案B/Cを短期トライアル。
- **未確認の前提**: 各案の「使いやすさ」素点は試用前の見積り（当て推量）。実地トライアルで裏取りが要る（推測のまま確定しない）。

## 相性（組み合わせると効く）

- `mece`: 評価基準（列）を漏れ・ダブりなく設計する前工程。基準の重複は二重重みづけの元なので特に有効。
- `payoff-matrix`: 効果×実現性の2軸で選択肢をざっと絞る軽量スクリーニング。多数案を数個に減らしてから本マトリクスへ。
- `eisenhower-matrix`: 「選ぶ」でなく「タスクを緊急度・重要度で並べる」場合はこちら（用途の切り分け＝誤用防止）。
- `pmi`: 各案を Plus/Minus/Interesting で定性評価し、基準に入れ損ねた観点を洗い出す軽い前さばき。
- `kgi-kpi-okr`: 重みの根拠を「どの目標に効くか」に接続し、基準・重みを恣意でなく戦略から導く。
- 揺さぶり枠として `premortem`（選んだ1位案が失敗する要因を先回り）／`devils-advocate`（重み・基準選定と結論の逆算を疑う）／
  `reverse-assumption`（「その基準は本当に要るか」と前提を反転）を添えると、点数の過信を防ぎ洞察が増す。
