# ビジネスモデルキャンバス（Business Model Canvas）

## 概要

ビジネスモデルキャンバス（BMC）は、ビジネスモデル——**組織が価値をどう創造・提供・獲得（capture）するかの論理**——を
**9つの構成要素（building blocks）** に分解し、1枚（ワンページ）で可視化する戦略デザインの共通言語。
穴埋めそのものが目的ではなく、**要素同士の因果と矛盾を議論するための思考ツール**として使う。

9要素は**左右2つのサイド**（顧客側とインフラ側）に分かれ、左右で意味が変わる。中央が価値提案。

| 領域 | ブロック | ざっくり |
|---|---|---|
| **顧客側（右＝価値サイド）** | 顧客セグメント(CS) / 価値提案(VP) / チャネル(CH) / 顧客との関係(CR) / 収益の流れ(RS) | 誰に、どんな価値を、どう届け、どう関係を結び、どう儲けるか |
| **インフラ側（左＝効率サイド）** | 主要リソース(KR) / 主要活動(KA) / パートナー(KP) / コスト構造(C$) | それを支えるために、何を持ち・何をし・誰と組み・いくらかかるか |

- **核となる考え方**: 右側（価値サイド）と左側（効率サイド）が**整合（fit）**して初めてビジネスモデルは回る。
  「誰にどんな価値か（CS×VP）」を軸に、届け方・儲け方・支え方が一貫しているかを問うのがBMCの本質。
- **出自（要確認扱い）**: 9つの building blocks は **2005年ごろ Alexander Osterwalder** が提案したとされる。
  指導教官 **Yves Pigneur** の下での博士研究「business model ontology」が土台。書籍 **『Business Model Generation』(2010)**
  （Osterwalder・Pigneur、Tim Clark 編、45か国470人の実務家の貢献とされる）で普及し、**Strategyzer 社**が
  Creative Commons で配布。年号・人数・書誌の細部は二次情報が多く、**断定を避け要確認扱い**とする（→出典・要確認項目）。
- **大物のため詳細を退避**: 9ブロック各々の定義・型・埋めるための設問・つまずき所は
  `references/nine-blocks-detail.md` にある。壁打ちで深掘りするブロックが決まったら、そこの設問を使う。

## いつ使う / 使わない

**使う（適する状況）**
- **新規事業の全体像を1枚で設計**したいとき（アイデアを「どう儲けるか」まで含めて構造化する）。
- **既存事業のビジネスモデルを可視化・診断**し、穴・矛盾・依存を発見したいとき。
- 競合や参入先の**ビジネスモデルを素早く俯瞰・比較**したいとき。
- **チームで事業の共通認識**を作り、議論の土台（共通言語）を1枚に載せたいとき。
- 事業計画・ピッチの**骨格**を、細部の前にまず一望したいとき。

**使わない / よくある誤用（アンチパターン）**
- **穴埋めフォーム化**——最頻の失敗。付箋を貼って写真を撮り、そのままお蔵入り。BMCは「記入する書式」ではなく
  「**議論する思考ツール**」。埋めた後の整合チェックと検証が本体。
- **1枚に複数アイデアを混載**——1キャンバス＝1ビジネスモデル。別セグメント・別モデルは別の1枚に分ける。
- **目的・対象・粒度を決めずに書く**——「何のBMCか（どの事業を・現状か構想か）」が曖昧だと散漫になる。
- **細部の書き込みすぎ**——BMCは重要要素のハイライト。網羅ドキュメントにしない。
- **仮説を検証せず勘で埋める**——マスの中身は「検証すべき仮説」。データ・顧客の声で裏を取らないと机上の空論。
- **顧客セグメントが広すぎ/狭すぎ**——新規起業家の典型ミス。行動・状況で切って絞る。
- 精緻な**財務モデリング**、**競合・競争戦略の分析**、**実行計画/KPI設計**、**顧客課題の深掘り**には単体では不向き。
  他フレーム（5フォース、KPI/OKR、VPC/JTBD 等）で補う（→相性・前提と限界）。

## 前提と限界

- **前提**: 対象事業・目的・粒度（新規の構想か、既存の記述か）が1つに定まっていること。
  外部（顧客・競合・市場）の基礎情報が乏しければ、壁打ちで補うか 3C/PEST を先に回してから持ち込む。
- **限界（批判を踏まえて）**:
  - **静的なスナップショット**——ある時点の一断面で、戦略の変化やモデルの時間発展を捉えない。定期的に描き直す前提で使う。
  - **競争・競争戦略の視点が無い**——業界構造や競合の反応を描かない（概念的に環境から孤立）。**5フォース/3C**で補う。
  - **実行・オペレーションに踏み込まない**——資源配分や具体的な打ち手は別（プランニングの器であり実行計画ではない）。
  - **要素間の相互作用・挙動を規定しない**——マスの並びだけでは因果は出ない。整合チェック（fit）を人が問う必要がある。
  - **財務と顧客充足に偏り**、社会・環境価値を扱わない（拡張版キャンバスで補う議論がある）。
- これらは、**VPC/JTBDで価値提案を深掘り / 5フォース・3Cで競争と外部を補完 / KRの優位性をVRIOで検証 /
  極初期の不確実な事業はリーンキャンバスに置換**することで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。ブロックごとの詳細設問は `references/nine-blocks-detail.md` を使う。

1. **対象と目的を1つに固定する。** 「どの事業の・現状の記述か構想か・何を決めたいか」を明文化する。
   なぜ: 目的が無いと9マスが発散し、穴埋めで終わる最頻の失敗に直結する。1キャンバス＝1モデルを守る。
2. **右側（顧客側）から埋める。** 順序は CS（誰に）→ VP（どんな価値）→ CH（どう届ける）→ CR（どう関係を結ぶ）→ RS（どう儲ける）。
   なぜ: 価値を先に設計するとオペレーションを「価値を届けるため」に作れる。手持ち資源から始めると価値が自社の都合に寄る。
3. **中央のVPをCSと対で検算する。** 「誰の・どの課題（用事）に効くか」を必ずペアで言えるようにする。
   なぜ: 相手不在のVPは空論。刺さり方が曖昧なら Value Proposition Canvas / JTBD で深掘りする。
4. **左側（インフラ側）を埋める。** KR（不可欠な資産）→ KA（中核活動トップ3）→ KP（外部依存の要）→ C$（最大コスト）。
   なぜ: 右側（価値）を支えるために左側がある。まず何を届けるかが決まってから、それを支える体制を設計する。
5. **収益(RS)とコスト(C$)を突き合わせ、採算の型を判定する。** コスト主導（安さで勝つ）か価値主導（高価値で勝つ）か。
   なぜ: VPが強くても薄利では回らない。入り（RS）と出（C$）の整合はモデル成立の最低条件。
6. **整合（fit）を検算する。** CS↔VP／VP↔CH↔CR／RS↔C$／左右のバランスに矛盾が無いかを問い、**最もあやしいマス**を特定する。
   なぜ: BMCの価値は個々のマスでなく、**マス同士の因果と矛盾**にある。ここが分析の核。
7. **仮説と次の一手に落とす。** 各マスは仮説。最も不確実で事業の成否を左右する仮説を選び、検証実験・意思決定に変える。
   なぜ: BMCはゴールでなく起点。埋めて終わると「思考の劇場」で終わる。検証すべきことを1〜3個決めて止める。

## 壁打ち質問リスト

9マスを事実で埋めるために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。
（ブロック別のさらに細かい設問は `references/nine-blocks-detail.md`。）

1. この事業で価値を届ける**最重要の顧客は誰**ですか？（属性でなく行動・状況で。捨てる相手も言えますか）
2. その顧客が抱える**未解決の課題・やりたい用事**は具体的に何で、自社はそれを**どう解決**しますか？
3. 既存の代替手段（競合・自作・我慢）と比べ、**なぜ自社を選ぶ**のですか？その差は顧客が体感できますか？
4. 顧客はこの価値を**どこで知り、どこで買い、どう受け取り**ますか？（認知→購入→提供→アフターのどこが弱い？）
5. 顧客は**何に対して、どう（一括/継続）お金を払い**ますか？どの収益が事業を支えていますか？
6. このモデルを回すのに**絶対に欠かせない資産・活動・提携**は何ですか？（無いと止まるもの）
7. 最も**大きなコスト**は何で、それは「安さで勝つ」設計ですか「高い価値で勝つ」設計ですか？（RSと整合していますか）
8. 9マスの中で、**一番あやしい（未検証で、外れたら事業が崩れる）マス**はどれですか？それをどう確かめますか？

## 出力フォーマット

ALWAYS この2段構えで出力する（1枚俯瞰 → 整合チェックと次の一手）。9マスは埋めて終わりにせず、必ずfitを検算する。

```
【BMC（1枚俯瞰）】対象事業: <何のBMCか> ／ 種別: 新規構想 or 既存記述
  ── 顧客側（価値サイド）──
  顧客セグメント(CS):  - <誰／最重要セグメント（絞る）>
  価値提案(VP):        - <誰の・どの課題に／何の価値（便益）>
  チャネル(CH):        - <認知→購入→提供→アフターの経路>
  顧客との関係(CR):    - <獲得/維持の型（人的/セルフ/自動/コミュニティ等）>
  収益の流れ(RS):      - <何に対し・どう課金（一括/サブスク等）>
  ── インフラ側（効率サイド）──
  主要リソース(KR):    - <不可欠な資産（人/物/知/財）>
  主要活動(KA):        - <中核活動トップ3>
  パートナー(KP):      - <外部に頼る要（依存リスクも）>
  コスト構造(C$):      - <最大コスト／コスト主導 or 価値主導>

【整合チェック（fit）】
  CS↔VP:      <その価値は選んだ顧客に本当に刺さるか>
  VP↔CH↔CR:  <届け方・付き合い方はVPと期待に合うか>
  RS↔C$:      <収益がコストを上回るか（採算の型）>
  左右:        <インフラは価値サイドを支えているか（自社都合に寄っていないか）>
  最大の矛盾/欠落: <一番あやしいマスと、その理由>

【次の一手】<最も不確実で成否を分ける仮説の検証実験・意思決定を1〜3個>
【未確認の前提】<事実確認が要る点（壁打ちで埋める。推測のまま進めない）>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。**地域密着の小規模な語学教室が、オンライン講座への展開を検討する**場面。

- **手順①目的**: 「対面教室のモデルを、オンライン展開でどう組み替えるか」を決める。種別＝新規構想（既存事業の派生）。
- **手順②右側（顧客側）**:
  - CS: 従来は「近隣に住む通学可能な学習者」。オンラインでは「全国の、対面に通えない/都合が合わない学習者」に広がる（＝別セグメント）。
  - VP: 対面の強みは「講師との密な対話と継続の場」。オンラインでは「場所に縛られず、同じ密度の指導を受けられる」ことが価値の芯。
  - CH: 従来は教室・口コミ。オンラインでは自社サイト・オンライン会議ツール・SNSでの認知に変わる（認知〜提供の経路が総入れ替え）。
  - CR: 従来は対面の人的関係。オンラインでは継続を支える仕組み（進捗の可視化・コミュニティ）で密着を代替する必要が出る。
  - RS: 従来は月謝（対面回数ベース）。オンラインでは定額サブスク＋単発講座など、課金の型を選び直す。
- **手順③CS×VP検算**: 「全国の通えない学習者」×「対面同等の密度の指導」を対で言えるか確認し、これを最大の未検証仮説と特定する。
- **手順④左側（インフラ側）**:
  - KR: 講師の指導力（人的）＋教材・カリキュラム（知的）。オンラインでは配信・予約の仕組み（物的/知的）が新たに要る。
  - KA: 「授業」に加え、オンラインでは「コンテンツ制作」「継続支援」が中核活動に昇格する。
  - KP: 配信・決済・予約のプラットフォーム提供者への依存が生まれる（依存リスクを認識）。
  - C$: 対面は教室の固定費が重い。オンラインは変動費寄りに移るが、集客コストが新たに膨らみうる。
- **手順⑤採算**: 月謝（回数）からサブスクに移すなら、継続率が採算を左右する。価値主導（密度の高い指導）で設計する。
- **手順⑥整合チェック**:
  - CS↔VP: 「全国の通えない層」に「対面同等の密度」を約束できるか——ここが最大の賭け（未検証）。
  - VP↔CR: 密度を対面なしでどう担保するか。継続支援の仕組みが弱いとVPが崩れる。
  - RS↔C$: サブスクの継続率と集客コストの綱引き。ここが薄いと回らない。
  - 左右: 「配信の仕組みがあるから」でVPを寄せると自社都合になる。あくまで学習者の価値から設計する。
- **手順⑦次の一手**: 「対面に通えない層が、オンラインでも継続するか」を最重要仮説として小さく試し、継続率で検証する。
- **未確認の前提**: 対象層の実在規模、対面同等の満足を得られるか、継続率——推測で進めず実データで裏を取る。

## 相性（組み合わせると効く）

- `value-proposition-canvas`: BMC中央の CS×VP を拡大鏡で深掘り（顧客のGain/Pain/Job ↔ 提供価値の対応）。手順③の直接の続き。
- `jtbd`: 価値提案(VP)を「顧客が片付けたい用事」から捉え直し、CSとVPの当たりを鋭くする前工程（揺さぶりにも効く）。
- `lean-canvas`: 極初期・高不確実の新規事業では、BMCの一部を Problem/Solution/Key Metrics/Unfair Advantage に置換した派生版が向く。使い分けの相棒。
- `five-forces`: BMCが描かない**競争構造**（新規参入・代替・売り手/買い手の交渉力・競合）を補い、モデルの持続性を問う。
- `3c`: 顧客・競合・自社の3視点でBMCの入力（特に外部情報）を精緻化する前工程。
- `vrio`: 挙げた主要リソース(KR)が本当に持続的な競争優位か（価値/希少/模倣困難/組織）を検証し、思い込みを弾く。
- `customer-journey`: チャネル(CH)と顧客との関係(CR)を、顧客体験の時系列で具体化する。
- 揺さぶり枠として `premortem`（「3年後にこのモデルが失敗した」と仮定して破綻要因を先回り）、
  `devils-advocate`（VPの過信・「刺さる」の思い込みを疑う）、`reverse-assumption`（課金の型や顧客前提を反転して発想）を添えると洞察が増す。
