# アブダクション（仮説形成 / Abductive Reasoning）

## 概要

アブダクションは、**観察された「驚くべき事実（アノマリー）」から、それを最もよく説明する仮説へ遡って跳躍する推論**。
演繹（deduction）・帰納（induction）と並ぶ「第三の推論」で、C・S・パースが位置づけた。

- **核となる考え方**: いま既存の前提では腑に落ちない事実がある。「もしAが真なら、この事実は当然のこと（当たり前）になる」——
  そういうAを探し、「Aが真かもしれない」と考える。既知の枠内で答えを固める演繹・帰納と違い、**枠の外に新しい仮説を生む**。
  これが創造・発見・イノベーションの起点になる（パースはアブダクションを「新しいアイデアを生む唯一の推論」とみなした）。
- **パースの論理形式（1903年ごろの定式とされる・要確認）**:
  > 驚くべき事実 C が観察される。／ もし A が真なら、C は当然のこと（a matter of course）となる。／ ゆえに A が真だと疑う理由がある。
  この形は論理的には**「後件肯定」**（＝演繹としては形式的誤謬）。だがアブダクションは演繹的な証明を主張しない**拡張的推論**であり、
  「新しい情報を生む代わりに不確実」なのが本質。仮説は"証明済み"ではなく"考慮に値する候補"にすぎない。
- **演繹・帰納との違い**:

| 推論 | 向き | 生むもの | 確からしさ |
|---|---|---|---|
| 演繹 | 一般原則 → 個別結論 | 必然的な結論（新情報なし） | 確実 |
| 帰納 | 多数の観察 → 一般法則 | 一般化（例外で覆る） | 蓋然的 |
| **アブダクション** | 単一の意外な事実 → 説明仮説 | **新しい仮説・切り口** | もっともらしい（要検証） |

- **必ずセットで使う「探究の3段階」**: パースは **アブダクション（仮説形成）→ 演繹（仮説から検証可能な予測を導く）→ 帰納（予測を経験的にテスト）** を科学的方法とした。
  アブダクション単体で完結しない。**立てた仮説は必ず予測→検証まで回す**（立てっぱなしは誤用の筆頭）。
- **IBE（最善の説明への推論）との関係**: Harman が1965年に IBE を定式化。パース的アブダクションが仮説を**生成**する文脈なのに対し、
  IBE は候補を**評価・正当化**する文脈に重きがある（本スキルは両方を扱う：まず複数生成し、次に説明の良さで評価する）。

## いつ使う / 使わない

**使う（適する状況）**
- 既存の前提・分析では説明のつかない**意外な事実／アノマリー**があるとき（数字の異変、予想と逆の反応、原因不明の現象）。
- データや観察はあるが**解釈・意味づけ**に詰まっているとき（「何が起きているのか」の仮説が欲しい）。
- 発想が行き詰まり、**既存の枠外の新しい切り口**が欲しいとき。演繹・帰納だと他社と同質な結論になりがちな局面の突破口。
- 真因が未知で、**複数の可能性を並べて**当たりをつけたいとき（診断・原因究明の初手）。
- 顧客の**意外な行動の裏にある動機**を読みたいとき（表層の要望でなく、それを説明する隠れたジョブ・文脈）。

**使わない / よくある誤用（アンチパターン）**
- **仮説を立てて検証しない**——最頻の誤用。アブダクションは"暫定の当たり"であって答えではない。演繹（予測）→帰納（テスト）まで回さないなら使う意味が薄い。
- **最初に思いついた1つの仮説に飛びつく**——確証バイアス。複数仮説を並べるのが原則。単一仮説は「説明の良さ」を比較できず、思い込みを強化する。
- **候補を網羅せず「最善だから真」と断定する（bad lot／悪い候補群の罠）**——van Fraassen の古典的批判。
  少数しか思いついていない中の"最善"は、真の説明を最初から見落としていれば「悪い候補の中のマシな1つ」にすぎない。**「他に見落とした仮説はないか」を必ず問う**。
- **「腑に落ちる（loveliest）」を「確からしい（likeliest）」と混同する**（Lipton）——きれいに説明できることと真であることは別。物語的な納得感で検証を省略しない。
- **説明的美徳を恣意的に使う**——「単純だから正しい」等を都合よく使うと結論を後付けで正当化できてしまう。基準を先に決める。
- 厳密な確実性・定量最適化が要る**意思決定の最終段**や、検証手段が全く無い場には不向き。他フレームで補完する。

## 前提と限界

- **前提**: 出発点となる「驚くべき事実（説明を要する事実）」が特定できていること。凡庸な事実からは跳躍が起きない。
  また、仮説を**検証に回せる**環境（データ・実験・小さな試行のいずれか）があること。検証不能なら発想止まりになる。
- **限界（批判を踏まえて）**:
  - **非確定・拡張的**——結論は「もっともらしい／最善（best available）」に留まり、真とは確定しない。反証で覆り得る。
  - **bad lot 反論（van Fraassen, 1989 とされる・要確認）**——候補の網羅性が担保されない限り「最善＝真」は成立しない。候補集合の質が結論の質を決める。
  - **説明的美徳が未定義**——Stanford百科は「単純さ・射程・整合性などの美徳は現状まだ十分に定式化されていない」と明記。評価が恣意に流れる危険。
  - **確率的整合性の論争**——説明力にボーナスを与える確率版は Bayes 則と衝突し得る（未決着）。数値化には注意。
- これらは、**複数仮説を強制的に出す／候補の見落としを疑う／演繹→帰納で必ず検証する／揺さぶり枠で仮説を叩く**ことで実務的に緩和する（→相性）。

## 進め方（手順）

命令形で示す。各ステップに「なぜ」を添える。

1. **驚くべき事実（アノマリー）を1つに特定し、言語化する。** 「既存の前提だとこうなるはずが、実際はこうだった」の形で、
   何が・どう意外かを書く。なぜ: 跳躍の起点。ここが凡庸だと仮説も凡庸になる。「なぜ意外か（どの前提と食い違うか）」を必ず添える。
2. **その事実を"当然のこと"にする仮説を、複数（最低3つ）強制的に出す。** 「もしAが真なら、この事実は当たり前になる」を満たすAを並べる。
   なぜ: 単一仮説は確証バイアスの温床。数を出すことで初めて比較・跳躍が起きる。凡庸案と大胆案を混ぜる。
3. **各仮説の「説明範囲」を確かめる。** その仮説は観察事実のどこまでを説明し、どこを説明できないか。
   なぜ: 良い仮説は事実を過不足なく説明する。一部しか説明しない仮説は候補として弱い。
4. **説明の良さ（説明的美徳）で候補をランクづけする。** 軸: 説明力（射程）・単純さ・既存知識との整合性・検証可能性・意外性/新規性。
   なぜ: 「腑に落ちる（loveliest）」と「確からしい（likeliest）」は別物。基準を先に決め、物語的納得だけで選ばない。
5. **見落とし（bad lot）を疑う。** 「この候補群に、真の説明が入っていない可能性は？」「正反対の仮説、外れ値の仮説は？」を問う。
   なぜ: 少数の候補の中の最善は、真の説明を見落としていれば無意味。候補集合の網羅性が結論の質を決める。
6. **最有力仮説を"暫定"として選び、演繹で検証可能な予測に変換する。** 「もしこの仮説が真なら、〈観察A／データB〉が見られるはず」を導く。
   なぜ: 仮説は答えでなく問い。検証できる予測に落とさないと真偽を確かめられない。反証条件（何が見えたら棄却か）も決める。
7. **帰納でテストし、次の一手に落とす。** 予測を最小コストで確かめる方法（データ確認・小さな実験・ヒアリング）を決め、実行する。
   なぜ: アブダクション→演繹→帰納の3段階で初めて発想が検証済みの知見になる。外れたら手順2に戻り仮説を更新する（反復）。

## 壁打ち質問リスト

各要素を事実で埋め、跳躍と検証を成立させるために、利用者へ投げ返す問い。勝手に埋めず、まずこれで引き出す。

1. いま**説明のつかない「意外な事実」**は具体的に何ですか？「本来こうなるはずが、実際はこうだった」の形で教えてください。
2. それは**どの前提・常識と食い違う**から意外なのですか？（その"ズレ"の大きさが跳躍の燃料になる）
3. その事実を「もしこれが真なら当然」にする仮説を、**まず3つ以上**挙げるとどうなりますか？（凡庸案・大胆案・正反対の案を混ぜて）
4. それぞれの仮説は、観察された事実の**どこまでを説明でき、どこを説明できません**か？
5. あなたが今**まだ考えていない仮説**はないですか？（この候補群に真の説明が入っていない可能性＝見落としを疑う）
6. 最有力の仮説が**もし真なら、他に何が観察されるはず**ですか？（＝検証可能な予測。逆に、何が見えたらこの仮説は棄却されますか？）
7. その予測を**最小コストで確かめる方法**（既存データ・小さな実験・ヒアリング）は何ですか？
8. 「きれいに腑に落ちる説明」と「実際に確からしい説明」がずれている恐れはありませんか？（納得感で検証を省いていないか）

## 出力フォーマット

ALWAYS この2段構えで出力する（仮説生成 → 評価・検証設計）。単一仮説では出さない。

```
【アブダクション：仮説形成】
驚くべき事実（アノマリー）: <観察された、説明を要する意外な事実>
  なぜ意外か（食い違う前提）: <どの常識・想定と矛盾するか>

仮説候補（複数・強制3つ以上）:
  H1: もし〈A1〉が真なら、この事実は当然になる  ／ 説明範囲: <どこまで説明できる/できない>
  H2: もし〈A2〉が真なら…                    ／ 説明範囲: <…>
  H3: もし〈A3〉が真なら…（大胆案/逆張り案）   ／ 説明範囲: <…>

【説明の良さで評価】（loveliest でなく likeliest を狙う）
  | 仮説 | 説明力(射程) | 単純さ | 既存知識との整合 | 検証可能性 | 意外性/新規性 |
  | H1  |  …          |  …     |  …               |  …         |  …            |
  最有力（暫定）: <Hi> ── 選定理由: <…>
  見落とし(bad lot)の点検: <他に考えるべき仮説／この候補群が"悪い候補群"である可能性>

【検証設計：演繹 → 帰納】
  演繹（予測）: もし Hi が真なら、〈観察A／データB〉が見られるはず
  反証条件   : 〈何が見えたら Hi を棄却するか〉
  帰納（テスト）: 〈最小コストで確かめる方法：データ確認/小実験/ヒアリング〉

【次の一手】<仮説を最小コストで検証する具体行動を1〜2個>
【未確認の前提】<推測と事実の切り分け。外れたら手順2へ戻り仮説を更新>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。あるサブスク型サービスで、値下げ施策を打った月に、想定と逆に解約が増えたという意外な事実を検討する場面。

- **手順①アノマリー**: 「値下げすれば解約は減るはず」という前提に反し、**値下げした月に解約が増えた**。これが説明を要する驚くべき事実。
- **手順②複数仮説（強制3つ）**:
  - H1: 値下げ告知が「サービスの質を下げる／撤退の前触れ」と受け取られ、不安から解約が出た。
  - H2: 値下げで**新たに増えた低関与の顧客層**が、そもそも定着せずすぐ抜けた（値下げ前からの既存顧客は動いていない）。
  - H3（逆張り）: 値下げは無関係で、同月にあった別要因（不具合・競合の新機能・季節性）が真因。値下げとの同時発生は偶然。
- **手順③説明範囲**: H1は「告知に触れた層」の解約は説明するが、告知を見ていない解約は説明しにくい。H2は「増加分がどの層か」を説明できる。H3は値下げ以外の全体変動を説明し得る。
- **手順④評価（loveliest≠likeliest）**: H2は単純で検証可能性が高い。H1は物語として"腑に落ちる"が、確からしさは別途データが要る。H3は見落としを防ぐ対抗仮説として重要。
- **手順⑤見落とし点検（bad lot）**: 「値下げ＝解約増」の因果自体が思い込みで、実は**計測の問題**（解約定義の変更・集計タイミング）という第4の仮説がないか——候補群の外を疑う。
- **手順⑥演繹（予測）**: もしH2が真なら、「解約したのは主に値下げ後に加入した新規層で、既存層の解約率は横ばい」というデータが見られるはず。反証条件＝既存層の解約率も同様に上がっていたらH2は棄却。
- **手順⑦帰納（テスト）→次の一手**: 加入時期別に解約率を分解して確認する（既存データで低コスト検証）。外れたらH1/H3へ移り、仮説を更新する。
- **未確認の前提**: 「値下げが原因」という因果はまだ仮説。相関と因果を混同せず、上記の分解で裏を取るまで断定しない。

## 相性（組み合わせると効く）

- `analogical-thinking`: 遠い分野の構造を借りて「もしAなら当然」の仮説Aを発想する。跳躍の質を上げる直接の相棒（同じ視点転換レンズ）。
- `five-whys`: アブダクションで立てた仮説を、なぜを繰り返して因果の深さ方向に検証・掘り下げる（真因究明とセット）。
- `lean-startup-mvp`: 仮説を最小の実験（MVP）で検証する——パースの「演繹→帰納」を実務化する検証エンジン。立てっぱなし防止の要。
- `jtbd`: 顧客の意外な行動（アノマリー）から、その裏にある未充足のジョブ（隠れた説明仮説）へ跳ぶときに噛み合う。
- 揺さぶり枠として `devils-advocate`（最有力仮説にあえて反論し bad lot を暴く）、`premortem`（仮説が外れた前提で失敗要因を先回り）、
  `reverse-assumption`（前提を反転させて対抗仮説を生む）を1つ添えると、単一仮説への飛びつきを防げる。
