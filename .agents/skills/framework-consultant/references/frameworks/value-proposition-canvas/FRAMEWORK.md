# バリュープロポジションキャンバス

## 概要

バリュープロポジションキャンバス（VPC）は、**顧客が本当に求めるもの** と **自社が提供する価値** を
突き合わせ、両者の **フィット（Fit）** を可視化するツール。2つのブロックで構成される。

| | 右：顧客プロフィール（円・観察対象＝動かせない） | 左：価値マップ（四角・設計対象＝動かせる） |
|---|---|---|
| **中核** | 顧客の仕事（ジョブ） | 製品とサービス |
| **負** | ペイン（悩み・障害・リスク） | ペインリリーバー（ペインを取り除く） |
| **正** | ゲイン（求める便益・成果） | ゲインクリエイター（ゲインを生む） |

- **核となる考え方**: 顧客の中で起きていること（右）を先に観察し、それに応える価値（左）を後から設計する。
  図形が **円（顧客）と四角（提供価値）** なのは意図的で、「四角が円に収まる＝フィット」を視覚化する。
- **フィット**: 価値マップの各要素を、顧客の **重要なジョブ・強いペイン・重要なゲイン** に線でつなぎ、
  刺さっている所と抜けている所を明示する。全要素に応える必要はないが、**最重要ジョブに刺さらなければフィットしない**。
- **位置づけ**: ビジネスモデルキャンバス(BMC)の9ブロックのうち **価値提案(Value Propositions)と
  顧客セグメント(Customer Segments)** の2つを拡大（ズームイン）した補完ツール。
- **出自（要確認扱い）**: **Alexander Osterwalder と Yves Pigneur**（Strategyzerのチーム）が中心で、
  書籍 **『Value Proposition Design』(Wiley, 2014)** で発表。『Business Model Generation』(2010)の続編。
  年号・共著者の役割分担は二次情報が多いため断定を避ける（→出典・要確認参照）。
- **3段階のフィット**（同書）: (1)**課題-解決フィット**＝ジョブ/ペイン/ゲインの証拠に応える価値を設計した紙の上の段階、
  (2)**製品-市場フィット**＝市場で顧客が実際に反応する証拠がある段階、(3)**ビジネスモデルフィット**＝収益性・拡張性ある事業に載る段階。

## いつ使う / 使わない

**使う（適する状況）**
- 新製品/新規事業で **提供価値（バリュープロポジション）を言語化・設計** したいとき。
- 作ったのに **顧客に響かない/売れない** 原因を、ニーズと提供価値のズレとして診断したいとき。
- **BMCの価値提案ブロックを深掘り** し、「誰に・何を・なぜ」を精緻化したいとき。
- ピボットや訴求（キャッチコピー・LP）の核を、顧客のジョブ/ペイン/ゲインから導きたいとき。
- チームで **顧客理解の共通言語** を作りたいとき。

**使わない / よくある誤用（アンチパターン）**
- **複数セグメントを1枚に混ぜる**——最頻の誤用。誰にも刺さらない曖昧な提案になる。1キャンバス=1セグメントを徹底する。
- **自社の提供価値のレンズで顧客プロフィールを書く**——自社が既に解けているジョブしか挙がらず、発見が消える。
  人類学者の視点で観察し、なぜなぜ（Five Whys）で深掘りする。
- **機能的ジョブだけに注目**——社会的・感情的ジョブを見落とす。地位・承認・安心は実利より重いことがある。
- **すべてのペイン/ゲインに応えようとする**——焦点が薄まる。最重要にだけ卓越して応える。
- **記憶・思い込みで埋める**——インタビューや行動データでなく机上で埋めると空論になる。
- **価値マップを固定し、顧客像の方を都合よく書き換える**——顧客を発見せず捏造する罠。動かせるのは左だけ。
- 顧客セグメントが未確定/一次情報ゼロの段階、価格・チャネル等 **事業全体の設計**、定量最適化・実行フェーズには不向き。

## 前提と限界

- **前提**: 対象の顧客セグメントが **1つに絞れている** こと。未確定なら先に STP/ペルソナ/ジョブ理論で顧客を掴む。
  顧客プロフィールを埋めるには **顧客の一次情報**（インタビュー・観察・行動データ・レビュー）が要る。無ければ壁打ちで
  仮説と事実を分け、テストで埋める前提にする。
- **限界（批判を踏まえて）**:
  - **製品/サービス起点に偏りやすい**——VPCは価値提案の中身に集中するため、価格・チャネル・ブランド・収益性など
    提供価値を成立させる **他の要素を見落とす**。事業全体は BMC で補う。
  - **静的になりやすい**——一度作って固定すると環境・顧客の変化に追随できない。定期的に見直し、テストで更新する前提で使う。
  - **フィット＝成功ではない**——紙の上のフィット（課題-解決）は仮説にすぎない。市場での検証（製品-市場フィット）を
    経なければ「売れる」保証はない。VPCの出力は検証すべき仮説である。
  - **ジョブ/ペイン/ゲインの粒度がぶれる**——抽象的すぎると当たり前の羅列に、細かすぎると発散する。
    「顧客の言葉で・観察可能な粒度で」書けているかを常に問う。
- これらの限界は、**顧客理解をジョブ理論/ペルソナ/カスタマージャーニーで補強する / 事業全体はBMCへ広げる /
  フィット仮説をMVPで検証する** ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。**必ず右（顧客）から埋め、左（自社）は後**。

1. **顧客セグメントを1つに絞る。** 「誰のためのVPCか」を1セグメントに固定し、キャンバス上部に明記する。
   なぜ: 複数混在は最頻の失敗。1キャンバス=1セグメントでないと、どのニーズに応えているか判別不能になる。
2. **顧客の仕事（ジョブ）を洗い出す。** 顧客が片付けたい用事を、**機能的・社会的・感情的（個人的）** の3種で挙げる。
   なぜ: 機能面だけ見ると本当の動機を外す。「なぜそれをしたいのか」を Five Whys で掘り、社会的・感情的ジョブを拾う。
3. **ペインを洗い出す。** ジョブ遂行の **前・中・後** に生じる悪い結果・障害・リスク・不満を、顧客の言葉で列挙する。
   なぜ: 障害だけでなく「望まない結果」「リスク」も含めると、刺さりどころが広がる。
4. **ゲインを洗い出す。** 顧客が求める/期待する成果・便益を、**必須〜想定外** のレンジで挙げる。
   なぜ: 当たり前品質（必須ゲイン）と感動品質（想定外ゲイン）は打ち手が違う。両端を意識する。
5. **右の要素を重要度でランク付けする。** ジョブ/ペイン/ゲインを **深刻さ・重要さ** で並べ、上位（各3〜5）に絞る。
   なぜ: 「眠れないほどのペイン」「上司にヒーローと言われるゲイン」に資源を集中するため。全部は等価でない。
6. **価値マップ（左）を埋める。** 製品/サービス → ペインリリーバー（どのペインをどう除くか）→
   ゲインクリエイター（どのゲインをどう生むか）の順で、右の要素に **紐づけて** 書く。
   なぜ: 右と無関係な機能自慢を防ぐ。左の各項目は「右のどれに効くか」を必ず指す。
7. **左右を線で結び、フィットを確認する。** 各ペインリリーバー/ゲインクリエイターを、対応する上位ペイン/ゲインへつなぐ。
   なぜ: 最重要ジョブ・激しいペイン・本質的ゲインに刺さっているか、逆に **未対応の重要ニーズ** が残っていないかを可視化する。
8. **検証すべき仮説に落とす。** フィットは仮説。最も危うい前提（本当にそのジョブが重要か等）を1〜3個、テスト計画に落とす。
   なぜ: VPCはゴールでなく起点。紙のフィットを市場のフィットに変えるにはMVP/インタビューでの検証が要る。

## 壁打ち質問リスト

各要素を **顧客の一次情報** で埋めるために利用者へ投げ返す問い。空欄を勝手に埋めず、まずこれで引き出す。

1. この提供価値は **誰のためのもの** ですか？ 顧客セグメントを1つに絞れていますか？（複数混在していませんか）
2. その顧客が片付けたい **仕事（ジョブ）** は何ですか？ 機能面だけでなく、**社会的（どう見られたいか）・感情的（どう感じたいか）** な狙いは何ですか？
3. その顧客が今、ジョブの **前・中・後** で困っていること・避けたいリスク・不満（ペイン）は何ですか？ その中で **一番深刻** なのはどれですか？
4. その顧客が **本当に喜ぶ成果・便益（ゲイン）** は何ですか？ 「あって当たり前」と「あったら感動」を分けると、それぞれ何ですか？
5. それらのジョブ/ペイン/ゲインは、**顧客の観察・インタビュー・行動データ** に基づいていますか、それとも自社の推測ですか？（事実と仮説を分ける）
6. 自社の製品/サービスは、上で挙げた **どのペインを取り除き、どのゲインを生む** のですか？ 具体的にどの要素がどれに効きますか？
7. 顧客の **最重要ジョブ/最も強いペイン** に、自社の価値は刺さっていますか？ 逆に、応えられていない重要ニーズはどれですか？
8. このフィットの中で **最も危うい前提**（外れたら価値提案が崩れる仮説）は何ですか？ どう検証しますか？

## 出力フォーマット

ALWAYS この2段構えで出力する（棚卸し→フィット診断）。左は右に紐づけて書く。

```
【VPC】セグメント: <誰のためか・1つに絞る>

◆顧客プロフィール（右／観察）  ※各カテゴリ重要順・上位3〜5
  顧客の仕事(Jobs):  - 機能的: <…> / 社会的: <…> / 感情的: <…>
  ペイン(Pains):     - <悪い結果・障害・リスク＋深刻度>
  ゲイン(Gains):     - <求める便益＋必須/想定外の別>

◆価値マップ（左／設計）  ※各項目が右のどれに効くかを明記
  製品/サービス:            - <提供物>
  ペインリリーバー:         - <どのペインを どう軽減/除去>（→ ペインX）
  ゲインクリエイター:       - <どのゲインを どう創出>（→ ゲインY）

【フィット診断】
  刺さっている(Fit):   <最重要ジョブ/強ペイン/重要ゲインへの対応>
  未対応(Gap):         <応えられていない重要ニーズ／過剰な機能自慢>
  段階:                <課題-解決フィット(仮説) / 製品-市場フィット(検証済) のどちらか>

【検証すべき仮説】<最も危うい前提を1〜3個＋検証方法（インタビュー/MVP等）>
【未確認の前提】<推測で埋めた箇所（顧客の一次情報で裏取りが要る点）>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。忙しい共働き世帯向けの「調理キット宅配」サービスの提供価値を設計する場面。

- **手順①セグメント**: 「平日に自炊したいが時間がない共働き世帯」に1つ絞る（単身者や料理好き層は別キャンバス）。
- **手順②ジョブ**:
  - 機能的: 平日の夕食を短時間で用意する。
  - 社会的: 家族に「ちゃんとした手料理」を出したと思われたい。
  - 感情的: 献立を考える負担から解放され、罪悪感なく時短したい。
- **手順③ペイン**: 献立を考えるのが面倒（前）、買い物・下ごしらえに時間がかかる（中）、食材を余らせ罪悪感（後）。最深刻＝献立を考える認知負荷。
- **手順④ゲイン**: 必須＝短時間で完成。想定外＝レパートリーが自然に増える、栄養バランスが整う。
- **手順⑤ランク付け**: 最重要ジョブ＝時短で夕食、最強ペイン＝献立の認知負荷、重要ゲイン＝手抜きに見えない仕上がり。
- **手順⑥価値マップ**:
  - 製品/サービス: 計量済み食材＋レシピカードの定期宅配。
  - ペインリリーバー: 献立を事前に組んで届ける（→献立の認知負荷）、下処理済み食材（→下ごしらえ時間）。
  - ゲインクリエイター: 見栄えする一品になるレシピ設計（→手抜きに見えない）、日替わりで飽きない献立（→レパートリー増）。
- **手順⑦フィット確認**: 最強ペイン「献立の認知負荷」に献立設計が刺さる＝フィット。一方、食材の余り（後のペイン）への対応は弱く未対応領域。
- **手順⑧検証すべき仮説**: 「献立を考える負担が、時短そのものより重いペインである」——ここが外れると価値提案の軸が崩れる。ターゲット世帯へのインタビューで優先度を検証する。
- **未確認の前提**: 社会的ジョブ（家族の評価）の強さ、価格許容度——一次情報での裏取りが要る（推測のまま進めない）。

## 相性（組み合わせると効く）

- `business-model-canvas`: VPCが拡大した2ブロック（価値提案・顧客セグメント）を含む事業全体像。VPCの結論を収益・チャネル・コストへ広げる後工程。
- `jtbd`: 顧客の仕事（ジョブ）を「片付けたい用事」として深掘りし、機能面に偏らない本質的ジョブを掘り当てる直接の補強。
- `persona`: 顧客プロフィールの土台となる典型顧客像を具体化し、1セグメントへの絞り込みを助ける前工程。
- `customer-journey`: ジョブ遂行の前・中・後を時系列で追い、ペイン/ゲインの抜け漏れ（特に「後」のペイン）を発見する。
- `lean-startup-mvp`: 手順⑧で挙げたフィット仮説を最小構成で検証し、紙のフィットを製品-市場フィットへ進める後工程。
- 揺さぶり枠として `devils-advocate`（「このジョブは本当に重要か」と価値提案の前提を疑う）や `premortem`（提供価値が刺さらず失敗した前提で原因を先回り）を添えると、思い込みで固めたキャンバスを弾ける。
