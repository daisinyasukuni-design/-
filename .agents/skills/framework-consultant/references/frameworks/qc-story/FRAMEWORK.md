# QCストーリー

## 概要

QCストーリーは、品質管理（QC）における**問題解決／課題達成を、決まった順序のステップで進める標準手順**。
QCサークル・小集団活動から生まれ、事実とデータ（三現主義＝現場・現物・現実）に基づいて、
対策に飛びつかず**真因にたどり着き、再発防止（標準化）まで到達させる**ことを狙う。

- **核となる考え方**: 「原因が分かる前に対策しない」「勘でなく事実・データで語る」「PDCAを回し切り、
  効いた対策を標準（歯止め）にして二度と起こさない」。QC7つ道具が各ステップの土台になる。
- **重要なニュアンス（出自）**: QCストーリーは元来「**すでに終わった改善事例を他人に分かりやすく
  説明するための“報告・発表の型”**」として生まれ、名称もそこに由来する（諸説あり）。後にこれが
  問題解決の手順として広く使われるようになった。**この“報告の型”と“探索の実順序”の混同が、
  後述の形骸化・誤用の温床**になる（→前提と限界）。
- **出自（諸説あり・要確認）**: QCサークル活動は日本発。日本科学技術連盟（JUSE）が1962年に発した
  雑誌「現場とQC」創刊を契機に広まり、石川馨（Kaoru Ishikawa）が「QCサークルの父」と紹介される。
  ただし「QCストーリー」という名称・型そのものの**命名者と発生年は特定困難**（→出典・要確認項目）。

**型（状況で使い分ける）**

| 型 | 使う場面 | 特徴 |
|---|---|---|
| **問題解決型** | 現在起きている問題（あるべき姿とのギャップ）を潰す | 原因を解析して真因を叩く。最も基本 |
| **施策実行型** | 原因がすでに分かっている | 要因解析を省き対策実行を優先（問題解決型の短縮版） |
| **課題達成型** | ありたい姿・新規/前例のない目標へ到達 | 原因分析でなく「攻めどころ→方策設計→成功シナリオ」で攻める |
| **未然防止型** | 潜在リスクを事前に防ぐ | FMEA等と結合し、起こる前に手を打つ（※資料により型の数え方は揺れる） |

## いつ使う / 使わない

**使う（適する状況）**
- 不良・クレーム・ロス・手戻り・納期遅れなど、**原因が未知の再発性問題を、勘でなく事実で潰したい**とき。
- **対策したのに再発する**（＝真因に届いていない）とき。要因解析まで戻ってやり直す型がほしい。
- QCサークル/小集団活動・改善提案で、メンバー共通の**進め方の型と共通言語**がほしいとき。
- 改善の成果を、他部署や次のメンバーに**伝わる形で報告・横展開**したいとき。
- **ありたい姿・新しい目標**に前例のないやり方で到達したいとき（→課題達成型）。

**使わない / よくある誤用（アンチパターン）**
- **記入用紙を順番通りに先に配って穴埋めさせる**——最頻の誤用。QCストーリーは“完了後の報告の型”が
  出自で、探索の実順序ではない。実際は要因解析↔対策で往復する。型に押し込むと形骸化する。
- **型の目的化＝形骸化**——発表会に間に合わせるため「成功が確定したテーマだけ」選ぶ、失敗を隠す
  “ウソ話”化、一度の対策で終える。手段（型）が目的（問題解決）を食う。
- **原因究明の前に目標を数値で固定**——根拠なき宣言になる。現状把握と要因の見当がついてから定量化する。
- **なぜなぜが人責めで止まる**——「不注意だった」で終える。個人でなく**仕組み・条件**で問い、
  対策できるレベルまで掘る。
- **一発の大改善の型を、小さな反復改善に無理適用**——小改善はCAPDを速く回す方が合う。
- 原因が自明なのに問題解決型でぐるぐる回す（→**施策実行型**へ）。
- **緊急トラブルの即時対応**、精緻な統計的最適化そのもの（→**シックスシグマ/DMAIC**）、
  非連続なブレークスルー発明（→**TRIZ**）には不向き。

## 前提と限界

- **前提**: **事実・データで語れること**（三現主義）。数字が無ければまず測る/チェックシートで取る。
  テーマが1つに絞れていること。QC7つ道具を扱えるか、壁打ちで補えること。
- **限界（批判を踏まえて）**:
  - **出自が「報告の型」**——手順どおりに探索が進む保証はない。実際は行き来する。順序を絶対視しない。
  - **形骸化しやすい**——発表様式が目的化すると、成功確定テーマだけ・失敗隠しに堕ちる。
    目的は「問題を潰し再発を防ぐ」ことで、資料を仕上げることではない。
  - **既存の延長線上の改善に強く、非連続なブレークスルーは苦手**——問題解決型は特にそう。
    飛躍が要るなら課題達成型や別発想法（TRIZ等）へ。
  - **標準化が定着しない**——人依存・教育のばらつきで歯止めが外れる。仕組み化と再監査が要る。
  - **QCサークル文化への批判**（時代遅れ・強制感・様式主義）。型は問題解決の補助線であって儀式ではない。
- これらは、**要因解析を特性要因図/なぜなぜで深掘りする・PDCA/CAPDで回し切る・対策の失敗をpremortemで
  先回りする**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップに「なぜ」を添える。**まず型を選び**、問題解決型なら1〜8を回す。

0. **型を選ぶ。** 現在の問題を潰す＝問題解決型／原因が既知＝施策実行型／ありたい姿へ新規到達＝課題達成型。
   なぜ: 原因が自明なのに解析工程を回すのは無駄。逆に未知なのに対策先行すると再発する。入口の誤りが全体を狂わせる。
1. **テーマを選定する。** 重要性・緊急性・効果・自分たちで手が届くかで、1つに絞る（パレート図/マトリックスで優先度づけ）。
   なぜ: 欲張って複数を同時に追うと、どれも中途半端になる。「なぜこのテーマか（選定理由）」を言語化する。
2. **現状を把握する。** 三現主義で事実を集め、いつ・どこで・どの工程・どんな条件で・どれだけ起きているかを
   層別（機械/人/時間帯/ロット等）してデータで掴む。
   なぜ: 現状の解像度が対策の質を決める。「多い気がする」を数字と場所に落とす。ここで問題を具体的に絞り込む。
3. **目標を設定する。** 「何を・いつまでに・どの水準まで」を定量で置く（現状値→目標値、期限、指標）。
   なぜ: 効果確認の物差しになる。ただし**原因の見当がつく前に無根拠な数字を置かない**——現状把握と地続きで決める。
4. **活動計画を作る。** 誰が・何を・いつまでに（役割分担と日程、ガントチャート）。
   なぜ: 小集団活動は分担と締切がないと止まる。ただし原因未知の段階で全工程を確定できない前提で、見直し可とする。
5. **要因を解析し真因を特定する。** 特性要因図で要因を4M（人/機械/材料/方法）等に洗い出し、
   なぜなぜ分析で掘り下げ、**仮説をデータで検証**して真因を絞る。
   なぜ: ここがQCストーリーの心臓。**人責めで止めず仕組み・条件で問う**。検証なき“真因らしきもの”で対策すると再発する。
6. **対策を立案し実施する。** 真因に対してECRS（排除/結合/交換/簡素化）等で案を出し、効果・実現性・副作用で選び、
   小さく試して展開する。
   なぜ: 症状でなく真因に効く対策を選ぶ。「やりやすい対策」に逃げると真因が残る。副作用（別の不具合誘発）も確認する。
7. **効果を確認する。** 対策**前後を同一条件で比較**し、目標達成度を指標で見る。未達なら5へ戻る。
   なぜ: 「やった」ではなく「効いた」を証明する。条件を揃えないと改善に見えて別要因の影響を拾う。
8. **標準化し歯止めをかける。** 効いた対策をSOP・作業標準・帳票・教育に落とし、逸脱を検知する管理の仕組みを作る。
   最後に**反省と今後の対応**（残課題・横展開先）を整理する。
   なぜ: 標準化しないと元に戻る（歯止めが外れる）。QCストーリーの目的は「二度と起こさない」で、ここが終点。

> **課題達成型の場合**: 2〜6を「攻めどころ（課題の明確化）と目標設定 → 方策の立案・評価 →
> 成功シナリオの追求（最適策の選定）→ 実施」に置き換える。原因分析でなく、ありたい姿から
> **やり方を設計**する（緊急の問題には使わない）。

## 壁打ち質問リスト

各ステップを事実で埋めるために利用者へ投げ返す問い。空欄を勝手に埋めず、まずこれで引き出す。

1. 今回**潰したいのは「現在起きている問題」か「まだ無い理想像への到達」**か？（問題解決型／課題達成型の見極め。原因はもう分かっていますか＝施策実行型か）
2. その問題は**いつ・どこで・どの工程・どんな条件で・どれくらい**起きていますか？数字やデータはありますか、まだ勘の段階ですか？（現状把握・層別）
3. このテーマを**選ぶ理由**は何ですか？他に候補はあり、なぜこれを優先しますか？（テーマ選定・優先度）
4. **いつまでに・どの水準まで**改善できたら成功ですか？その目標値の根拠は？（目標設定と物差し）
5. 考えられる**要因（人・機械・材料・方法など）**は何ですか？「なぜそれが起きる？」をあと何段まで説明できますか——**個人の不注意でなく仕組み・条件**で言えますか？（要因解析・真因）
6. 過去に**似た対策をして再発した**ことはありますか？そのとき何が残っていたと思いますか？（真因の取りこぼし確認）
7. 対策後、**効果を何の指標でどう比較**して「効いた」と判断しますか？対策前後の条件は揃えられますか？（効果確認）
8. 効いた場合、**標準（作業手順・教育・チェック）にどう落とし**、外れないよう誰がどう監視しますか？横展開先は？（標準化・歯止め）

## 出力フォーマット

ALWAYS この型で出力する（型選定 → 8ステップ表 → 標準化と残課題）。原因未確定のステップは
勝手に埋めず「未確認（壁打ちで確認）」と明記する。

```
【型の選定】問題解決型 / 施策実行型 / 課題達成型 のいずれか（理由: <なぜこの型か>）
【テーマ】<1つに絞ったテーマ ／ 選定理由>

① 現状把握 : <いつ/どこ/どの工程/条件/量。層別した事実・データ。無ければ「未確認」>
② 目標設定 : <何を・いつまでに・どの水準へ（現状値→目標値、指標）>
③ 活動計画 : <誰が/何を/いつまで（見直し可）>
④ 要因解析 : <特性要因図/なぜなぜで挙げた要因 → 検証で絞った真因（仕組み・条件で）>
⑤ 対策    : <真因に効く対策案（ECRS等）→ 選定理由・副作用の確認>
⑥ 効果確認 : <対策前後の比較方法と指標。目標達成度。未達なら④へ戻す>
⑦ 標準化  : <SOP/教育/帳票への落とし込み ＋ 逸脱を検知する管理の仕組み（歯止め）>

【反省と今後】<残課題・横展開先・次テーマ>
【未確認の前提】<事実確認が要る点（推測のまま進めない）>
```
※課題達成型のときは①〜⑤を「攻めどころ／方策立案／成功シナリオ／実施」に読み替える。

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は捏造しない。数量はプレースホルダで示す）。
ある組み立て工程で、特定工程の不良（例: ネジ締め不良）が慢性的に発生し、対策しても再発する場面。

- **型の選定**: 現在起きている再発性の不良で原因が未確定 → **問題解決型**。
- **①現状把握**: いつ・どのライン・どの作業者・どのロットで起きるかを層別し、パレート図で
  「不良の大半が特定工程の特定条件に集中」といった偏りを事実で掴む（“なんとなく多い”を場所と数字に落とす）。
- **②目標設定**: 「対象工程の当該不良を、期限までに現状値から目標値へ低減」と定量で置く（現状把握で見えた集中箇所に的を絞る）。
- **③活動計画**: 担当・観察日・検証日を分担し日程化（原因未確定のため見直し前提）。
- **④要因解析**: 特性要因図で4M（作業者の手順、工具の状態、部品の公差、手順書の指示）に要因を展開。
  なぜなぜで「締め付けトルクがばらつく→なぜ→工具設定が作業者任せ→なぜ→標準が無い」と**仕組みの欠落**まで掘り、
  データで裏取りして真因を絞る（「作業者の不注意」で止めない）。
- **⑤対策**: 真因（標準の欠落）に対し、工具設定の固定化・治具化などをECRSで発想し、副作用を確認して試す。
- **⑥効果確認**: 対策前後を同一条件で比較し、目標達成度を指標で確認。未達なら④へ戻る。
- **⑦標準化**: 効いた設定を作業標準・教育・チェックシートに落とし、逸脱を検知する管理を設ける（歯止め）。
- **反省と今後**: 同種工程への横展開、残った要因を次テーマに。
- **未確認の前提**: 実データ（発生率・条件別の偏り）は現場で測って確認する——推測のまま数値を置かない。

## 相性（組み合わせると効く）

- `fishbone`: 手順⑤「要因の解析」で、要因を4M等に**漏れなく**洗い出す中核ツール（特性要因図）。
- `five-whys`: 挙げた要因を「なぜ」で掘り、**仕組み・条件レベルの真因**まで届かせる（人責め防止）。
- `pdca`: QCストーリーはPDCAの実装形。**回し切って標準化→次サイクル**へつなぐ土台の考え方。
- `ecrs`: 手順⑥「対策」で、排除/結合/交換/簡素化の観点から具体的な改善案を発想する。
- `mece`: 現状把握の層別や要因の洗い出しを、漏れ・ダブりなく整理して抜けを防ぐ。
- `six-sigma`: ばらつきを統計的に詰めたい/大規模な工程能力改善はDMAICへ橋渡し（QCストーリーの精密版）。
- `toc`: 全体のボトルネック工程を特定してからテーマ選定すると、効く所に力を集中できる。
- 揺さぶり枠として `premortem`（対策が失敗する要因を事前に洗う）や `devils-advocate`（“真因”の思い込み・
  成功前提を疑う）を手順⑤〜⑥に添えると、形骸化・ウソ話化を防ぎ洞察が増す。
