# ペイオフマトリクス

## 概要

ペイオフマトリクスは、施策・アイデア・打ち手を **効果（Impact / ペイオフ）** と **実現容易性（Effort・労力・コスト）**
の2軸で評価し、2×2の4象限に配置して**優先順位を可視化する**意思決定フレーム。別名は Impact-Effort Matrix /
Action Priority Matrix (APM) / Value vs. Effort。Six Sigma では Payoff Matrix と呼ばれ改善案の選別に使う。

| | 効果 高 | 効果 低 |
|---|---|---|
| **実現 容易** | Quick Win（最優先で即実行） | スキマ / Fill-in（余裕時に処理・委譲） |
| **実現 困難** | 大型プロジェクト（計画的に段階推進） | 保留 / 見送り（捨てる・やらない） |

- **核となる考え方**: 「効果が高く実現が容易なもの（Quick Win）から着手する」という**投資対効果（ROI）による選別**。
  多くの候補を"捨てる/後回しにする"判断を、感覚でなく共通の2軸で言語化し、関係者の合意形成を助ける。発散（多数の案）を
  受けて**収束（絞り込み）**させる磨き・検証フェーズのツール。
- **象限の呼び名は流派で異なる**（→出典）。MindTools の APM は Quick Wins / Major Projects / Fill Ins /
  Thankless Tasks、Six Sigma DSI は Quick Win / Filler / "Do we have time & money?" / Kill It。呼称より
  **「効果×実現の掛け合わせで着手順を決める」構造**が本質。
- **出自（考案者は特定不能・断定回避）**: 単一の原典・発表年・人物には帰属できない。MindTools は "originator unknown"
  と明記する。Eisenhower（緊急×重要）マトリクスや Stephen Covey の思想と系譜を共有するとの解説はあるが因果は未確証。
  Six Sigma / リーン / プロダクトマネジメント / デザイン思考の選別工程で独立に定着した実務ツール（→出典・要確認）。
- **注意（名称衝突）**: ゲーム理論の "payoff matrix"（戦略の組合せごとの利得表）とは**別物**。本項はビジネスの
  効果×実現マトリクスを指す。

## いつ使う / 使わない

**使う（適する状況）**
- **候補が多すぎて絞り込みたい**とき（ブレストで出たアイデア、施策バックログ、改善案 15〜50 件の一次スクリーニング）。
- **限られたリソースで最大の成果**を出す着手順を決めたいとき。**Quick Win を先に見つけたい**とき。
- 施策の優先順位を**関係者で合意・見える化**したいとき（1人の主観でなく共通軸で議論したい）。
- 「**やること / やらないこと**」を仕分けたいとき。戦略やアクションプランの実行フェーズ入口。

**使わない / よくある誤用（アンチパターン）**
- **選択肢が既に1〜2個しかない**——並べる意味が薄い。比較不要ならそのまま検討へ。
- **効果や労力の見積り根拠が皆無**——当てずっぽうの配置は誤った結論を正当化する。先にデータ収集・小さな検証を回す。
- **本質的に3軸以上の評価軸が要る**（品質・戦略適合・リスク・コストを別々に重みづけしたい）——`decision-matrix`（加重採点）へ。
- **緊急度で切りたい**（効果の大小でなく締切）——`eisenhower-matrix`（緊急×重要）が適切。
- **贔屓した案の追認装置に使う**（confirmation device 化）——最頻の政治的誤用。中立な判断ツールとして運用する。
- **象限に置いて終わり**——配置は議論の出発点。リスク・依存・戦略的重要性を加味した総合判断まで進めないと意味が無い。

## 前提と限界

- **前提**: 比較対象となる候補が複数あること。効果と実現容易性を**同じスケールで見積もれる最低限の情報**があること
  （無ければ壁打ちで引き出すか、先に検証する）。効果の指標（何をもって効果とするか＝売上/コスト削減/リスク低減/顧客維持など）が
  スコープとして1つに定まっていること。
- **限界（批判を踏まえて）**:
  - **効果の過大評価**——贔屓（endowment effect）で自分の推し案を高く置く。A/Bテストでは効果の出る施策は概ね3件に1件以下
    （新規性が高い領域ほど低い）とされ、企業は便益を実際より大きく見積もりがち（→出典 Gilad）。
  - **労力の過小評価**——Planning Fallacy（Kahneman & Tversky）。依存関係・レビュー工程・手戻りを忘れ、実プロジェクトは
    見積りの数倍に膨らむことがある。「右上（Quick Win）に見えて実は大型」が頻発する。
  - **2軸の捨象**——リスク・**確信度（当たる確率）**・戦略的重要性・相互依存を落とす。Gilad は
    「**優先度 = 効果 ÷ 労力 × 確信度**」で確信度を明示的に足すべきと主張する。
  - **静的**——一度置いて放置すると陳腐化。効果/実現は環境で動く。境界線上の案は追加分析が要る。
- これらの限界は、**確信度・リスクを第3の視点として併記する / 効果の過信を `devils-advocate` や `premortem` で叩く /
  3軸以上なら `decision-matrix` に切り替える**ことで補える（→相性）。

## 進め方（手順）

命令形で示す。各ステップの「なぜ」を添える。

1. **候補を洗い出す。** 評価対象の施策・アイデア・打ち手をリスト化する（目安 10〜20、多くて50程度）。
   なぜ: 比較は候補が揃って初めて成立する。少なすぎると象限化の意味が薄い。発散が足りなければ `brainstorming` 等を先に回す。
2. **効果（縦軸）の意味と測り方を1つに定義する。** 「効果＝何か」（売上/利益/コスト削減/リスク低減/顧客維持/工数削減など）と
   スコアの尺度（例: 1〜5）を先に決める。なぜ: 人により"効果"の解釈がずれると配置が崩れる。共通のものさしを先に固定する。
3. **実現容易性（横軸）の意味と測り方を定義し、軸の向きを明示する。** コスト・時間・難易度・依存関係で測る。
   「右＝容易」か「右＝高労力」かを宣言する。なぜ: 横軸の向きは流派で逆転し、混乱の元。何が右上かを毎回明記する。
4. **各候補を2軸でスコアリングし配置する。** 複数人で討議しながら象限に落とす。
   なぜ: 1人・声の大きい人の支配は偏りを生む。効果の過大評価・労力の過小評価という定番バイアスを相互に牽制する。
5. **確信度とリスクで検算する。** 高効果に置いた案に「その効果は実測・根拠があるか（確信度）」、右（容易）に置いた案に
   「依存・レビュー・手戻りを数えたか」を問い、必要なら位置を修正する。なぜ: 2軸だけだと確信度・リスクを見落とす（既知の弱点）。
6. **象限ごとに方針を決める。** Quick Win＝即実行 / 大型＝計画的に段階推進（1つが Quick Win を圧迫しないよう注意）/
   スキマ＝余裕時に処理・委譲 / 保留＝捨てる・やらない。なぜ: 象限は着手戦略に直結する。捨てる判断まで含めて優先順位である。
7. **総合判断で最終決定し、次の一手に落とす。** 戦略的重要性・依存順序を加味し、着手する上位数件と検証すべき前提を1〜3個決める。
   なぜ: 配置はゴールでなく議論の出発点。ここで止めると「置いて終わり」の典型に陥る。

## 壁打ち質問リスト

各要素を事実で埋めるために、利用者へ投げ返す問い。空欄は勝手に埋めず、まずこれで引き出す。

1. 優先順位をつけたい**候補（施策・アイデア）を全部**挙げてください。いま何個ありますか？（絞り込む母集団を確定する）
2. この文脈で言う「**効果**」とは具体的に何ですか？（売上/利益/コスト削減/リスク低減/顧客満足/工数削減——測る指標を1つに）
3. 「**実現容易性**」は何で測りますか？（費用・所要時間・技術難易度・必要人員・他部署や外部への依存——重い制約はどれ）
4. 各候補について、その**効果の根拠**はありますか？（実測値・過去実績・顧客の声か、それとも期待値・仮説か＝確信度の確認）
5. 「実現が容易」に見える案に、見落としている**依存関係・レビュー・手戻り**はありませんか？（労力の過小評価を潰す）
6. 効果は小さくても、**戦略的にやらざるを得ない**もの（規制対応・基盤・約束事）はありますか？（2軸で切れない例外の確認）
7. この優先順位は**誰が合意する必要**がありますか？（意思決定者・巻き込む関係者。政治的な追認装置化を避けるため）
8. 決めた優先順位を、**いつ・何をトリガーに見直し**ますか？（静的な放置を防ぐ運用の確認）

## 出力フォーマット

ALWAYS この型で出力する（軸の定義→4象限→着手順と次の一手）。象限に置いて終わらせず、必ず「次の一手」まで書く。

```
【前提】効果の定義: <何で測るか> ／ 実現容易性の定義: <何で測るか> ／ 軸の向き: <右=容易 か 右=高労力か>

【ペイオフマトリクス】
  Quick Win（高効果×実現容易 / 最優先）:      - <候補>（効果:__ 実現:__ 確信度:__）
  大型プロジェクト（高効果×実現困難 / 計画的）: - <候補>（同上）
  スキマ（低効果×実現容易 / 余裕時・委譲）:    - <候補>（同上）
  保留・見送り（低効果×実現困難 / 捨てる）:    - <候補>（同上）

【着手順（優先順位）】1) <Quick Winから> 2) … （確信度・依存順を加味した総合判断）
【次の一手】<まず着手する上位1〜3件と、実行前に潰すべき検証・意思決定>
【未確認の前提】<効果/労力の見積り根拠が弱い点・壁打ちで埋める点>
```

## 具体例（ワークスルー）

対象を一般化した例（架空の数値・企業名は用いない）。ある店舗が「顧客の再来店を増やす」ための施策を複数持ち、
リソースが限られる中で着手順を決める場面。

- **手順①候補**: 会員アプリ導入、店頭POPの改善、スタッフの声かけ徹底、公式SNS開設、店内レイアウト全面改装、
  レシートにクーポン印字 ——を候補として列挙する。
- **手順②効果の定義**: 「効果＝再来店率への寄与」と1つに固定し、尺度を高/中/低で見る。
- **手順③実現容易性の定義**: 「費用・所要時間・現場の負担」で測り、**右＝容易**と宣言する。
- **手順④配置**（相対評価、値は捏造しない）:
  - Quick Win（高効果×容易）: スタッフの声かけ徹底、レシートへのクーポン印字。
  - 大型（高効果×困難）: 会員アプリ導入、店内レイアウト全面改装。
  - スキマ（低効果×容易）: 店頭POPの改善。
  - 保留（低効果×困難）: 公式SNS開設（現状の体制では運用負荷が高く効果も不確実）。
- **手順⑤確信度・リスクで検算**: 「クーポン印字」の効果は過去のクーポン利用実績で裏が取れる→確信度高。
  「アプリ導入」は"容易寄り"に見積もっていたが、保守・個人情報対応の依存を数え直すと労力が上振れ→大型のまま固定。
- **手順⑥方針**: Quick Win を即実行、大型は投資判断を要するため段階検証、SNSは当面保留。
- **手順⑦次の一手**: まず「声かけ徹底」と「クーポン印字」を今週から実施し、再来店率という仮説を小さく検証する。
  アプリ導入は効果の確信度を上げる小規模テストを先行させる。
- **未確認の前提**: 各施策の再来店への寄与度は実データで裏取りが必要——期待値のまま大型投資に進めない。

## 相性（組み合わせると効く）

- `brainstorming`: 先に候補を発散させる前工程。ペイオフマトリクスは"絞り込み(収束)"側なので、母集団づくりに使う（`scamper` / `mind-map` でも可）。
- `decision-matrix`: 2軸では足りず、品質・戦略適合・リスクなど**3軸以上を加重採点**したいときの上位互換。効果×実現で粗選別→重要案は加重採点、の二段構え。
- `eisenhower-matrix`: 同じ2×2でも軸が**緊急×重要**。効果でなく締切で切りたいタスク整理はこちらへ切り替える。
- `pmi`: 象限の"境界線上"で迷う単一案を、Plus/Minus/Interesting で多面評価して押し出す。
- 揺さぶり枠として `premortem`（Quick Win/大型に潜む失敗要因と労力の過小評価を先回り）や `devils-advocate`（高効果という見立ての過信・贔屓を疑う）を添えると、効果の過大評価という定番バイアスを潰せる。

**要ファクトチェック（Web調査で誤りが混入しやすい断定）**
- **考案者・発表年は特定不能**（MindTools「originator unknown」）。Eisenhower/Covey との系譜は思想的類似であり、直接の由来・因果は未確証。単一人物・単一年に帰属させない。
- **4象限の呼称は流派で異なる**（APM: Quick Wins/Major Projects/Fill Ins/Thankless Tasks ／ Six Sigma DSI: Quick Win/Filler/"Do we have time & money?"/Kill It ／ 日本の実務: Quick Win/大型/スキマ/保留）。唯一の正解ではない。
- **横軸の向きが資料で逆転する**（右＝実現容易 か 右＝高労力 Effort か）。本文は「右＝容易」で統一したが、他資料と突き合わせる際は要注意。
- Gilad が引く数値（効果の出る施策は概ね3件に1件以下、企業の便益過大評価など）は二次引用。原典（Gourville, Kahneman & Tversky の Planning Fallacy）に当たると精度が上がる。
- ゲーム理論の "payoff matrix"（利得表）とは別概念。名称衝突があるため文脈で意味が変わる。
